# 5.2 身份 + 语气：定调全靠它

⬅ [01-入职手册的13节](01-%E5%85%A5%E8%81%8C%E6%89%8B%E5%86%8C%E7%9A%8413%E8%8A%82.md)　|	➡ [03-做事规则10金句](03-%E5%81%9A%E4%BA%8B%E8%A7%84%E5%88%9910%E9%87%91%E5%8F%A5.md)

## 🎬 故事比喻：迪士尼员工的"角色"训练

迪士尼员工被反复训练：你不是"演员"，你**就是**米奇。
- 不能脱下头套
- 不能说"我们演员"
- 必须用米奇的语气

为啥？因为**角色感**决定了所有后续行为的风格。

LLM 也一样：**身份语决定了模型整段对话的语气、能力边界、是否能自称 Claude Code**。

**学习点**：身份语就一句话，但它决定了**所有后续语气**。

## 🔧 第 4 节：Tone and style（5 条规则）

`prompts.ts:430`：

```
# Tone and style
 - Only use emojis if the user explicitly requests it. Avoid using emojis in all communication unless asked.
 - Your responses should be short and concise.
 - When referencing specific functions or pieces of code include the pattern file_path:line_number to allow the user to easily navigate to the source code location.
 - When referencing GitHub issues or pull requests, use the owner/repo#123 format (e.g. anthropics/claude-code#100) so they render as clickable links.
 - Do not use a colon before tool calls. Your tool calls may not be shown directly in the output, so text like "Let me read the file:" followed by a read tool call should just be "Let me read the file." with a period.
```

---

## ⭐ 加深理解：5 条规则的真实背景

### 规则 1：NEVER emoji unless asked

**为啥**：
- 终端等宽字体下 emoji 经常**错位**
- 很多用户**讨厌 AI 卖萌**

> 你今天看到我从头到尾没用 emoji，就是这条在起作用。

### 规则 2：Responses should be short and concise

**为啥**：
- 长回答 = 多 token = 用户等久 = API 贵
- 大部分 coding 任务不需要长篇解释

### 规则 3：`file_path:line_number` 格式

**为啥**：
- 让用户能在 IDE 里 ⌘+click 跳转
- 这是 UX 细节，但**写进 prompt 才能保证一致**

### 规则 4：GitHub 用 `owner/repo#123` 格式

**为啥**：
- Markdown 渲染时会自动变 clickable
- 写 `https://github.com/...` 反而占字符

### 规则 5：Don't use a colon before tool calls

**为啥**（这条最妙）：
- 工具调用是结构化的，UI 可能不显示
- 如果模型写 "让我读一下：" 然后调工具，UI 上看就是一个**孤零零的冒号**
- 这条是**用户体验事故**驱动的

---

## 💡 学习重点：每条规则都源于真实问题

| 规则 | 源于什么 |
|---|---|
| NEVER emoji | 用户反馈 + 终端兼容性 |
| 简短回答 | 成本 + 体验 |
| file:line | IDE 协作功能 |
| owner/repo#N | Markdown 渲染 |
| 冒号问题 | bug 报告反推 |

**写规则要从"用户痛点"出发**，不是凭空想象。

## 🐍 Python 模仿

```python
def get_identity():
    return "You are MiniCC, an interactive CLI coding agent."

def get_tone_and_style():
    rules = [
        "Only use emojis if the user explicitly requests it.",
        "Your responses should be short and concise.",
        "When referencing code, use file_path:line_number format.",
        "When referencing GitHub issues, use owner/repo#123 format.",
        "Do not use a colon before tool calls.",
    ]
    return "# Tone and style\n" + "\n".join(f" - {r}" for r in rules)
```

---

## ⚠️ 写身份/语气的反模式

| ❌ 反模式 | 后果 |
|---|---|
| "你是一个 AI 助手" | 太泛，模型按 ChatGPT 默认风格答 |
| "请保持友好" | 模型理解为"加 emoji + 拍马屁" |
| "回答尽量详细" | 模型给你 2000 字 |
| "不要说错话" | 完全没指导，模型懵 |

| ✅ 替代 | 效果 |
|---|---|
| "You are Claude Code, official CLI..." | 清晰角色 |
| "Be professional and concise" | 具体可执行 |
| "Keep responses under 200 words unless complex" | 有量化标准 |
| "If unsure, say so explicitly rather than guess" | 明确行为 |
