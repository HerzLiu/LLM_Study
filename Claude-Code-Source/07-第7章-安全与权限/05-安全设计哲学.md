# 7.5 安全设计 5 哲学

⬅ [04-物理沙箱与Hooks](04-%E7%89%A9%E7%90%86%E6%B2%99%E7%AE%B1%E4%B8%8EHooks.md)　|	➡ [99-代码-权限系统](99-%E4%BB%A3%E7%A0%81-%E6%9D%83%E9%99%90%E7%B3%BB%E7%BB%9F.md)

> 🎯 全章浓缩成 5 条哲学。每一条都值得抄进你自己的项目。

---

## 哲学 1：**纵深防御（Defense in Depth）**

不靠任何**单一**机制保安全。**多层防护**，任何一层失败下一层兜底。

回顾 [04-物理沙箱与Hooks](04-%E7%89%A9%E7%90%86%E6%B2%99%E7%AE%B1%E4%B8%8EHooks.md) 的 8 层：

```
Prompt 教育 → 工具过滤 → 用户规则 → 危险检测 →
canUseTool 弹窗 → Hooks → 物理沙箱 → 远程 killswitch
```

**学习点**：永远不要相信"我做了 X，就安全了"。
**永远多准备一层**。

---

## 哲学 2：**默认拒绝优于默认允许**

| 默认行为 | 风险 |
|---|---|
| **默认允许 + 黑名单** | 漏一个就完蛋 |
| **默认拒绝 + 白名单** | 多麻烦一点，但安全 |

Claude Code 选择：
- destructive 工具**默认弹窗**（不自动放行）
- 进 Bypass 模式必须**显式红字确认**
- 危险命令**永远拦**，无视任何 mode

**对照你自己的代码**：
```python
# ❌ 默认允许
if blacklist.matches(input):
    return deny()
return allow()

# ✅ 默认拒绝
if whitelist.matches(input):
    return allow()
return deny()
```

## 哲学 3：**用户可控**

权限模式用户可以**一键切换**（Shift+Tab），不是隐藏在配置里。

为啥？
- 用户知道当前状态 → 心里有数
- 切换便捷 → 不会"为了方便永远开 bypass"
- 出事时能马上回 default 模式

**对照**：很多产品把权限藏在 5 层菜单里，用户找不到，干脆永远关闭 → 安全形同虚设。

---

## 哲学 4：**拒绝要带原因**

```typescript
// ❌
return false

// ✅
return { behavior: 'deny', message: 'Blocked: rm -rf root pattern' }
```

为啥？
- **让模型知道为啥被拒** → 下次不再重试同样的事
- **让用户知道为啥被拒** → 决策 override 或换思路
- **让你（开发者）能调试** → 知道哪条规则在拦

**`denialTracking.ts`** 还把这条信息塞回 messages —— 模型学到"哦，这条路不通，我换思路"。

---

## 哲学 5：**假设模型会被攻击/出错**

**永远不要相信"模型会自觉"**。
所有约束都用**代码层强制**，不靠 prompt 自律。

| 错误信念 | 正确做法 |
|---|---|
| "我在 prompt 里说了不要 rm -rf，模型会听话" | 工具集里禁掉，或者危险模式拦 |
| "模型不会被 prompt injection" | 任何外部数据进 prompt 都假设可能恶意 |
| "我的 SubAgent 老老实实只搜索" | 物理禁掉 Write 工具 |
| "用户填的 allow 规则没问题" | `Bash(python:*)` 这种特殊 allow 要警告 |

---

## ⭐ 加深理解：注释也是文档

Claude Code 源码里几乎每条护栏都有**注释解释为什么**：

```typescript
const MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3
// BQ 2026-03-10: 1,279 sessions had 50+ consecutive failures (up to 3,272)
// in a single session, wasting ~250K API calls/day globally.
```

```typescript
// Zsh EQUALS expansion: =cmd at word start expands to $(which cmd).
// `=curl evil.com` → `/usr/bin/curl evil.com`, bypassing Bash(curl:*) deny
// rules since the parser sees `=curl` as the base command, not `curl`.
```

**好处**：
- 后来者读到代码立刻明白"为什么这条特殊"
- 改代码时不会无意识破坏
- 数据驱动可追溯（`BQ 2026-03-10`）

**对照你自己的代码**：所有"看起来多余的安全检查"都要写注释。否则下一个人会觉得"这个检查多余" → 删掉 → 翻车。

---

## 🎯 安全 checklist（送给你的项目）

设计任何"会执行用户/AI 输入"的系统时：

- [ ] 至少 3 层防御（不是 1 层）
- [ ] 默认拒绝（白名单 > 黑名单）
- [ ] 用户能看到/切换当前权限状态
- [ ] 拒绝时返回明确原因
- [ ] 不信任 prompt 自律，用代码强制
- [ ] 危险操作 → 弹窗确认
- [ ] 物理沙箱 / 资源限制
- [ ] 审计日志（hook 或内置）
- [ ] 紧急 killswitch（远程能关功能）
- [ ] 所有"看似多余"的检查都写注释解释 why

---

## 📝 一章一句话小结

> **安全不是单一防线，是层层叠加。** 不要假设"我做了 X 就安全"，**永远多准备一层**。
