# 1.3 最简核心循环：5 步看懂 Agent

⬅ [02-Claude-Code是什么](02-Claude-Code%E6%98%AF%E4%BB%80%E4%B9%88.md)　|	➡ [04-30行Python假Agent](04-30%E8%A1%8CPython%E5%81%87Agent.md)

> ⭐ 把所有花里胡哨的工程化细节剥掉，Claude Code 的本质就是这 5 步。

---

## 🎬 故事：餐厅服务员、厨师和传菜员

回到那家餐厅：

- **客人** → 服务员下单（user input）
- **服务员**（LLM）看单子，喊："番茄、鸡蛋拿来！"
- **传菜员**（工具执行器）跑去取，把食材摆到出菜口
- **服务员**看到食材到位，决定下一步："盐！"
- 反复 N 次，最后服务员说："上菜！" → 给客人

**这个流程是个循环**：服务员每次喊话 → 传菜员跑一趟 → 回来后服务员再决定下一步。
**循环不停，直到服务员说"上菜"。**

---

## 🔧 5 步核心循环（源码自带的图）

`_source/claude-code-source-code-main/README_CN.md` 里画了这张极简循环图：

```
用户 ──> messages[] ──> Claude API ──> 响应
                                       │
                          stop_reason == "tool_use"?
                          ┌────────────┴────────────┐
                          是                         否
                          │                          │
                    执行工具                   返回文本给用户
                    追加 tool_result               (循环结束)
                    回到 messages[] ──┐
                          ↑           │
                          └───────────┘
```

### 白话翻译

| 步 | 干啥 |
|---|---|
| **1** | 你输一句话，进程把它放进一个"消息列表" `messages` |
| **2** | 把整个 `messages` 发给 Claude API |
| **3** | Claude 回一个响应。**关键看 `stop_reason` 字段**：<br>`"end_turn"` → 它觉得说完了 → 给你看 → 结束<br>`"tool_use"` → 它想用工具 → 进入"执行工具" |
| **4** | 程序执行工具（比如读文件），把结果包成消息塞回 `messages` |
| **5** | 再发给 Claude → **回到第 2 步**（循环） |

---

## ⭐ 加深理解：3 个关键洞察

### 洞察 1：`messages` 是一条"只增不减的录像带"

每一轮，`messages` 末尾会追加两段：
- 模型的回复（含 tool_use）
- 工具的执行结果（tool_result）

下次请求时，**整盘录像带都重新喂给模型**。

视觉化：

```
轮 1 开始：
  [user: "帮我修 bug"]
       ↓ 调 API
  Claude 回："让我读一下 main.py" + tool_use Read
       ↓ 执行工具
  tool_result: <main.py 内容>

轮 2 开始：
  [user: "帮我修 bug",
   assistant: "让我读一下" + tool_use,
   user(tool_result): <main.py 内容>]
       ↓ 调 API
  ...
```

> ⚠️ 这就是为什么 token 会爆——录像带越来越长。治理方法见 [第 4 章](../04-%E7%AC%AC4%E7%AB%A0-%E4%B8%8A%E4%B8%8B%E6%96%87%E7%AE%A1%E7%90%86/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

### 洞察 2：循环退出条件是"没有 tool_use"，不是 stop_reason

Claude Code 源码有这条神奇注释：
```
// Note: stop_reason === 'tool_use' is unreliable -- it's not always set correctly.
```

意思是：API 有时候不会正确设 `stop_reason`。所以 Claude Code 改用一个更稳的判断：**只要本轮收到的 `toolUseBlock` 数量 > 0，就继续循环**。

### 洞察 3：所有工业级优化都建在这 5 步之外

| 工业级特性 | 在哪一步加？ |
|---|---|
| 流式（streaming） | 第 3 步：边收 chunk 边渲染 |
| 并发工具执行 | 第 4 步：多个 tool_use 一起跑 |
| 上下文压缩 | 第 2 步前：先看 messages 是否太长 |
| 权限弹窗 | 第 4 步前：每个工具问"能跑吗" |
| 子代理 | 第 4 步：某个工具叫 Task，会递归启动新循环 |

**整个 Claude Code = 这 5 步的工业级实现 + 上面这 5 类加料**。
