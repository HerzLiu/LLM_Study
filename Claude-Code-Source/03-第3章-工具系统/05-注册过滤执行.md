后厨有 100 道菜的食材，但每天给客人的菜单只有 30 道。

## 🔧 三阶段：定义 → 注册 → 过滤

### 阶段 1：定义所有工具

`src/tools.ts` 里有一个全量工具数组：

```typescript
const ALL_TOOLS = [
  FileReadTool, FileWriteTool, FileEditTool,
  BashTool, GrepTool, GlobTool,
  AgentTool, TodoWriteTool, WebFetchTool,
  // ... 40+ 个
]
```

### 阶段 2：按场景过滤

```typescript
function getAllAvailableTools(context) {
  let tools = ALL_TOOLS

  // 1. 用户配置禁用
  tools = tools.filter(t => !context.disabledTools.includes(t.name))

  // 2. 当前会话不可用（如 MCP 没连上时禁 MCP 工具）
  tools = tools.filter(t => t.isEnabled())

  // 3. Plan Mode 下只保留只读工具
  if (context.permissionMode === 'plan') {
    tools = tools.filter(t => t.isReadOnly({}))
  }

  // 4. 加上 MCP 服务器提供的工具
  tools.push(...loadMcpTools(context))

  // 5. 加上 Skill 提供的命令
  tools.push(...loadSkillTools(context))

  return tools
}
```

### 阶段 3：转成 API 格式


## ⭐ 加深理解：过滤的 4 个维度

| 维度 | 例子 |
|---|---|
| **用户配置** | `.claude/settings.json` 里 `"disabledTools": ["Bash"]` |
| **会话状态** | MCP 没连成功 → MCP 工具不可用 |
| **权限模式** | Plan Mode → 删掉所有写工具 |
| **动态发现** | MCP / Skill 动态加进来 |

**为什么不"教 LLM 不要用某些工具"，而是物理上不给？**

> **物理隔离 >>> Prompt 约束**。
> 哪怕模型"想"用 Write，工具集里压根没 Write，它**调不出来**。
> 用 Prompt 约束就只能"祈祷模型听话"，靠不住。

## 🔧 执行器：工具被调用后发生什么

`src/services/tools/StreamingToolExecutor.ts` 大概流程：

```python
async def execute_one(tool_use):
    # 1. 查注册表
    tool = registry.get(tool_use["name"])
    if not tool:
        return error("Unknown tool")

    # 2. 权限检查
    perm = await can_use_tool(tool, tool_use["input"], context)
    if perm.behavior == "deny":
        return error(perm.message)
    if perm.behavior == "ask":
        ok = await ask_user(...)
        if not ok: return error("User denied")

    # 3. 执行（带超时）
    try:
        result = await asyncio.wait_for(
            tool.call(**tool_use["input"]),
            timeout=tool.timeout or 60
        )
    except TimeoutError:
        return error("Tool timed out")
    except Exception as e:
        return error(f"Tool failed: {e}")

    # 4. 结果太大就持久化
    if len(result) > tool.max_result_size_chars:
        path = await persist_to_file(result)
        result = f"(result too large, saved to {path}, preview: {result[:500]}...)"

    # 5. 返回 tool_result
    return {
        "type": "tool_result",
        "tool_use_id": tool_use["id"],
        "content": result
    }
```

## 🔧 并发执行的逻辑

```python
async def execute_batch(tool_uses):
    parallel, serial = [], []
    for tu in tool_uses:
        tool = registry.get(tu["name"])
        if tool.is_concurrency_safe:
            parallel.append(tu)
        else:
            serial.append(tu)

    # 能并发的一起跑
    parallel_results = await asyncio.gather(*[
        execute_one(tu) for tu in parallel
    ])

    # 不能并发的串行跑
    serial_results = []
    for tu in serial:
        serial_results.append(await execute_one(tu))

    return parallel_results + serial_results
```

**例子**：
- 同时收到 3 个 Read + 1 个 Bash
- 3 个 Read 并发跑（is_concurrency_safe=True）
- 1 个 Bash 串行跑（is_concurrency_safe=False，避免命令互相干扰）

## ⚠️ 小白避坑

1. **`description` vs `prompt`**：转 API 时用的是 `prompt()` 不是 `description()`！
2. **工具 schema 是发给 LLM 的**：Schema 里每个字段的 `description` 都会影响模型行为
3. **Plan Mode 不是"教模型别动"**：是物理上不给写工具
4. **结果截断**：工具返回超过 `maxResultSizeChars` 会被截/存盘，模型看到的是截断后版本
