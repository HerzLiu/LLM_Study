# 2.1 从 30 行到工业级：差距在哪？

⬅ [00-章节总览](00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)　|	➡ [02-queryLoop骨架](02-queryLoop%E9%AA%A8%E6%9E%B6.md)

## 🎬 故事比喻：家用车 vs F1 赛车

|  | 家用车 | F1 赛车 |
|---|---|---|
| 主要部件 | 引擎+轮子+方向盘 | 引擎+轮子+方向盘 |
| 总成数量 | ~30000 个零件 | ~80000 个零件 |
| 多出来的零件干啥？ | — | 散热、空气动力、瞬态调教、应急熔断…… |

**架构是同一个**：都是引擎驱动轮子，方向盘控制方向。
**差距在"工业级护栏"**：F1 多出 5 万个零件，每一个都对应一个"如果不加，赛道上就翻车"的场景。

Claude Code 的主循环 vs 你 30 行 demo 也是这个关系。

| 维度 | 30 行 demo（[1.4 节](../01-%E7%AC%AC1%E7%AB%A0-Agent%E5%85%A5%E9%97%A8%E4%B8%8ECC%E6%80%BB%E8%A7%88/04-30%E8%A1%8CPython%E5%81%87Agent.md)） | Claude Code `query.ts` |

## ⭐ 加深理解：为什么需要这些护栏？

每条护栏背后都有一个"血泪故事"。

### 例：为什么要 maxTurns？

> 没有它：模型陷入死循环，烧光 API 配额
> 真实案例：早期 prompt 有 bug，模型反复"我要再读一次"，4 小时跑了 800 轮，烧了几百美金

### 例：为什么要 fallback model？

> 没有它：主模型挂了 → Agent 直接死
> 真实案例：Sonnet 短暂故障 → 切到 Opus 继续工作 → 用户无感

### 例：为什么要 auto-compact？

> 没有它：跑久了 → API 报 `prompt_too_long` → Agent 卡死
> 真实案例：长任务跑到 30 分钟自动崩，体验灾难

### 例：为什么用流式？

> 没有它：用户等 30 秒看不到任何反馈，以为程序挂了
> 真实案例：早期版本没流式，用户主动 Ctrl+C 中断率 40%

**每条护栏都是用户痛苦换来的**。学源码很重要的一部分就是看这些护栏，知道生产级代码需要考虑什么。
