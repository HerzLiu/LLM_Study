## 🎬 故事比喻：高速公路上的护栏

直路上跑车，护栏好像没用。

## 🔧 逐个拆解

### 1️⃣ `maxTurns` — 死循环熔断

```typescript
if (maxTurns && nextTurnCount > maxTurns) {
  yield createAttachmentMessage({ type: 'max_turns_reached', ... });
  return { reason: 'max_turns', turnCount: nextTurnCount };
}
```

**默认无上限**（你可以设 `--max-turns=50`）。
**真实事故**：早期没这玩意，模型 prompt 有 bug，反复"再试一次"，4 小时跑了 800 轮，烧几百刀 API 配额。

### 2️⃣ `taskBudgetRemaining` — token 预算追踪

```typescript
let taskBudgetRemaining: number | undefined = undefined
```

**功能**：跨 compact 边界保持准确的 token 预算计数。
**为啥复杂**：压缩后模型只看到 summary，会"低估"已花费 tokens。需要主动告诉服务端"虽然你看到的少，但实际花了 X"。

### 3️⃣ `autoCompact` — 上下文压缩

详见 [第 4 章](../04-%E7%AC%AC4%E7%AB%A0-%E4%B8%8A%E4%B8%8B%E6%96%87%E7%AE%A1%E7%90%86/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)。
**触发点**：每轮开始前检查 token，超阈值就调一次 LLM 做总结，用 summary 替换历史。

### 4️⃣ `fallbackModel` — 模型回退

```typescript
import { FallbackTriggeredError } from './services/api/withRetry.js'
```

**机制**：主模型 API 故障/超时 → 自动切到 fallback model（通常 Opus → Sonnet 或反之）。
**用户感受**：可能慢一点，但不会"突然 Agent 死了"。

### 5️⃣ `canUseTool` — 权限拦截

详见 [第 7 章](../07-%E7%AC%AC7%E7%AB%A0-%E5%AE%89%E5%85%A8%E4%B8%8E%E6%9D%83%E9%99%90/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)。
**位置**：每个工具执行前调一次，可以 deny / ask / allow。

### 6️⃣ `stopHook` — 用户自定义中断

```typescript
import { executeStopFailureHooks } from './utils/hooks.ts'
```

**机制**：用户可以在 `.claude/settings.json` 配 `Stop` hook，主循环每轮检查；hook 说"停"就停。
**用途**：CI 集成、企业合规、外部触发。

### 7️⃣ `mediaRecovery` — 图片附件超限恢复

```typescript
const mediaRecoveryEnabled = reactiveCompact?.isReactiveCompactEnabled() ?? false
```

**场景**：用户传了 10 张大图，API 报"图片太大"。
**恢复**：自动降清晰度 / 删掉部分图片 / 重试。

### 8️⃣ `maxOutputTokensRecovery` — 单轮输出超限重试

```typescript
let maxOutputTokensRecoveryCount: 0
```

**场景**：模型生成超过 `max_tokens` 被截断 → 自动给 `max_tokens` 涨一倍重试。
**上限**：最多重试几次，防止无限放大。

### 9️⃣ `consecutiveFailures` — 反复失败熔断

`compact/autoCompact.ts`：
```typescript
const MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3
// BQ 2026-03-10: 1,279 sessions had 50+ consecutive failures (up to 3,272)
// in a single session, wasting ~250K API calls/day globally.
```

**真实数据驱动**：工程师查 BigQuery 发现有用户在一次会话中尝试 3272 次压缩失败，浪费 25 万 API 调用/天。
**对策**：连续失败 3 次就停手。

## ⭐ 加深理解：护栏的设计哲学

### 哲学 1：**默认安全，可选解开**

`maxTurns` 默认有上限，你想跑长任务自己调。
`bypassPermissions` 默认关，要红字警告才能进。

### 哲学 2：**所有失败都要"可观测 + 可恢复"**

不光是"挂了报错"，要：
- 告诉用户哪挂了（事件类型、原因）
- 自动尝试恢复（fallback model、重试）
- 实在不行才退出，并解释为什么

### 哲学 3：**数据驱动阈值**

不是拍脑袋设 `MAX_FAILURES = 3`，是查日志后定的。
`BQ 2026-03-10` 这种注释是工程师查 BigQuery 那天的日期——所有阈值有据可查。

### 哲学 4：**护栏要写注释**

源码里几乎每个护栏都有 5-10 行注释解释"为什么需要这条"。**注释 ≠ 啰嗦，注释是"对后来人的保险"**。

## 🐍 把护栏加到 Python 版

在 [99-代码-Python版AgentLoop](99-%E4%BB%A3%E7%A0%81-Python%E7%89%88AgentLoop.md) 基础上加 3 条最实用的：

```python
MAX_TURNS = 30
MAX_TOKENS_PER_TURN = 100_000           # 单轮 token 上限
MAX_CONSECUTIVE_ERRORS = 3              # 连续错误熔断

async def agent_loop_with_guardrails(messages):
    state = {"turn": 1, "consecutive_errors": 0}

    while True:
        # 护栏 1: 轮次上限
        if state["turn"] > MAX_TURNS:
            yield {"event": "halt", "reason": "max_turns"}
            return

        # 护栏 2: 单轮 token 上限
        if estimate_tokens(messages) > MAX_TOKENS_PER_TURN:
            yield {"event": "compact_needed"}
            messages = await compact(messages)

        # 护栏 3: try-except + 连续错误熔断
        try:
            response = await call_llm(messages)
            state["consecutive_errors"] = 0     # 成功重置
        except Exception as e:
            state["consecutive_errors"] += 1
            if state["consecutive_errors"] >= MAX_CONSECUTIVE_ERRORS:
                yield {"event": "halt", "reason": "too_many_errors", "error": str(e)}
                return
            yield {"event": "retry", "attempt": state["consecutive_errors"]}
            continue                            # 跳过本轮，进下一轮重试

        # ... 正常处理 ...
        state["turn"] += 1
```
