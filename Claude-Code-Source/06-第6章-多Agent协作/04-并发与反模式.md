# 6.4 并发派发 + 反模式

---

## 🎬 故事比喻：5 个实习生同时去 5 个图书馆

老板说："去查 5 家咖啡店的价格"。

| 方案 | 总耗时 |
|---|---|
| 1 个实习生跑 5 家 | 5 × 30 分钟 = 150 分钟 |
| **5 个实习生并发** | 30 分钟 |

**5 倍速度**。SubAgent 并发就是这个原理。

---

## 🔧 并发派发

主 Agent 可以一次发出多个 Task 工具调用，**这些 SubAgent 并发执行**：

```json
[
  {"name": "Task", "input": {"subagent_type": "Explore", "prompt": "Find auth code"}},
  {"name": "Task", "input": {"subagent_type": "Explore", "prompt": "Find DB schema"}},
  {"name": "Task", "input": {"subagent_type": "Explore", "prompt": "Find API routes"}}
]
```

主 Agent 等三个都完成，拿到三段摘要后再综合分析。

**这是"研究类任务"的最优解**：拆 N 个独立问题 → 并发派 N 个 SubAgent → N 倍速。

---

## 🐍 Python 实现

```python
async def main_agent_research():
    """主 Agent 并发派 3 个 SubAgent。"""
    # ⭐ asyncio.gather 让 3 个 SubAgent 并发跑
    results = await asyncio.gather(
        spawn_subagent("Explore", "Find all auth files"),
        spawn_subagent("Explore", "Find all DB schemas"),
        spawn_subagent("Explore", "Find all API routes"),
    )
    # 拿到 3 段摘要，综合分析
    summary = "Auth: {}\nDB: {}\nAPI: {}".format(*results)
    return summary
```

总耗时 ≈ max(3 个 SubAgent 耗时)，**不是 sum**。

## ⭐ 加深理解：什么任务适合并发？

✅ **适合**：
- 独立的多个搜索（找 A、找 B、找 C）
- 多个无依赖的验证
- 多个文件的独立审查

❌ **不适合**：
- 串行依赖（先找文件，再改文件）
- 共享状态（多个 SubAgent 同时改同一文件）
- 累积式分析（A 的结论影响 B 的查询）

判断标准：**问题能否拆成 N 个独立子问题**？

## ⚠️ 6 大反模式

### ❌ 反模式 1：SubAgent 嵌套太深

```
Main → Sub1 → Sub2 → Sub3 → Sub4...
```

每嵌套一层：
- prompt cache miss
- 启动延迟累积
- 上下文传递变形（每层都重新解释）

**经验**：3 层就该停。Claude Code 通过 `disallowedTools: [AGENT_TOOL_NAME]` 物理禁掉。

### ❌ 反模式 2：给 SubAgent "理解任务"

```
❌ Task(prompt="看完代码后帮我修 bug")
✅ Task(prompt="在 src/auth.py:42 把 == 改成 ===")
```

理解和综合是主 Agent 的事，SubAgent 只负责执行。

### ❌ 反模式 3：派完后偷看进度

```
❌ result = await spawn_subagent(...)
   progress = await read("/tmp/sub_progress.log")  # 把脏 context 拉回主
```

违背"上下文隔离"初衷。

### ❌ 反模式 4：小任务也派 SubAgent

```
❌ Task(subagent_type="Explore", prompt="Read this one file")
✅ Read(file_path="...")   # 直接调
```

SubAgent 启动有 overhead（prompt 加载、消息初始化）。**小任务直接调专用工具更快**。

### ❌ 反模式 5：不限制 SubAgent 工具集

```
❌ Explore Agent 允许 Write   → 真的会改文件
✅ Explore Agent 禁 Write     → 物理隔离
```

### ❌ 反模式 6：用昂贵模型跑通用任务

```
❌ Explore Agent 用 Opus     → 烧钱
✅ Explore Agent 用 Haiku    → 同样效果，省 12 倍
```

## ⭐ 加深理解：并发的 token 经济学

假设你要审查一个项目：

### 方案 A：主 Agent 自己干

```
主 Agent 跑 50 个工具调用
总 token: 100K
耗时: 5 分钟
费用（Sonnet $3/M）: $0.30
```

### 方案 B：派 5 个 Explore SubAgent (Haiku 并发)

```
主 Agent context: 10K（轻量）
5 个 SubAgent 各 20K (Haiku $0.25/M)：5 × 20K × $0.25 = $0.025
主 Agent 综合：10K × $3 = $0.03
总耗时: 1 分钟（并发）
总费用: $0.055
```

**便宜 5 倍 + 快 5 倍**。

## 🛡️ 真实使用 checklist

派 SubAgent 前问自己：

- [ ] 这个子任务能"独立"完成吗？（不依赖主 Agent 后续决策）
- [ ] 中间产物是否"不需要"出现在主 context？
- [ ] 任务大小够大吗？（< 5 个工具调用别派）
- [ ] 选对了 subagent_type？
- [ ] prompt 写够具体？包含背景？
- [ ] 是否要并发派多个？
- [ ] 嵌套深度是否 < 3？
