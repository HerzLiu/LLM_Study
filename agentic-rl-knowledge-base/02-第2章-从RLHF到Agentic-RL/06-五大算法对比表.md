## 🧭 2.6.1 谱系图（再回顾）

```
                              【起点】
                          预训练 + SFT
                                │
                                ▼
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
   【偏好驱动】              【可验证驱动】          【奖励粒度】
        │                       │                       │
   2.1 RLHF                2.4 RLVR                2.5 PRM
   (SFT+RM+PPO)         (验证器代替 RM)        (过程奖励)
        │                       │                  vs
   2.2 DPO                      │                  ORM
   (省 RM + 离线)               │
                                │
                       【算法骨架】
                          2.3 GRPO
                       (组内相对，省 critic)
                                │
                                ▼
                      Agentic RL 标准配方:
                      GRPO + RLVR + (可选 PRM)
```

## 🏆 2.6.2 核心对比表（最重要的一张）

| 维度 | PPO (RLHF) | DPO | GRPO | RLVR | PRM |
|---|---|---|---|---|---|
| **类别** | RL 算法 | 偏好优化 | RL 算法 | **奖励范式** | **奖励范式** |
| **Reward 来源** | RM（人标） | 偏好对（人标） | 任意 | **客观验证器** | 中间步骤打分 |
| **需要 critic？** | ✅ 是 | ❌ 否 | ❌ 否 | 配 PPO 时要 | 配 PPO 时要 |
| **需要 RM？** | ✅ 是 | ❌ 否 | 看 reward 来源 | ❌ 否 | 看是否训 PRM |
| **On/Off policy** | On | Off | On | On | 看用法 |
| **Rollout 成本** | 中（1 个） | **0（静态数据）** | **高（K 倍）** | 看算法 | 看算法 |
| **训练稳定性** | 难调 | **稳** | 中 | 看 verifier 质量 | 看 PRM 质量 |
| **适合任务** | 通用 | alignment | 可验证 reward | 数学/代码/工具 | 长链推理 |
| **典型用例** | InstructGPT/ChatGPT | Zephyr/小模型对齐 | DeepSeek-R1/SWE-RL | DeepSeek-R1/SWE-RL | OpenAI math reasoning |
| **代表论文** | InstructGPT (2022) | DPO (2023) | DeepSeekMath (2024) | DeepSeek-R1 (2025) | Let's Verify (2023) |
| **当前主流？** | 经典骨架 | 工业常用 | **最热** ⭐ | **最热** ⭐ | 进阶 |

## 🔧 2.6.3 工程成本对比

| 算法 | 人标成本 | 训练显存 | 训练时间 | rollout 次数 |
|---|---|---|---|---|
| PPO (RLHF) | 高 (RM 偏好对) | actor + critic + RM + ref | 高 | 1 个 prompt 1 次 |
| DPO | 中 (偏好对) | actor + ref | **最低** | **0** |
| GRPO | **0**（如果 reward 自动） | actor + ref（**无 critic**） | 中 | 1 个 prompt **K 次** |
| RLVR | **0**（用 verifier） | 看搭配算法 | 看 verifier 慢不慢 | 看搭配算法 |
| PRM | **极高**（每步标注） | 看搭配算法 | 看 PRM 训练成本 | 看搭配算法 |

## 🎯 2.6.4 决策树：你该用哪个？

```
                    我要做什么？
                       │
        ┌──────────────┼──────────────────────┐
        │              │                      │
   alignment       reasoning/code/         多步 agent 长链推理
   单轮对话         math 任务                │
        │              │                      │
        ▼              ▼                      ▼
      DPO          GRPO + RLVR           GRPO + RLVR + (PRM 辅助)
   (最便宜)       (主流配方)             (长程信用分配)
        │              │                      │
   如果有大量      （DeepSeek-R1                如果 PRM 标注太贵：
   人标偏好对      SWE-RL 都是这个）          → 用自动 PRM
   且预算大:                                      (执行反馈打分)
   → PPO (RLHF)
```

## 🧪 2.6.5 在 Code Agent 中的"现实选择"

如果你目标是 Code Agentic RL，**99% 情况这样选**：

| 阶段 | 推荐 |
|---|---|
| **冷启动** | **SFT**（用 SWE-Gym/SWE-smith 的成功 trajectory） |
| **初阶训练** | **DPO**（用 pytest 自动构造 chosen/rejected） |
| **进阶训练** | **GRPO + RLVR**（同 issue sample K patch，组内相对） |
| **难点突破** | + 自动 **PRM**（step-level execution 信号） |
| **不推荐** | PPO + RM（除非你有大量 code 偏好标注） |

## 💡 2.6.6 常见黑话翻译速查

| 黑话 | 翻译 |
|---|---|
| "用 GRPO 训" | 用 [GRPO](03-GRPO%EF%BC%88%E7%BB%84%E5%86%85%E7%9B%B8%E5%AF%B9%E4%BC%98%E5%8A%BF%EF%BC%89.md)，**没 critic**，组内相对 advantage |
| "RLVR-based training" | 用 [可验证 reward](04-RLVR%EF%BC%88%E5%8F%AF%E9%AA%8C%E8%AF%81%E5%A5%96%E5%8A%B1%EF%BC%89.md)，**不要 RM** |
| "rule reward" | 规则打分（如 patch diff size 惩罚） |
| "verifier reward" | learned verifier 打分（[PRM 类似](05-PRM%E4%B8%8EORM%EF%BC%88%E8%BF%87%E7%A8%8Bvs%E7%BB%93%E6%9E%9C%E5%A5%96%E5%8A%B1%EF%BC%89.md)） |
| "outcome reward" | 只看 final 结果（ORM） |
| "process reward" | 看每一步（PRM） |
| "在线 / 离线 RL" | rollout vs 静态数据集 |
| "policy gradient" | 用 ∇log π · A 更新 |
| "actor-critic" | 同时训 π（actor）和 V（critic） |
| "KL penalty" | β · KL(π‖π_ref)，防偏离 |

## ⚠️ 2.6.7 常见误用

| 误用 | 真相 |
|---|---|
| "GRPO 是 RLVR" | 错。GRPO 是**算法**，RLVR 是**奖励范式**，两者正交 |
| "DPO 是 RL" | 半对。DPO 数学上和 RL 等价，但实际**不在线 rollout**，更像偏好优化 |
| "RLVR 不需要 RL 算法" | 错。RLVR 需要算法（PPO/GRPO）来更新 π，**RLVR 只是说 reward 怎么来** |
| "PRM 替代 ORM" | 不一定。两者**可以混合**，且 ORM 在很多任务足够 |
| "Agentic RL 必须用 RLVR" | 不一定，**但 99% 实际系统都用 RLVR**（因为可验证 task 多） |

## 📌 2.6 节要点

| 算法 | 一句话 | 何时用 |
|---|---|---|
| **PPO** | RL 的算法底座 + clip + KL | 通用 / 经典 RLHF |
| **DPO** | 偏好对直接训 π，绕过 RM | alignment / 静态偏好 |
| **GRPO** | 组内相对 advantage，省 critic | **可验证 reward 主流** |
| **RLVR** | 用客观验证器代替 RM | **代码/数学/工具** |
| **PRM** | 评每一步，缓解 sparse | 长链推理 / 长 trajectory |

| 黄金配方 | GRPO + RLVR（+ 可选 PRM） |
|---|---|
