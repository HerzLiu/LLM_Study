## 🤔 两个 Toy 怎么选？

| 维度 | 5.1 Calculator | 5.2 Bug-Fix Gym |
|---|---|---|
| **原始资料** | `07-toy-project-spec.md` | `code-agentic-rl/08-toy-bugfix-agent-gym.md` |
| **任务** | 多步算术 / 单位转换 | 修 Python pytest bug |
| **动作空间** | 调 calculator + 文本答案 | search / read / edit / run_tests / final |
| **Reward 来源** | 答案 exact match | pytest 通过率 |
| **代码量** | 极小（~200 行就够） | 中等（每个 task 一个 src+tests 目录） |
| **对你目标** | ⭐⭐ 暖手 | ⭐⭐⭐⭐⭐ 直击 Code Agentic RL |
| **失败模式** | 工具格式错、解析漏洞 | localization 错、patch overfit、regression、tool misuse |

**强烈建议**：

> 跳过 5.1，直接做 5.2。
> 你的目标明确是 Code，Calculator 学到的东西在 Bug-Fix Gym 都能学到。

## ✅ 验收标准（来自原始资料 § 验收标准）

### 最低验收（Bug-Fix Gym 版）

- 至少 5 个可运行任务
- 每个任务有 failing test、gold summary、metadata
- 能运行 baseline 并保存 trajectory
- 能计算 success rate、invalid action rate、regression rate
- 能输出失败模式表

### 理想验收

- 30 个任务
- 至少 2 个 baseline 对比（如 No-tool vs ReAct vs Test-feedback loop）
- 有 verifier/rerank 结果
- 3 条「失败 → 成功」trajectory case study
- 一份 reward hacking 风险分析

---

## ⚠️ 学习建议

1. **先做 pilot 5 个，再扩到 30 个**：原始资料明确写了这条。
2. **不要一开始接 GRPO 训练**：先保存 trajectory + 算指标即可，训练是进阶。
3. **失败模式 taxonomy 必须写出来**：这是你"做过实验"的证据。
4. **如果有 GPU**：进阶可接 [Hello-Agents 11.4](../../Hello-Agents/11-%E7%AC%AC11%E7%AB%A0-Agentic-RL/04-GRPO%E8%AE%AD%E7%BB%83%E5%AE%9E%E6%88%98.md)，用 toy 数据跑 SFT/GRPO。

## 📝 本章一句话小结

> **第 1-4 章是地图，第 5 章是腿。**
> 没跑过 toy gym，你在面试或同行评议里说"我会 Code Agentic RL"是站不住的。
