## 📋 A.1.0 19 个术语速查（按出现频率排序）

### 1. RLHF

| 一句话 | 人类偏好 → reward model → PPO 优化 LLM |
|---|---|
| 常见误区 | 以为 RLHF 一定是 agentic；很多 RLHF 是**单轮**回答质量优化 |
| 详讲 | [01-RLHF三阶段（SFT-RM-PPO）](../02-%E7%AC%AC2%E7%AB%A0-%E4%BB%8ERLHF%E5%88%B0Agentic-RL/01-RLHF%E4%B8%89%E9%98%B6%E6%AE%B5%EF%BC%88SFT-RM-PPO%EF%BC%89.md) |

### 2. RLAIF

| 一句话 | AI 偏好或规则反馈替代人类反馈 |
|---|---|
| 常见误区 | 以为 AI judge 一定可靠；它也会偏置和被 **reward hacking** |
| 代表 | Constitutional AI (Anthropic) |

### 3. DPO

| 一句话 | 用偏好对直接训练策略，不显式 RM，不在线 rollout |
|---|---|
| 常见误区 | 以为 DPO 是强化学习完整替代；它更像**偏好优化方法** |
| 详讲 | [02-DPO（偏好直接优化）](../02-%E7%AC%AC2%E7%AB%A0-%E4%BB%8ERLHF%E5%88%B0Agentic-RL/02-DPO%EF%BC%88%E5%81%8F%E5%A5%BD%E7%9B%B4%E6%8E%A5%E4%BC%98%E5%8C%96%EF%BC%89.md) |

### 4. PPO for LLM

| 一句话 | 把 LLM 输出当策略行为，用 reward 和 KL 约束更新 |
|---|---|
| 常见误区 | 只看最终 reward，忽略 **KL、value head、rollout 成本** |
| 详讲 | [04-PPO与KL约束](../01-%E7%AC%AC1%E7%AB%A0-RL%E6%9C%80%E5%B0%8F%E5%BF%85%E8%A6%81%E5%9F%BA%E7%A1%80/04-PPO%E4%B8%8EKL%E7%BA%A6%E6%9D%9F.md) |

### 5. GRPO

| 一句话 | 同 prompt 多采样，用**组内相对奖励**估 advantage，**通常省 critic** |
|---|---|
| 常见误区 | 以为 GRPO 只适合数学；它也可用于可验证任务，**但 reward 设计仍关键** |
| 详讲 | [03-GRPO（组内相对优势）](../02-%E7%AC%AC2%E7%AB%A0-%E4%BB%8ERLHF%E5%88%B0Agentic-RL/03-GRPO%EF%BC%88%E7%BB%84%E5%86%85%E7%9B%B8%E5%AF%B9%E4%BC%98%E5%8A%BF%EF%BC%89.md) |

### 6. RLVR

| 一句话 | Reinforcement Learning with Verifiable Rewards，用**可验证信号**训练 |
|---|---|
| 常见误区 | 以为 verifier 一定完美；**测试覆盖和答案解析都可能被钻空子** |
| 详讲 | [04-RLVR（可验证奖励）](../02-%E7%AC%AC2%E7%AB%A0-%E4%BB%8ERLHF%E5%88%B0Agentic-RL/04-RLVR%EF%BC%88%E5%8F%AF%E9%AA%8C%E8%AF%81%E5%A5%96%E5%8A%B1%EF%BC%89.md) |

### 7. Agentic RL

| 一句话 | 用 RL 训练多轮 agent 在环境中**计划、调工具、观察反馈、完成任务** |
|---|---|
| 常见误区 | 以为用了 agent 框架就是 Agentic RL；**必须有奖励优化训练才算** |
| 详讲 | [01-Agentic-RL定义与边界](../03-%E7%AC%AC3%E7%AB%A0-%E9%80%9A%E7%94%A8Agentic-RL%E8%BE%B9%E7%95%8C%E4%B8%8E%E5%9B%BE%E8%B0%B1/01-Agentic-RL%E5%AE%9A%E4%B9%89%E4%B8%8E%E8%BE%B9%E7%95%8C.md) |

### 8. Tool-use RL

| 一句话 | Agentic RL 子类，重点训练**何时、如何调工具** |
|---|---|
| 常见误区 | **只训练工具格式**，不训练**调用时机和失败恢复** |
| 详讲 | [能力栈 §4.2.5](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/02-Code-Agent%E8%83%BD%E5%8A%9B%E6%A0%8810%E6%A8%A1%E5%9D%97.md) |

### 9. Multi-agent RL (MARL)

| 一句话 | 多个策略/agent 在共享环境中学习（合作或竞争） |
|---|---|
| 常见误区 | LLM 多 agent 编排**不一定是 MARL**；很多只是 workflow |
| 详讲 | [§3.1.2 表格](../03-%E7%AC%AC3%E7%AB%A0-%E9%80%9A%E7%94%A8Agentic-RL%E8%BE%B9%E7%95%8C%E4%B8%8E%E5%9B%BE%E8%B0%B1/01-Agentic-RL%E5%AE%9A%E4%B9%89%E4%B8%8E%E8%BE%B9%E7%95%8C.md) |

### 10. Self-play

| 一句话 | 模型通过和**自己或对手**交互产生训练信号 |
|---|---|
| 常见误区 | self-play **不等于** self-improvement；**需要有效选择和验证信号** |

### 11. Self-improvement

| 一句话 | 模型从自生成数据、反思、反馈或 verifier 中**迭代提升** |
|---|---|
| 常见误区 | 没有外部检验时**容易自我强化错误** |

### 12. ORM

| 一句话 | **Outcome** Reward Model，只评价**最终答案或最终状态** |
|---|---|
| 常见误区 | 对长链任务**信用分配弱** |
| 详讲 | [05-PRM与ORM（过程vs结果奖励）](../02-%E7%AC%AC2%E7%AB%A0-%E4%BB%8ERLHF%E5%88%B0Agentic-RL/05-PRM%E4%B8%8EORM%EF%BC%88%E8%BF%87%E7%A8%8Bvs%E7%BB%93%E6%9E%9C%E5%A5%96%E5%8A%B1%EF%BC%89.md) |

### 13. PRM

| 一句话 | **Process** Reward Model，评价**中间步骤** |
|---|---|
| 常见误区 | 标注成本高，且**步骤粒度设计**很重要 |
| 详讲 | [05-PRM与ORM（过程vs结果奖励）](../02-%E7%AC%AC2%E7%AB%A0-%E4%BB%8ERLHF%E5%88%B0Agentic-RL/05-PRM%E4%B8%8EORM%EF%BC%88%E8%BF%87%E7%A8%8Bvs%E7%BB%93%E6%9E%9C%E5%A5%96%E5%8A%B1%EF%BC%89.md) |

### 14. Verifier-based training

| 一句话 | 用**规则、单测、执行器、形式系统或 judge** 验证输出 |
|---|---|
| 常见误区 | verifier 覆盖不足时会产生 **reward hacking** |
| 详讲 | [04-RL如何用在Code-Agent上](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/04-RL%E5%A6%82%E4%BD%95%E7%94%A8%E5%9C%A8Code-Agent%E4%B8%8A.md) |

### 15. Agent benchmark

| 一句话 | 评估 agent 在交互环境中的**成功率、效率、鲁棒性** |
|---|---|
| 常见误区 | 只看总分，**忽略环境偏差、成本、失败模式** |
| 代表 | AgentBench / tau-bench / AppWorld / SWE-bench |

### 16. Trajectory

| 一句话 | 一次 episode 中 **observation、action、reward 的序列** |
|---|---|
| 常见误区 | **只保存最终答案**，导致无法做失败分析和 credit assignment |
| 详讲 | [01-MDP与轨迹（用Agent语言讲RL）](../01-%E7%AC%AC1%E7%AB%A0-RL%E6%9C%80%E5%B0%8F%E5%BF%85%E8%A6%81%E5%9F%BA%E7%A1%80/01-MDP%E4%B8%8E%E8%BD%A8%E8%BF%B9%EF%BC%88%E7%94%A8Agent%E8%AF%AD%E8%A8%80%E8%AE%B2RL%EF%BC%89.md) |

### 17. Credit assignment

| 一句话 | 判断**哪些中间动作**导致最终成功或失败 |
|---|---|
| 常见误区 | 长程任务中**只用最终 reward** 往往学习信号太粗 |
| 详讲 | [05-Sparse-Reward与信用分配](../01-%E7%AC%AC1%E7%AB%A0-RL%E6%9C%80%E5%B0%8F%E5%BF%85%E8%A6%81%E5%9F%BA%E7%A1%80/05-Sparse-Reward%E4%B8%8E%E4%BF%A1%E7%94%A8%E5%88%86%E9%85%8D.md) |

### 18. Sparse reward

| 一句话 | **大多数步骤没有奖励**，只有最终成功/失败 |
|---|---|
| 常见误区 | 简单加 reward shaping **可能改变目标** |
| 详讲 | [05-Sparse-Reward与信用分配](../01-%E7%AC%AC1%E7%AB%A0-RL%E6%9C%80%E5%B0%8F%E5%BF%85%E8%A6%81%E5%9F%BA%E7%A1%80/05-Sparse-Reward%E4%B8%8E%E4%BF%A1%E7%94%A8%E5%88%86%E9%85%8D.md) |

### 19. Reward hacking ⚠️

| 一句话 | 模型利用**奖励漏洞**获得高分但**不真正完成目标** |
|---|---|
| 常见误区 | Agentic RL 中**比单轮问答更常见**，因为环境和工具更复杂 |
| 详讲 | [08-Reward-Hacking与Sandbox安全](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/08-Reward-Hacking%E4%B8%8ESandbox%E5%AE%89%E5%85%A8.md) |

## 🌟 A.1.2 本库主动扩展的术语（不在原始资料里）

下列术语不在 `05-glossary.md` 但在本库出现频繁，**也给一句话**：

| 术语 | 一句话 | 来源 |
|---|---|---|
| **MDP / POMDP** | 决策过程的数学框架 / 状态部分可观测版 | 本库 §1.1 |
| **Policy / Value / Advantage** | π / V / A，RL 四件套 | 本库 §1.2 |
| **Actor-Critic** | 同时训 π（actor）和 V（critic） | 本库 §1.3 |
| **KL penalty** | 防止 π 偏离 reference 的约束项 | 本库 §1.4 |
| **Reference model** | 冻结的 SFT 模型，**只用于算 KL** | 本库 §1.4 |
| **Value head** | 加在 LLM 上的标量输出层 | 本库 §1.4 |
| **Rollout** | 用当前 π 采样 prompt → response 这一过程 | 本库 §1.4 |
| **FAIL_TO_PASS / PASS_TO_PASS** | SWE-bench 评测的两类测试 | 本库 §4.2.9 |
| **Resolved rate** | SWE-bench 完全解决的比例 | 本库 §4.2.9 |
| **ACI (Agent-Computer Interface)** | 为 LLM 优化的命令集（vs raw bash） | 本库 §4.3.3 |
| **Sandbox** | 容器隔离 + 网络限制 + 资源配额 | 本库 §4.8 |
