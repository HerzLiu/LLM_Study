## ⚠️ A.2.2 资料中的不一致点

### 不一致 #1：SWE-bench 仓库 URL 两套写法（**已实查 2026-06-05**）

| 文件 | 写法 |
|---|---|
| `03-repos.md` (通用) row 22 | `https://github.com/SWE-bench/SWE-bench` |
| `code-agentic-rl/03-repos.md` row 9 | `https://github.com/princeton-nlp/SWE-bench` |
| `code-agentic-rl/07-shortest-path.md` row 33 | `https://github.com/princeton-nlp/SWE-bench` |

**实查结论**：

| 组织 | 当前状态 |
|---|---|
| `SWE-bench/SWE-bench` | ✅ **当前官方主仓库**（GitHub README 自我声明：5.1k stars，42 tags，最新维护） |
| `princeton-nlp/SWE-bench` | ✅ **仍然有效**（HuggingFace `datasets` 和 SWE-Llama 模型仍挂在此），README 里 `git clone git@github.com:princeton-nlp/SWE-bench.git` 还在用 |

→ **两个都活跃**：`SWE-bench/SWE-bench` 是新主仓库（代码），`princeton-nlp/SWE-bench` 仍承载 HF dataset 和模型。
→ **本知识库统一采用** `princeton-nlp/SWE-bench`（与多数 SWE 工具默认 path 一致），但**两个 URL 都能跳转**。
→ **用户使用时**：clone repo 用 `git@github.com:princeton-nlp/SWE-bench.git`（与官方 README 一致），引用文档跳 `SWE-bench/SWE-bench` 也 OK。

### 不一致 #2：通用最短路径 vs Code 最短路径的"5 篇必读"重叠少

| 通用 `06-shortest-path.md` 5 篇必读 | Code `07-shortest-path.md` 5 篇必读 |

### 不一致 #3：通用 02-papers.md 必学 10 篇 vs 通用 06-shortest-path 10 篇

通用 02-papers.md 必学表里有 **12 篇**（包含 ArCHer / Agent Lightning / GiGPO），但 06-shortest-path 推荐顺序里只列了 **10 篇**（去掉 ArCHer 和 GiGPO，把 GRPO/RLVR 内容并入 DeepSeekMath/R1）。

→ 不是错，是"必学全集 vs 最短路径"的差异。
→ **用户使用时**：6 周计划读全 12 篇，14 天计划读 10 篇。

### 不一致 #4：Code 专题最短路径 10 篇 vs 必学 9 篇

`code-agentic-rl/02-papers.md` 必学表 9 篇 + `code-agentic-rl/07-shortest-path.md` 最短路径 10 篇，**OpenHands** 在必学是 9 个里的第 4 个，在最短路径是第 4 个。两者基本对齐，**只是 LEVER 在必学里**（row 8），在最短路径**不在**。

→ 本知识库 [05-必读论文10篇精读卡（SWE-bench线）](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/05-%E5%BF%85%E8%AF%BB%E8%AE%BA%E6%96%8710%E7%AF%87%E7%B2%BE%E8%AF%BB%E5%8D%A1%EF%BC%88SWE-bench%E7%BA%BF%EF%BC%89.md) 采用合集 10 篇方案（必学 9 + LEVER）。

## ⚠️ A.2.5 概念/任务设计上需要警惕的点

### 通用 toy（Calculator）vs Code toy（Bug-Fix Gym）的混淆

- 通用 `07-toy-project-spec.md`：**Calculator** 工具调用任务
- Code 专题 `08-toy-bugfix-agent-gym.md`：**Python pytest bug 修复**任务

**两个 toy 设计目标完全不同**，但都叫 "toy project"，新手容易以为是同一个项目演进。
→ 本库 [00-章节总览](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E9%A1%B9%E7%9B%AE/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md) 已明确区分。

### "Agentic RL 用了 agent 框架就是 Agentic RL" 的误解

资料 `05-glossary.md` 多处强调：

> 用 LangGraph / AutoGen / workflow 不等于 Agentic RL，**必须有奖励优化训练**才算。

但实际很多工业讨论混用这两个概念。
→ 本库在 [00-总览](../00-%E6%80%BB%E8%A7%88.md) 和 [01-Agentic-RL定义与边界](../03-%E7%AC%AC3%E7%AB%A0-%E9%80%9A%E7%94%A8Agentic-RL%E8%BE%B9%E7%95%8C%E4%B8%8E%E5%9B%BE%E8%B0%B1/01-Agentic-RL%E5%AE%9A%E4%B9%89%E4%B8%8E%E8%BE%B9%E7%95%8C.md) 反复强调。

### "Self-play = Self-improvement" 的误解

资料 `05-glossary.md`：

> Self-play **不等于** self-improvement；需要有效选择和验证信号。

写笔记时请保留这个区分。
