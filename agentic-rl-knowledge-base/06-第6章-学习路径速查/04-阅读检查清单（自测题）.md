## ✅ 6.4.1 9 道核心自测题

### Q1：Agentic RL 和 RLHF / DPO / GRPO / RLVR 的关系是什么？

**关键点**：

- Agentic RL = LLM Agent + 多轮环境 + RL 奖励优化
- RLHF / DPO / GRPO 是**算法**
- RLVR 是**奖励范式**
- 它们可以组合（例如 GRPO + RLVR）

**答不出？** → 重读 [01-Agentic-RL定义与边界](../03-%E7%AC%AC3%E7%AB%A0-%E9%80%9A%E7%94%A8Agentic-RL%E8%BE%B9%E7%95%8C%E4%B8%8E%E5%9B%BE%E8%B0%B1/01-Agentic-RL%E5%AE%9A%E4%B9%89%E4%B8%8E%E8%BE%B9%E7%95%8C.md) + [06-五大算法对比表](../02-%E7%AC%AC2%E7%AB%A0-%E4%BB%8ERLHF%E5%88%B0Agentic-RL/06-%E4%BA%94%E5%A4%A7%E7%AE%97%E6%B3%95%E5%AF%B9%E6%AF%94%E8%A1%A8.md)

### Q2：Code Agent 和普通 code generation model 的区别是什么？

**关键点**：

- Code generation model（如 Codex / CodeLlama）：输入 prompt → 输出代码段
- Code Agent：在 **repo + execution env** 里**多步**完成 issue 修复
- 紧凑公式：**Code Agent = LLM + repo context + editing tools + execution env + iterative debug loop**

**答不出？** → 重读 [01-Code-Agent定义与边界](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/01-Code-Agent%E5%AE%9A%E4%B9%89%E4%B8%8E%E8%BE%B9%E7%95%8C.md)

---

### Q3：SWE-bench 的 reward / 评测来自哪里？

**关键点**：

- 来自 **真实 GitHub issue 对应的 PR + 测试**
- 用 **FAIL_TO_PASS**（修复前 fail，修复后 pass）+ **PASS_TO_PASS**（修复前后都 pass，不能破）评测
- **resolved rate** = 这两组测试都对的比例
- **SWE-bench Verified** 是人工筛 500 题，reward 更可信

**答不出？** → 重读 [05-必读论文10篇精读卡（SWE-bench线）](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/05-%E5%BF%85%E8%AF%BB%E8%AE%BA%E6%96%8710%E7%AF%87%E7%B2%BE%E8%AF%BB%E5%8D%A1%EF%BC%88SWE-bench%E7%BA%BF%EF%BC%89.md) § 必读卡 1-2 + [能力栈](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/02-Code-Agent%E8%83%BD%E5%8A%9B%E6%A0%8810%E6%A8%A1%E5%9D%97.md) §4.2.9

### Q4：为什么测试反馈适合作为 RLVR 信号？

**关键点**：

- **客观**：pytest pass/fail 不依赖人类
- **自动**：程序可计算
- **便宜**：跑一次几秒
- **明确**：通常 0/1（也可连续）
- **配 GRPO 极好**：同 issue sample K patch，组内相对 advantage

**但有风险**：

- 测试覆盖不全
- agent 可能 hack（改测试 / hard-code / skip）

**答不出？** → 重读 [04-RLVR（可验证奖励）](../02-%E7%AC%AC2%E7%AB%A0-%E4%BB%8ERLHF%E5%88%B0Agentic-RL/04-RLVR%EF%BC%88%E5%8F%AF%E9%AA%8C%E8%AF%81%E5%A5%96%E5%8A%B1%EF%BC%89.md) + [04-RL如何用在Code-Agent上](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/04-RL%E5%A6%82%E4%BD%95%E7%94%A8%E5%9C%A8Code-Agent%E4%B8%8A.md)

### Q5：什么是 pass/fail reward、dense reward、process reward、verifier reward？

**关键点**：

| 类型 | 何时给 | 优缺点 |
|---|---|---|
| **Pass/fail** | episode 终局 | 简单 / 极稀疏 |
| **Dense** | 每步 | 信号密 / 易被 reward shape 钻 |
| **Process** | 每步 | 缓解 credit assignment / 标注贵 |
| **Verifier** | 终局 | 可 rerank / verifier 会被攻击 |

**答不出？** → 重读 [04-RL如何用在Code-Agent上](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/04-RL%E5%A6%82%E4%BD%95%E7%94%A8%E5%9C%A8Code-Agent%E4%B8%8A.md) §4.4.3

### Q6：SWE-agent、OpenHands、Aider、Agentless、SWE-Gym 分别扮演什么角色？

**关键点**：

| 项目 | 角色 |
|---|---|
| **SWE-agent** | 经典 coding agent scaffold，**ACI 设计典范** |
| **OpenHands** | **完整 SE agent 平台**（含 sandbox/UI/多工具） |
| **Aider** | **最低成本** 终端 pair-programming |
| **Agentless** | **不用 agent** 的强 baseline（localization + repair + rerank） |
| **SWE-Gym** | **训练**用 SWE agent + verifier（从 eval 走向 training） |

**答不出？** → 重读 [07-Repo地图（SWE-agent-OpenHands等）](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/07-Repo%E5%9C%B0%E5%9B%BE%EF%BC%88SWE-agent-OpenHands%E7%AD%89%EF%BC%89.md)

### Q7：Code Agent 的 observation、action、reward、trajectory 分别是什么？

**关键点**：

| 字段 | 内容 |
|---|---|
| **Observation** | issue + 文件 summary + 上次 diff + 上次 test output + budget_remaining |
| **Action** | `{search / read / edit / run_tests / final}`（**不要 raw bash**） |
| **Reward** | 主用 pytest 通过率（pass/fail 或 dense） |
| **Trajectory** | `[{t, observation, action_type, action, result, reward}]` 的 JSON list |

**答不出？** → 重读 [03-Observation-Action-Reward定义](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/03-Observation-Action-Reward%E5%AE%9A%E4%B9%89.md)

### Q8：最小 toy bug-fix gym 如何设计？

**关键点**：

- 30 个小 Python bug + failing pytest
- metadata.json 含 `allowed_files`（**防止改测试**）
- Action space 限定 5 个动作
- 3 版 reward（binary / dense / verifier）
- 4 个 baseline（no-tool / ReAct / test-feedback / rerank）
- 保存 trajectories.jsonl
- 标注 7 类失败模式
- 渐进：**5 → 30** 任务

**答不出？** → 重读 [02-Toy-Bug-Fix-Agent-Gym（核心）](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E9%A1%B9%E7%9B%AE/02-Toy-Bug-Fix-Agent-Gym%EF%BC%88%E6%A0%B8%E5%BF%83%EF%BC%89.md)

---

### Q9：这个方向最主要的风险是什么？

**关键点**（4 类）：

| 风险 | 一句话 |
|---|---|
| **Reward hacking** | agent 改测试 / hard-code / skip 拿高分 |
| **Benchmark overfitting** | 数据污染 / 模型记答案 / 对 harness 投机 |
| **环境不稳定** | Docker / 依赖 / flaky / 网络 |
| **Sandbox 安全** | agent 执行任意命令、删文件、泄密 |

**对应防护**：

- 锁测试文件 + hidden tests + 人工抽查
- Verified + 时间切分 + OOD repo
- 固定镜像 + 重试 + 分类统计
- 容器 + 配额 + 权限 + 网络白名单 + 审计

**答不出？** → 重读 [08-Reward-Hacking与Sandbox安全](../04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/08-Reward-Hacking%E4%B8%8ESandbox%E5%AE%89%E5%85%A8.md)
