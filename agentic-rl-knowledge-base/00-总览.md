# 0 总览：从 LLM Agent 到 Code Agentic RL

⬅ [README](README.md) | ➡ [00-章节总览](01-%E7%AC%AC1%E7%AB%A0-RL%E6%9C%80%E5%B0%8F%E5%BF%85%E8%A6%81%E5%9F%BA%E7%A1%80/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

## 🎬 一句话故事

你已经会用 ReAct / LangChain / Tool use 拼一个 agent。
但你会发现：

> **现成的 GPT-4 / Claude 调出来的 agent，遇到真实 GitHub issue 还是改一下崩一下。**

为什么？因为它**没在「跑测试 → 看报错 → 再修」这种闭环上被训练过**。

Agentic RL 就是解决这个问题的方法：
**把 agent 在环境里多轮试错的轨迹 (trajectory) 收集起来，用奖励 (reward) 反过来训练它**。
Code Agentic RL 就是把这套用在代码任务上，奖励来自 **pytest / 编译器 / 测试通过率**。

## ⚠️ 学习前避坑

| 坑 | 怎么避 |
|---|---|
| 一上来就读 PPO 推导 | **跳过**！先读第 1 章故事比喻版，公式只看一眼。 |
| 想先把 Sutton & Barto 读完再来 | **不要**！你需要的是「能描述 agent 任务为 MDP」即可。 |
| 把 LangGraph / AutoGen 当 Agentic RL | 它们是 **workflow agent**，不更新模型参数，**不算 RL**。 |
| 直接挑战 SWE-bench 全量 | 单题 Docker build 都要十几分钟，**先跑 Aider 修一个 pytest bug**。 |
| 误以为 RLVR 是万灵药 | reward hacking 在代码任务里极常见，见 [08-Reward-Hacking与Sandbox安全](04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/08-Reward-Hacking%E4%B8%8ESandbox%E5%AE%89%E5%85%A8.md) |
