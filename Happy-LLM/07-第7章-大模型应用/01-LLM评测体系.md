# 7.1 LLM 评测体系

## 🎬 故事比喻：给学霸们排"高考成绩"

100 个学霸（LLM）站在你面前，怎么判断**谁更强**？

→ **办场高考** —— 出一套标准题，让所有人都做，按分数排名。

**LLM 评测就是给大模型办高考**：
- 准备**标准题库**（评测数据集）
- 让所有模型**做同样的题**
- 按分数排**榜单**

---

## 🧠 为什么要做评测？

| 价值 | 解释 |
|---|---|
| **选型** | 想用某个 LLM 做应用，先看它在相关评测上多少分 |
| **训练优化** | 训新模型时，跑评测看效果有没有提升 |
| **公开公平** | 学术界 / 工业界有统一标准，能横向比较 |
| **发现弱点** | 暴露偏见、鲁棒性问题，指导改进方向 |
| **商业决策** | "我们的模型超越 GPT-4 了"——卖货必备话术 |

## 📊 7.1.1 主流评测数据集（按能力分类）

### 1. 通用知识理解

| 数据集 | 一句话 | 题量 |
|---|---|---|
| **MMLU**（Massive Multitask Language Understanding） | 涵盖 **57 个学科**：历史/数学/物理/法律/医学… | 15K+ |
| **C-Eval** | MMLU 的中文版（国内常用） | 13K+ |
| **CMMLU** | 中文综合评测 | 11K+ |

→ MMLU 是**最经典**的"通才考试"。

### 2. 数学推理

| 数据集       | 一句话                             |
| --------- | ------------------------------- |
| **GSM8K** | 小学数学应用题（"小明有 5 个苹果…"），考**多步推理** |
| **MATH**  | 高中竞赛题，考**复杂代数和几何**              |
| **MGSM**  | 多语言版 GSM8K，考跨语言数学               |

### 3. 代码生成

| 数据集 | 一句话 |
|---|---|
| **HumanEval** | OpenAI 出品，164 个 Python 编程题（**pass@1 指标**） |
| **MBPP** | 974 个 Python 编程题 |
| **LiveCodeBench** | 实时更新的编程题，防作弊 |

### 4. 推理 / 常识

| 数据集               | 一句话                  |
| ----------------- | -------------------- |
| **ARC Challenge** | 科学常识题（小学到高中）         |
| **HellaSwag**     | 选最符合逻辑的句子续写          |
| **GPQA**          | 博士级科学难题（防 GPT-4 也答错） |

### 5. 长文本理解

| 数据集                     | 一句话                   |
| ----------------------- | --------------------- |
| **InfiniteBench/En.MC** | 长文档阅读理解               |
| **NIH/Multi-needle**    | "大海捞针"：在 100K+ 文档里找信息 |
| **LongBench**           | 多任务长文本综合              |

### 6. 工具调用

| 数据集 | 一句话 |
|---|---|
| **BFCL V2** | Berkeley Function Calling Leaderboard，考工具调用准确性 |

## 🏆 7.1.2 三大主流榜单

### 🥇 Open LLM Leaderboard（HuggingFace）

- **覆盖范围**：**开源 LLM** 排行
- **评测内容**：MMLU、GSM8K、HellaSwag、TruthfulQA 等多个 benchmark 综合
- **更新频率**：实时（任何人都能提交模型）
- **用途**：选**开源模型**首选

→ 国际社区**最权威的开源榜单**。

### 🥇 Lmsys Chatbot Arena Leaderboard

- **特别之处**：**真实用户盲测投票**（Anonymous A/B Test）
- **流程**：
  1. 用户输入问题
  2. 系统**随机选两个模型** 同时回答
  3. 用户**选哪个更好**（不知道是哪个模型）
  4. 用 **Elo 评分**（象棋排名算法）算总分
- **意义**：**最接近"真实使用感受"** 的榜单
- 经常爆出"开源模型超越 GPT-4"的新闻就来自这里

### 🥇 OpenCompass（上海 AI Lab）

- **国内最权威**的综合榜单
- **特点**：**重点关注中文场景**
- 集成了 100+ 评测集，分多个维度（知识、推理、语言、代码、长文本等）
- **国内选型必看**

## ⭐ 加深理解：评测指标常见类型

| 指标 | 含义 | 典型用法 |
|---|---|---|
| **Accuracy** | 准确率 | 选择题（MMLU） |
| **Exact Match** | 完全匹配率 | 数学（GSM8K） |
| **pass@k** | k 次中至少有一次正确率 | 代码（HumanEval） |
| **BLEU / ROUGE** | 文本相似度 | 翻译、摘要 |
| **Elo Rating** | 象棋排名分 | 对话榜（Lmsys） |
| **Win Rate** | 胜率 | 人工对比评测 |

---

## ⚠️ 评测的局限性（必须警惕）

### 局限 1：**Benchmark Hacking**（刷榜作弊）

- 把测试集泄露到训练数据里 → 模型"背答案"
- 在某 benchmark 上专门微调
- → **高分≠真实能力强**

### 局限 2：覆盖不全面

- 评测集是**固定的题**，但**真实任务千变万化**
- 在 MMLU 90 分的模型，在你具体业务场景可能只有 60 分

### 局限 3：评测自己也会过时

- LLM 进步太快，老 benchmark 区分度下降
- 比如 GSM8K 现在主流大模型都能 90%+

### 局限 4：人工评测主观性

- Lmsys Arena 依赖人投票
- 不同文化、背景的人喜好差异大

## 🎯 实战选型建议

```
我要选 LLM 做应用，怎么选？
   │
   ├── 看综合能力：OpenCompass（中文）/ Open LLM Leaderboard（英文）
   │
   ├── 看对话效果：Lmsys Arena 排名
   │
   ├── 看代码能力：HumanEval / LiveCodeBench
   │
   ├── 看数学/推理：GSM8K / MATH / GPQA
   │
   ├── 看具体行业：垂直榜（金融/法律/医疗等）
   │
   └── ⭐ 最重要：在你的实际业务样本上跑一遍小测试
                （所有 benchmark 都比不上"自己业务样本上的真实表现"）
```

---

## ⚠️ 小白避坑

1. **不要只看一个榜单**
   - 综合 3~5 个榜单看全貌
2. **不要迷信"全球第一"**
   - 大概率是刷榜作弊
3. **要看模型的"评测日期"**
   - 评测集泄露后，旧分数没参考价值
4. **业务场景与 benchmark 错配很常见**
   - 必须在自己数据上验证

---

## 📌 7.1 节要点

- LLM 评测 = **标准化题库 + 排行榜**
- 通用：MMLU；数学：GSM8K；代码：HumanEval；推理：GPQA
- 三大榜单：Open LLM Leaderboard、Lmsys Arena、OpenCompass
- 警惕**刷榜作弊**，必须在自己业务样本上验证
