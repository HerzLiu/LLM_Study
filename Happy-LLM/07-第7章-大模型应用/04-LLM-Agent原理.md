# 7.3.1-7.3.2 LLM Agent 原理与类型

⬅ [03-Tiny-RAG实战速览](03-Tiny-RAG%E5%AE%9E%E6%88%98%E9%80%9F%E8%A7%88.md)	|	➡ [05-Tiny-Agent实战速览](05-Tiny-Agent%E5%AE%9E%E6%88%98%E9%80%9F%E8%A7%88.md)

> ⭐ **本章核心理论**：Agent 是通往 **AGI** 的最热方向。

---

## 🎬 故事比喻：图书馆员 vs 私人助理

| | **传统 LLM** | **LLM Agent** |
|---|---|---|
| 比喻 | **图书馆员** | **全能私人助理** |
| 能力 | 知识渊博，但只能纸上谈兵 | 不仅懂得多，**还能跑腿办事** |
| 输入 | "什么是 RAG？" | "**帮我规划周末北京游 + 预订机票酒店**" |
| 输出 | 一段文字解释 | **完整行程方案 + 实际订票** |
| 是否使用工具 | ❌ | ✅ 调 API、查数据库、订机票 |
| 是否能规划 | ❌ | ✅ 自动分解大目标 |
| 是否能反思 | ❌ | ✅ 失败时调整策略 |

→ Agent 让 LLM **从"会说"变成"会做"**。

## 🧠 7.3.1 什么是 LLM Agent？

> **LLM Agent = 以 LLM 为"大脑"，赋予自主规划、记忆和工具使用能力的系统**

### Agent 的 5 大核心能力（必背）

```
              ┌────────────────────────┐
              │      LLM Agent          │
              │   (LLM = "大脑")         │
              └──────────┬─────────────┘
                          │
        ┌─────────┬───────┼───────┬─────────┐
        │         │       │       │         │
   目标理解   规划    记忆    工具使用   反思迭代
```

#### 能力 1：**目标理解**（Goal Understanding）
- 接收**复杂、高层次**的目标
- 例："帮我规划周末北京游" → 拆成具体子任务

#### 能力 2：**自主规划**（Planning）
- 把大目标**分解成可执行子步骤**
- 例：搜索景点 → 查天气 → 比较机票 → 找酒店 → 调用预订 API

#### 能力 3：**记忆**（Memory）
- **短期记忆**：当前任务上下文（对话历史）
- **长期记忆**：从过去交互 / 知识库中检索学习

#### 能力 4：**工具使用**（Tool Use）
- 调用外部 **API / 插件 / 代码环境**
- 例：搜索引擎、计算器、数据库、发邮件、订票

#### 能力 5：**反思与迭代**（Reflection & Iteration）
- **评估自己的行为结果**
- 失败时**学习并调整后续计划**

## 📊 7.3.2 Agent 四大类型

### 🔵 类型 1：任务导向型（Task-Oriented Agents）

**特点**：专注**特定领域** + 定义明确的任务

| 项 | 内容 |
|---|---|
| 工作方式 | 预设流程 + 特定工具集，LLM 主要填槽位、生成回复 |
| 例子 | 餐厅预订机器人、客服 Agent、**GitHub Copilot** |
| 复杂度 | ⭐⭐ |
| 当前应用 | 最成熟、最广泛 |

**典型场景**：
```
用户："我要订今晚 7 点的餐厅"
Agent："请问几位用餐？" → 调订餐 API → 返回确认
```

### 🟠 类型 2：规划与推理型（Planning & Reasoning Agents）⭐

**特点**：**自主分解任务 + 多步规划**

#### 核心框架：**ReAct**（Reason + Act）

> ReAct = **思考（Reasoning）+ 行动（Action）的交替循环**

```
Thought: 我需要知道今天的天气
Action: search_weather("北京", "今天")
Observation: 北京今天晴朗，25°C

Thought: 接下来我需要查景点
Action: search("北京 必去景点")
Observation: 故宫、长城、颐和园...

Thought: 用户喜欢历史，推荐故宫和长城
Final Answer: 推荐你今天去故宫和长城游玩，今天天气晴朗适合户外...
```

→ **每一步都是"先思考，再行动，再观察"**，循环到完成。

#### 与 ReAct 配套的提示工程

| 技术 | 作用 |
|---|---|
| **CoT**（Chain-of-Thought） | 引导逐步推理 |
| **ReAct** | 加入工具调用循环 |
| **Reflexion** | 失败后反思总结 |
| **Plan-and-Execute** | 先做完整计划，再分步执行 |

**例子**：
> 复杂任务："写一篇关于 LLM 发展的报告，并配上数据图表"
> Agent 拆解：查资料 → 整理大纲 → 写正文 → 生成图表 → 校对

### 🟢 类型 3：多 Agent 系统（Multi-Agent Systems）

**特点**：多个 Agent **协作完成**宏大目标

#### 经典模式

```
模拟软件开发团队:
   │
   ├── 产品经理 Agent  → 写需求文档
   ├── 架构师 Agent     → 设计系统
   ├── 程序员 Agent     → 写代码
   ├── 测试员 Agent     → 测试 + 反馈
   └── 项目经理 Agent  → 协调进度
```

#### 协作方式

| 模式 | 说明 |
|---|---|
| **通信** | Agent 之间发消息 |
| **协作** | 分工合作 |
| **辩论** | 互相质疑找出最佳方案 |
| **竞争** | 多 Agent 提方案选最优 |

#### 主流框架

| 框架 | 出品方 | 特点 |
|---|---|---|
| **AutoGen** | 微软 | 多 Agent 对话 |
| **ChatDev** | 清华 | 模拟软件公司 |
| **MetaGPT** | – | 模拟标准 SOP |
| **CrewAI** | 社区 | 简单易用 |

### 🟣 类型 4：探索与学习型（Exploration & Learning Agents）

**特点**：**在交互中学习**新知识、新技能

| 项 | 内容 |
|---|---|
| 工作方式 | 复杂记忆 + 反思机制 + 经验积累 |
| 例子 | 自主探索未知软件的 Agent、玩游戏越玩越强的 Agent |
| 复杂度 | ⭐⭐⭐⭐⭐ |
| 当前阶段 | **前沿研究**，未广泛落地 |

→ 接近**强化学习**思想：通过试错优化策略。

---

## ⭐ 加深理解：Agent vs Chatbot vs RAG

| 维度 | Chatbot | **RAG** | **Agent** |
|---|---|---|---|
| 主要能力 | 对话 | 知识问答 | **办事** |
| 是否会规划 | ❌ | ❌ | ✅ |
| 是否调用工具 | ❌ | 仅检索 | ✅ 多种 |
| 是否有记忆 | 短期 | 知识库 | 短期+长期 |
| 是否能反思 | ❌ | ❌ | ✅ |
| 复杂度 | 低 | 中 | 高 |
| 典型例子 | ChatGPT 原生对话 | 客服 + RAG | **AutoGPT / GPT 助手** |

→ 三者递进：**Chatbot ⊂ RAG ⊂ Agent**

## 🛠 实现 Agent 的核心技术

### 1. Function Calling / Tool Calling

LLM 的工具调用能力（OpenAI 2023 首推，现已成标配）：

```json
{
  "type": "function",
  "function": {
    "name": "get_weather",
    "description": "查询某地天气",
    "parameters": {
      "type": "object",
      "properties": {
        "city": {"type": "string", "description": "城市名"}
      },
      "required": ["city"]
    }
  }
}
```

→ **LLM 自动决定**何时调用、传什么参数。

### 2. ReAct 提示

通过 prompt 引导 LLM 输出 `Thought → Action → Observation` 循环。

### 3. 状态管理

Agent 需要维护 `messages` 列表，记录每一轮 `Thought / Action / Observation`。

### 4. 错误恢复

工具调用失败时，让 LLM 看到错误信息，自动重试或换方案。

## ⚠️ Agent 当前的局限

1. **可靠性低**
   - 多步规划中**任一步出错就全错**
   - 步数越多失败率越高
2. **成本高**
   - 每个工具调用都要过一次 LLM
   - 复杂任务可能十几次 API 调用
3. **延迟大**
   - 多步串行，用户等待时间长
4. **难以调试**
   - 出错时分不清是 LLM 错、工具错、还是 prompt 错
5. **安全风险**
   - LLM 可能被诱导调用危险工具
   - 例：让 Agent 自己删文件、转账

## 🚀 Agent 的未来方向

| 方向 | 解释 |
|---|---|
| **推理模型驱动**（o1 / R1） | 更强的 Reasoning 能力 |
| **代码即 Agent**（Code as Action） | 让 LLM 直接写代码而非调工具 |
| **多模态 Agent** | 看屏幕、听语音、操控浏览器 |
| **Computer-Use Agent** | 直接操控电脑（Claude Computer Use、Operator） |
| **Self-Improving Agent** | 自主优化、自我进化 |
| **Agent + RAG + Memory** | 三位一体的智能体 |

→ **Agent 是 LLM 走向 AGI 的关键一步**。
