# 5.1.1 定义超参数（ModelConfig）

⬅ [00-章节总览](00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)　|	➡ [02-RMSNorm代码实现](02-RMSNorm%E4%BB%A3%E7%A0%81%E5%AE%9E%E7%8E%B0.md)

## 🎬 故事比喻：盖楼前先画图纸

要盖一栋楼，必须先**画图纸**：
- 几层楼？
- 每层多大？
- 几个房间？
- 用什么材料？

写模型也一样 —— **先把所有超参集中定义在一个配置类里**，方便管理、调试、保存、加载。

→ **ModelConfig 就是 LLaMA2 模型的"图纸"**。

---

## 🐍 完整代码

```python
from transformers import PretrainedConfig

class ModelConfig(PretrainedConfig):
    model_type = "Tiny-K"

    def __init__(
            self,
            dim: int = 768,           # 模型维度（hidden size）
            n_layers: int = 12,       # Transformer 层数
            n_heads: int = 16,        # 注意力头数
            n_kv_heads: int = 8,      # KV 头数（用于 GQA）
            vocab_size: int = 6144,   # 词表大小
            hidden_dim: int = None,   # FFN 隐藏维度（None 则自动计算）
            multiple_of: int = 64,    # FFN 隐藏维度的对齐倍数
            norm_eps: float = 1e-5,   # LayerNorm/RMSNorm 的 eps
            max_seq_len: int = 512,   # 最大序列长度
            dropout: float = 0.0,     # Dropout 比例
            flash_attn: bool = True,  # 是否使用 Flash Attention
            **kwargs,
    ):
        self.dim = dim
        self.n_layers = n_layers
        self.n_heads = n_heads
        self.n_kv_heads = n_kv_heads
        self.vocab_size = vocab_size
        self.hidden_dim = hidden_dim
        self.multiple_of = multiple_of
        self.norm_eps = norm_eps
        self.max_seq_len = max_seq_len
        self.dropout = dropout
        self.flash_attn = flash_attn
        super().__init__(**kwargs)
```

## 📝 关键参数解读

| 参数               | 含义                | 默认值   | 典型范围          |
| ---------------- | ----------------- | ----- | ------------- |
| `dim`            | 词向量维度（也是模型内部主维度）  | 768   | 768~12288     |
| `n_layers`       | Transformer 堆叠层数  | 12    | 6~96          |
| `n_heads`        | 注意力头数             | 16    | 8~96          |
| **`n_kv_heads`** | **KV 头数（GQA 关键）** | **8** | **2~n_heads** |
| `vocab_size`     | 词表大小              | 6144  | 5K~150K       |
| `hidden_dim`     | FFN 中间层维度         | 自动    | ≈ 4×dim       |
| `multiple_of`    | FFN 维度对齐倍数        | 64    | 32~256        |
| `norm_eps`       | RMSNorm 分母 ε      | 1e-5  | 1e-6~1e-5     |
| `max_seq_len`    | 最大上下文长度           | 512   | 2K~128K       |
| `dropout`        | 防过拟合              | 0.0   | 0.0~0.1       |

### ⭐ 关键设计点 1：`n_heads` vs `n_kv_heads`

> 这是 [LLaMA](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/07-LLaMA.md) 引入的 **GQA**（分组查询注意力）的核心配置：

| 配置 | 名称 | 优势 |
|---|---|---|
| `n_kv_heads == n_heads` | **MHA**（标准多头） | 质量好，KV cache 大 |
| `n_kv_heads == 1` | **MQA**（多查询注意力） | KV cache 小，质量差 |
| **`1 < n_kv_heads < n_heads`** | **GQA**（分组查询） | **平衡** |

例：`n_heads=16, n_kv_heads=8` → 每 2 个 Q 头共享 1 组 K/V
→ 详见 [03-GQA与RoPE](03-GQA%E4%B8%8ERoPE.md)

### ⭐ 关键设计点 2：`hidden_dim` 自动计算

如果不指定，按 LLaMA 论文经验：
```python
hidden_dim = 4 * dim                                    # 升 4 倍
hidden_dim = int(2 * hidden_dim / 3)                    # 再缩 2/3（SwiGLU 经验值）
hidden_dim = multiple_of * ((hidden_dim + multiple_of - 1) // multiple_of)  # 对齐到 64 倍数
```

举例：`dim=768`
- 4 × 768 = 3072
- × 2/3 = 2048
- 对齐 64 倍数 = 2048

为什么对齐 64 倍数？→ **GPU 矩阵乘法对 8/16/32/64 倍数的维度优化最好**。

### ⭐ 关键设计点 3：继承 `PretrainedConfig`

`from transformers import PretrainedConfig` 是 Hugging Face 的配置基类。继承它的好处：
- 自动支持 `config.save_pretrained()` / `config.from_pretrained()`
- 后续可以**直接上传 Hugging Face Hub**
- 与 `AutoConfig` 等接口兼容

## 💡 不同规模模型的配置示例

| 模型        | dim      | n_layers | n_heads | 参数量       |
| --------- | -------- | -------- | ------- | --------- |
| 本章 Tiny   | 768      | 12       | 16      | ~80M      |
| **本章实战版** | **1024** | **18**   | **16**  | **~215M** |
| LLaMA-7B  | 4096     | 32       | 32      | 7B        |
| LLaMA-13B | 5120     | 40       | 40      | 13B       |
| LLaMA-70B | 8192     | 80       | 64      | 70B       |

→ 同样的代码框架，**只改超参就能从 80M 缩放到 70B**。

---

## ⚠️ 小白避坑

1. **`dim` 必须能被 `n_heads` 整除**
   - 否则注意力拆头会失败
2. **`n_heads` 必须能被 `n_kv_heads` 整除**
   - GQA 要求 Q 头能均匀分组
3. **`max_seq_len` 决定显存上限**
   - 注意力 O(N²)，长度翻倍显存约 4×
4. **`vocab_size` 影响 Embedding 参数**
   - 词表大 → Embedding 大 → 模型变重

---

## 🔬 验证：能跑起来吗？

```python
args = ModelConfig()
print(args.dim)          # 768
print(args.n_kv_heads)   # 8
print(args.n_heads // args.n_kv_heads)  # 2，即每 2 个 Q 头共享一组 KV
```
