# 4.1.3 LLM 的四大特点

⬅ [02-LLM四大能力](02-LLM%E5%9B%9B%E5%A4%A7%E8%83%BD%E5%8A%9B.md)　|	➡ [04-训练三阶段全景](04-%E8%AE%AD%E7%BB%83%E4%B8%89%E9%98%B6%E6%AE%B5%E5%85%A8%E6%99%AF.md)

> 上一节讲的是 LLM 的**"魔法"能力**（涌现、ICL、指令、CoT）。
> 这一节讲它的**"个性"特点**（多语言、长文本、多模态、幻觉）。

---

## 📊 四大特点速览

| 特点          | 简介               | 性质    |
| ----------- | ---------------- | ----- |
| **多语言支持**   | 天生支持几十种语言        | ✅ 优势  |
| **长文本处理**   | 上下文从 512 → 100K+ | ✅ 优势  |
| **拓展多模态**   | 图、视频、语音都能搞       | ✅ 优势  |
| **挥之不去的幻觉** | 一本正经地胡说八道        | ⚠️ 痛点 |

---

## 🌍 特点 (1)：多语言支持

### 🎬 故事：会说几十种语言的"语言天才"

传统的多语言/跨语言 NLP 是个**独立研究方向**（MUSE、XLM 等）。
但 LLM 训练时**直接吃几十种语言混合的语料**，**天生**多语言。

### 关键差异

| 时代 | 多语言怎么做 |
|---|---|
| **PLM 时代** | 专门设计跨语言模型（XLM、mBERT） |
| **LLM 时代** | 训练语料本身就是多语言 → **顺带就有了** |

### 不同语言能力差异

| 模型                        | 强项语言           | 原因         |
| ------------------------- | -------------- | ---------- |
| **GPT-4**                 | 英文 >> 中文 >> 其他 | 训练语料以英文为主  |
| **通义千问 / 文心一言 / ChatGLM** | 中文 >> 英文       | 国内团队针对中文优化 |
| **Qwen / DeepSeek**       | 中英文都强          | 双语精心配比     |

### 启示

> 想要某语言效果好 → 用该语言为主的训练数据 + 该语言指令微调

---

## 📏 特点 (2)：长文本处理

### 🎬 故事：从「读一段」到「读一本红楼梦」

传统 PLM（如 BERT）：最长 **512 token**（约一段话）
**LLM**：从 4K → 32K → 100K → 1M+（**整本《红楼梦》都能塞进去**）

### 上下文长度的演进

| 模型 | 上下文长度 |
|---|---|
| BERT / T5 | 512 token |
| GPT-3 | 2K |
| LLaMA-1 | 2K |
| LLaMA-2 | 4K |
| LLaMA-3 | 8K |
| ChatGLM2 | 32K |
| GPT-4 Turbo | 128K |
| Claude 3 | **200K** |
| Gemini 1.5 Pro | **1M+** |

### ⭐ 关键技术：RoPE 位置编码

LLM 之所以能处理长文本，[RoPE](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/07-LLaMA.md#%E6%94%B9%E8%BF%9B-1rope%E6%97%8B%E8%BD%AC%E4%BD%8D%E7%BD%AE%E7%BC%96%E7%A0%81) 起了关键作用：
- 相比 [sin/cos 绝对位置编码](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/09-%E4%BD%8D%E7%BD%AE%E7%BC%96%E7%A0%81.md)，RoPE 具有**长度外推能力**
- InternLM 在 32K 长度上预训练，**通过 RoPE 推理时能处理 200K**

### 长文本能力解锁的应用

| 应用     | 没长文本时 | 有长文本时      |
| ------ | ----- | ---------- |
| 论文阅读   | 只能读摘要 | 整篇 PDF 直接喂 |
| 代码理解   | 单个文件  | 整个仓库       |
| 视频转写分析 | 几分钟   | 几小时        |
| 长篇小说创作 | 短文    | 长篇         |

> 经典任务：要求 LLM 读完《红楼梦》并写一篇对应的高考作文 —— 32K+ 上下文才搞得定。

### ⚠️ 长上下文的代价

- **计算成本**：注意力是 **O(N²)**，长上下文非常贵
- **位置混乱**："针在草垛"（Lost in the Middle）问题 —— 答案在中间位置时容易被忽略
- **真实理解 vs 假理解**：长上下文模型不一定真的理解全部内容

## 🖼 特点 (3)：拓展多模态

### 🎬 故事：从"只会读字"到"看图说话"

LLM 原本只懂文字。
通过加几个组件，让它**也能看图、听声、看视频**：

```
图像 ──→ 图像编码器（如 CLIP）─→ Adapter ─→ LLM
                                              │
                                              ▼
                                       理解图像 + 生成文字
```

### 多模态 LLM 例子

| 模型                     | 模态                | 来源        |
| ---------------------- | ----------------- | --------- |
| **GPT-4V / GPT-4o**    | 文字 + 图像 + 语音      | OpenAI    |
| **Claude 3**           | 文字 + 图像           | Anthropic |
| **Gemini 1.5**         | 文字 + 图像 + 视频 + 音频 | Google    |
| **Qwen-VL / Qwen2-VL** | 文字 + 图像           | 阿里        |
| **LLaVA**              | 文字 + 图像           | 开源        |
| **MiniCPM-V**          | 文字 + 图像           | 面壁智能      |

### 技术路线

| 路线        | 思路                           | 代表            |
| --------- | ---------------------------- | ------------- |
| **后期对齐**  | 训好的 LLM + 图像编码器，加 Adapter 微调 | LLaVA、Qwen-VL |
| **原生多模态** | 从预训练就用图文混合数据                 | GPT-4o、Gemini |

### 应用场景

- 看医学影像写报告
- 看流程图自动生成代码
- 看截图回答问题
- 视频内容理解 + 摘要

## ⚠️ 特点 (4)：挥之不去的幻觉（Hallucination）

### 🎬 故事：一本正经地胡说八道

你问 LLM："请列出 5 篇关于量子计算的论文及作者"
LLM 流畅地给你 5 篇 —— **但全是它编的，根本不存在** 🤡

### 🔧 技术定义

> **幻觉（Hallucination）**：LLM 根据 prompt **杜撰生成虚假、错误信息**的现象。

### 为什么会有幻觉？

| 根本原因             | 解释                       |
| ---------------- | ------------------------ |
| **CLM 任务本质**     | 模型只学"什么词后面接什么词"，不学"是真是假" |
| **训练数据的错误**      | 互联网本身就有大量错误信息            |
| **模型不"知道自己不知道"** | 模型总是有"信心"输出答案            |
| **概率采样**         | 推理时随机选词，可能选到错误的          |

### 幻觉的危害

| 场景 | 风险 |
|---|---|
| **医学** | 给错诊断建议 → 健康风险 |
| **金融** | 编造法规、数据 → 法律风险 |
| **法律** | 引用不存在的判例 → 误导当事人 |
| **学术** | 编造论文、引用 → 学术不端 |

### 缓解幻觉的常见方法

| 方法             | 思路                   | 优劣        |
| -------------- | -------------------- | --------- |
| **Prompt 限制**  | "如不确定请回答'不知道'"       | 简单，效果有限   |
| **RAG（检索增强）**  | 先检索权威资料，再让 LLM 基于资料答 | 效果好，需建知识库 |
| **CoT / 自我反思** | 让模型多步推理 + 自查         | 增加成本      |
| **更好的对齐**      | RLHF + 真实性奖励         | 训练复杂      |
| **工具调用**       | 让 LLM 调用搜索、计算器等      | 工程复杂      |

> ⚠️ **现状**：幻觉是 LLM 的**固有缺陷**，目前**无法根除**，只能减弱。
> RAG 是工业界缓解幻觉最主流的方案 → [第 7 章 RAG](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/02-RAG%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md)

### ⭐ 加深理解：幻觉 ≠ 错误

| 概念 | 区别 |
|---|---|
| **错误** | 模型答错了简单题 |
| **幻觉** | 模型**编造**看似合理但**根本不存在**的内容 |

幻觉的危险在于**看起来很真**，普通用户很难分辨。

---

## 🔁 四大特点回顾

```
正面特点（要善用）：
  🌍 多语言 ─→ 跨语言场景拿来即用
  📏 长文本 ─→ 整本书、整个代码库可塞
  🖼 多模态 ─→ 图文视频音频都能搞

负面特点（要警惕）：
  ⚠️ 幻觉 ─→ 关键信息必须核实，结合 RAG 用
```

---

## ⚠️ 小白避坑

1. **多语言能力不均衡**
   - 别假设"GPT-4 中英都一样强"
   - 中文场景优先考虑国内 LLM
2. **长上下文 ≠ 真理解**
   - 模型可能"看到"了 100K 但只用了开头结尾
3. **多模态不是万能**
   - 复杂图表、艺术品理解仍有限
4. **幻觉是真实存在的**
   - **不要把 LLM 输出当百分百真理**
   - 关键场景必须人工核对
