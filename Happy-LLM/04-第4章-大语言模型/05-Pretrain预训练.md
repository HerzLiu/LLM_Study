# 4.2.1 Pretrain（预训练）—— 第一阶段：博览群书

⬅ [04-训练三阶段全景](04-%E8%AE%AD%E7%BB%83%E4%B8%89%E9%98%B6%E6%AE%B5%E5%85%A8%E6%99%AF.md)　|	➡ [06-SFT有监督微调](06-SFT%E6%9C%89%E7%9B%91%E7%9D%A3%E5%BE%AE%E8%B0%83.md)

> 🎯 **目标**：用海量无监督文本，让模型学到**所有语言知识和世界知识**
> 💰 **成本**：千卡级 GPU × 数月，**单次几百万美元**

---

## 🎬 故事比喻：让学生读完整个互联网

[BERT](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/02-BERT.md) Pretrain：让学生读 13GB 的书
**LLM Pretrain**：让学生读**几 T 的互联网文本**（**几万倍**）

→ Pretrain 是 LLM 一切能力的**根本来源**。

---

## 🔧 预训练任务：CLM（因果语言建模）

LLM 几乎都用 [CLM 任务](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/06-GPT.md#-%E9%A2%84%E8%AE%AD%E7%BB%83%E4%BB%BB%E5%8A%A1clm%E5%9B%A0%E6%9E%9C%E8%AF%AD%E8%A8%80%E5%BB%BA%E6%A8%A1)：
> 给前 N 个 token，预测第 N+1 个 token

```
"今天天气" → 预测 "很"
"今天天气很" → 预测 "好"
"今天天气很好" → 预测 "。"
```

简单直接，但需要**海量数据 + 海量算力**。

## 📊 LLM vs PLM 规模对比

| 模型 | 层数 | 隐藏维度 | 头数 | 参数量 | 预训练数据 |
|---|---|---|---|---|---|
| BERT-base | 12 | 768 | 12 | 0.1B | 3B token |
| BERT-large | 24 | 1024 | 16 | 0.3B | 3B token |
| **Qwen-1.8B** | 24 | 2048 | 16 | **1.8B** | **2.2T** |
| **LLaMA-7B** | 32 | 4096 | 32 | **7B** | **1T** |
| **GPT-3** | 96 | 12288 | 96 | **175B** | **300B** |

→ LLM 比 BERT 大 **3 个数量级**，数据量大 **2~3 个数量级**。

## ⭐ Scaling Law：参数和数据怎么配？

### OpenAI 的 Scaling Law（2020）

$$C \approx 6 \cdot N \cdot D$$

| 符号 | 含义 |
|---|---|
| `C` | 总计算量（FLOPs） |
| `N` | 模型参数量 |
| `D` | 训练 token 数 |
| `6` | 经验常数 |

OpenAI 实验得出：**最佳 D ≈ 1.7 × N**
→ 175B 的 GPT-3 → 用 300B token 训练

### Chinchilla 法则（DeepMind 2022）

后来 DeepMind 发现 OpenAI 的法则**数据用少了**，提出新法则：

> **最佳 D ≈ 20 × N**

→ 175B 模型应该用 **3.5T token** 训练才最优！

### LLaMA 采用 Chinchilla 思路

| 模型 | 参数 | 训练 token | 比例 |
|---|---|---|---|
| GPT-3 | 175B | 300B | ~1.7× |
| LLaMA-1 7B | 7B | 1T | **140×**（超量训练） |
| Chinchilla 最优 | 7B | 140B | 20× |

→ LLaMA-1 训练数据**远超 Chinchilla 法则**，所以才能用 7B 干翻 175B 的 GPT-3。

### ⭐ 实践启示

| 想要 | 怎么做 |
|---|---|
| 性能上限高 | 加大 N 和 D |
| 推理便宜 | 小 N + 超量 D（"超训练"） |
| 性价比 | 按 Chinchilla（D ≈ 20N） |

## 💻 分布式训练：单卡塞不下，怎么办？

百亿/千亿参数的模型，单张 GPU 显存装不下，必须**多卡分布式**。

### 两大基本策略

#### ① 数据并行（Data Parallel）

```
GPU 1: [完整模型] + batch 1
GPU 2: [完整模型] + batch 2
GPU 3: [完整模型] + batch 3
GPU 4: [完整模型] + batch 4

每张卡有完整模型，但用不同数据。
每步训练后同步梯度，更新参数。
```

**适用**：模型能塞进单卡（≤ 几十 B 参数）。
**问题**：每张卡都要存完整模型 → **显存浪费**。

#### ② 模型并行（Model Parallel）

```
GPU 1: 模型的 Layer 1~24
GPU 2: 模型的 Layer 25~48
GPU 3: 模型的 Layer 49~72
GPU 4: 模型的 Layer 73~96

每张卡只存一部分模型，数据按层流动。
```

**适用**：模型塞不进单卡（百亿+ 参数）。
**问题**：通信开销大、GPU 利用率低。

### 高级策略

| 策略 | 思路 |
|---|---|
| **张量并行** | 单个矩阵乘法切分到多卡 |
| **3D 并行** | 数据 + 模型 + 流水线 三种并行结合 |
| **ZeRO**（重点） | 数据并行的"显存优化版" |

---

## ⚡ ZeRO 与 DeepSpeed

### DeepSpeed 是什么？

> 微软开源的分布式训练框架，**最主流的 LLM 训练工具**之一。

核心策略：**ZeRO**（Zero Redundancy Optimizer，零冗余优化器）

### ZeRO 的核心思想

普通数据并行：每张卡都存一份"模型状态"
- 模型参数
- 梯度
- Adam 优化器状态（**最大头**）

ZeRO：**把这些"模型状态"切片分布到不同卡上**，需要时通信获取。

### 显存占用示意（假设模型 1M 参数）

| 项 | 显存占用 |
|---|---|
| 模型参数（fp16） | 2M |
| 模型梯度（fp16） | 2M |
| 优化器状态（Adam） | **12M**（最大头） |
| **总计** | **16M** |

### ZeRO 的三级优化

| 等级 | 切分内容 | 每张卡显存 | 通信开销 |
|---|---|---|---|
| **ZeRO-1** | 优化器状态 | 1/N 优化器 + 完整参数 + 完整梯度 | 低 |
| **ZeRO-2** | + 梯度 | 1/N 优化器 + 完整参数 + 1/N 梯度 | 中 |
| **ZeRO-3** | + 参数 | 1/N 全部 | 高 |

```
显存占用：  ZeRO-1 > ZeRO-2 > ZeRO-3
GPU 利用率：ZeRO-1 > ZeRO-2 > ZeRO-3
通信开销：  ZeRO-1 < ZeRO-2 < ZeRO-3
```

### 怎么选？

- **小模型（10B 以下）**：ZeRO-1 或 ZeRO-2
- **超大模型（百亿+）**：ZeRO-3
- **极端情况**：ZeRO-3 + CPU-offload（把状态扔到内存里）

| 数据集 | 大小 | 来源 |
|---|---|---|
| **CommonCrawl** | 数 TB | 互联网爬虫 |

### LLaMA-1 的数据配比

| 数据集 | 占比 |
|---|---|
| CommonCrawl | **67.0%** |
| C4 | 15.0% |
| GitHub | 4.5% |
| Wikipedia | 4.5% |
| Books | 4.5% |

> 💡 **配比是预训练的"核心秘籍"**，不同配比影响巨大，各家都不开源具体配方。

### 中文 LLM 的数据困境

| 语言 | 高质量开源数据 |
|---|---|
| 英文 | 多（Wikipedia、ArXiv、Books 等大量开源） |
| **中文** | **少**（ChatGLM/Baichuan 等都不开源训练数据） |

中文开源预训练语料（少量）：
- **SkyPile**（昆仑天工，150B）
- **yayi2**（中科闻歌，100B）

→ 比英文差**至少一个数量级**。

## 🧹 预训练数据处理三步

> **预训练数据质量比体量更重要**！

### Step 1：文档准备

| 步骤 | 内容 |
|---|---|
| URL 过滤 | 屏蔽有害网站 |
| 文档提取 | 从 HTML 抽取纯文本 |
| 语言选择 | 识别语种、按语种分组 |

### Step 2：语料过滤

| 方法 | 思路 |
|---|---|
| **模型法** | 训一个文本质量分类器，过滤低质量 |
| **启发式** | 人工定义指标（长度、标点比例、特殊字符比例等） |

过滤目标：去除乱码、广告、无意义内容。

### Step 3：语料去重

| 方法 | 思路 |
|---|---|
| 文档级 | 用 hash 算文档相似度 |
| 子串级 | 精确匹配重复片段 |

> ⚠️ 大量重复数据会**严重损害模型泛化能力**。

### 进阶高质量数据集

| 数据集 | 特点 |
|---|---|
| **RedPajama-1T** | 复刻 LLaMA 数据，1T token |
| **SlimPajama-627B** | RedPajama 去重精简版，**627B 反而比 1T 效果更好** |

→ 印证了**质量 > 数量**。

## 💰 真实算力消耗

| 模型规模 | 算力需求 |
|---|---|
| **1B 级 LLM** | 256 张 A100 × 2~3 天 |
| **10B 级 LLM** | 1024 张 A100 × 1~2 周 |
| **100B 级 LLM** | **1024 张 A100 × 1~2 个月** |
| **千亿+** | 万卡级集群 × 数月 |

→ 这就是为什么 Pretrain 是**资本和算力的游戏**，绝大多数人**只能基于开源 Base 做后训练**。

---

## ⚠️ 小白避坑

1. **不要试图自己 Pretrain**
   - 普通人/小公司根本玩不起
   - 99% 场景用开源 Base 模型 + SFT/RLHF 就够
2. **Scaling Law 不是绝对**
   - 数据质量 > 数据数量
   - 架构差异、训练技巧都会影响实际效果
3. **数据清洗是真正的"脏活累活"**
   - 抓数据 → 清洗 → 去重 → 配比，每步都很重要
4. **中文 LLM 训练成本更高**
   - 中文数据获取难，更贵
   - 这是国内 LLM 比 GPT-4 弱一些的部分原因
