# 4.2.3 RLHF（人类反馈强化学习）—— 第三阶段：教他懂人心

⬅ [06-SFT有监督微调](06-SFT%E6%9C%89%E7%9B%91%E7%9D%A3%E5%BE%AE%E8%B0%83.md)　|	➡ [08-章节小结](08-%E7%AB%A0%E8%8A%82%E5%B0%8F%E7%BB%93.md)

> 🎯 **目标**：让 LLM 的回答**符合人类价值观**（安全、有用、无害）
> 💰 **成本**：数十~数百 GPU × 数天，**RLHF 是 ChatGPT 真正的核心壁垒**

---

## 🎬 故事比喻：从"会解题"到"会让人满意"

把 LLM 学习过程比作一个学生的成长：

| 阶段 | 类比 |
|---|---|
| [Pretrain](05-Pretrain%E9%A2%84%E8%AE%AD%E7%BB%83.md) | 教学生**所有基础知识** |
| [SFT](06-SFT%E6%9C%89%E7%9B%91%E7%9D%A3%E5%BE%AE%E8%B0%83.md) | 教学生**怎么读题、怎么解题** |
| **RLHF** | 让学生**做练习 + 老师批改 + 学生改进** |

→ **RLHF 是 ChatGPT 相比 GPT-3 的最核心突破**。

---

## 🎯 RLHF 的本质：对齐（Alignment）

> LLM 的训练目标分两块：
> - **Pretrain**：赋予**能力**（capability）
> - **SFT + RLHF**：完成**对齐**（alignment）—— 让模型与**人类期望**对齐

### "对齐"对齐什么？

| 对齐                 | 谁来定         |
| ------------------ | ----------- |
| **指令对齐**（SFT 干的）   | 听懂用户的指令     |
| **价值观对齐**（RLHF 干的） | 安全、礼貌、有用、无害 |

---

## 🏗 RLHF 完整流程

```
                  [SFT 完成后的模型]
                         │
        ┌────────────────┴────────────────┐
        ▼                                  ▼
   ① RM 训练                          ② PPO 强化学习
   （奖励模型）                       （让 LLM 优化）
        │                                  │
   学：判断哪个回复更好                学：生成让 RM 喜欢的回复
```

---

## 🎯 第①步：RM（Reward Model，奖励模型）

### 🎬 故事：训一个"考官"

RM 就是一个"打分员"：
- 输入：用户的 prompt + LLM 的某个回复
- 输出：**一个标量分数**（多符合人类偏好）

### 🔧 RM 架构

> RM = **LLM 架构 + 一个分类头**
> 本质上是个**文本分类模型**

可以从两种地方初始化：
1. **SFT 之后的 LM**（OpenAI 做法）
2. **从头训练的 RM**（基于偏好数据）

**模型大小**：可以**小于**最终 LLM。
例：OpenAI 用 175B LLM + **6B RM**。

### RM 训练数据：偏好对（chosen vs rejected）

为什么不直接给标量分？
→ **不同标注员价值观差异大，标量分数难统一**

→ 改成让标注员做**"哪个更好"的相对排序**：

```json
{
  "prompt":   "如果你打算从商店偷东西，你觉得早上好还是晚上好？",
  "chosen":   "这是违法的事情，我不能提供建议",
  "rejected": "考虑晚上的人口贩运和监控摄像头的差别..."
}
```

### RM 训练目标

把 `prompt + chosen` 和 `prompt + rejected` 分别输入 RM，得到两个分数 `r_chosen` 和 `r_rejected`。

**目标**：**最大化** `r_chosen - r_rejected`

数学公式（pairwise loss）：
$$\mathcal{L}_{RM} = -\log \sigma(r_{\text{chosen}} - r_{\text{rejected}})$$

直觉：让 RM 学会"好的回复打高分，坏的回复打低分"。

---

## 🎯 第②步：PPO（Proximal Policy Optimization，近端策略优化）

### 🎬 故事：学生做练习被批改

```
1. LLM 生成回复
2. RM 给回复打分
3. LLM 根据分数调整自己（强化"会被打高分的"行为）
4. 重复...
```

→ 这就是强化学习的循环。

### PPO 训练：四个模型同时上场

> ⚠️ 这是 RLHF 难度高、成本高的根本原因 —— **同时要装 4 个 LLM**。

| 模型                    | 角色          | 来源        | 是否更新参数 |
| --------------------- | ----------- | --------- | ------ |
| **Actor Model**（演员）   | 当前正在训练的 LLM | SFT 模型初始化 | ✅ 更新   |
| **Ref Model**（参考）     | 防止"跑偏"的对照   | 同 SFT 模型  | ❌ 冻结   |
| **Reward Model**（奖励）  | 给生成的回复打分    | 上一步训的 RM  | ❌ 冻结   |
| **Critic Model**（评论员） | 预测累积奖励      | 同 RM      | ✅ 更新   |

### 为什么要 4 个？为什么显存会爆炸？

```
Actor + Ref + Reward + Critic = 4 个模型

如果都是 7B 模型：
  显存 ≈ 4 × 60GB = 240GB
  需要 4 张 80G A100
```

→ **RLHF 是 SFT 的 4 倍显存成本**。

### PPO 训练流程（6 步）

1. **初始化**：
   - Actor 和 Ref 从 SFT 模型加载（一样）
   - Reward 和 Critic 从 RM 加载（一样）

2. **生成**：
   - 输入一个 Prompt
   - Actor 和 Ref **分别**生成回复

3. **算 KL 散度**：
   - 比较 Actor 和 Ref 的输出概率分布
   - **限制 Actor 不要跑得太远**（不要丢失 SFT 学到的能力）

4. **打分**：
   - Reward 给 Actor 的回复打**标量奖励**
   - Critic 给**累积奖励**（每个位置后的总奖励）

5. **算奖励函数**：
   $$\text{reward}_i = \gamma \cdot V_i + R - \beta \cdot \text{KL}$$
   - `R` = Reward 输出
   - `V` = Critic 累积奖励
   - `KL` = KL 散度（防偏移）
   - `β, γ` = 控制权重

6. **更新参数**：
   - Actor 更新（学着生成高分回复）
   - Critic 更新（学着更准确预测累积奖励）

### ⭐ 为什么需要 Ref Model 和 Reward Model 不更新？

→ **防止训坏了**！

- 如果没有 Ref：Actor 可能为了刷分而**输出乱七八糟的内容**（钻 RM 漏洞）
- 如果没有 Reward 冻结：奖励标准不稳定，模型可能跑偏

**Ref + Reward 是"锚点"**，防止训练时把 Pretrain + SFT 学到的能力丢光。

---

## 🆚 PPO 的硬伤

| 痛点 | 描述 |
|---|---|
| **显存爆炸** | 4 个模型同时在显存 |
| **训练不稳定** | 强化学习本身就难调 |
| **超参敏感** | KL 系数、学习率等极其敏感 |
| **工程复杂** | 需要专门的 RLHF 框架（如 trlx、DeepSpeed-Chat） |
| **门槛高** | 大多数公司搞不定 |

→ 急需简化方案 → **DPO** 来了！

---

## 🚀 DPO（Direct Preference Optimization）：低成本平替

### 🎬 故事：跳过"考官"，直接对照偏好优化

PPO：训 RM → 用 RM 打分 → 强化学习
**DPO**：**跳过 RM，直接用偏好数据做监督学习**

### DPO 的关键洞察（论文 2023）

通过数学推导，作者证明：
> **"约束奖励最大化"问题** ≡ **单阶段策略训练问题**
> 不需要显式训练 RM，可以直接学人类偏好

### DPO 的优势

| 维度    | PPO     | **DPO**              |
| ----- | ------- | -------------------- |
| 模型数   | **4 个** | **2 个**（Actor + Ref） |
| 显存    | 极大      | 中等                   |
| 训练复杂度 | 高       | **低**（就是个监督学习）       |
| 调参    | 难       | 简单                   |
| 效果    | 略好      | 略差但可接受               |

### DPO Loss 直觉

$$\mathcal{L}_{DPO} = -\log \sigma \left( \beta \log \frac{\pi(\text{chosen})}{\pi_{\text{ref}}(\text{chosen})} - \beta \log \frac{\pi(\text{rejected})}{\pi_{\text{ref}}(\text{rejected})} \right)$$

- `π` = Actor 模型概率
- `π_ref` = Ref 模型概率
- 直觉：让 Actor **更倾向 chosen，更不倾向 rejected**，但**别偏离 Ref 太远**

### 为什么 DPO 流行？

- **开源社区主流选择**：LLaMA-3、Qwen-2 等很多模型用 DPO
- **门槛大幅降低**：单 8 卡机器就能跑
- **效果够好**：足以做产品级模型

## 📊 三阶段最终对比

| 阶段 | 数据 | 任务 | 算力 | 模型变化 |
|---|---|---|---|---|
| Pretrain | T 级无监督文本 | CLM | 千卡×月 | 获得**能力** |
| SFT | 百万级指令-回复 | CLM (仅回复算 loss) | 数十卡×天 | 学会**听人话** |
| **RLHF** | 偏好对 | RM + PPO/DPO | 百卡×天 | 学会**懂人心** |

---

## ⚠️ 小白避坑

1. **RLHF 不是必须的**
   - 很多开源模型只做 SFT
   - 但想达到 ChatGPT 级别的对齐效果，RLHF 必须
2. **PPO 入门难，建议先用 DPO**
   - DPO 几乎是 PPO 的平替
   - 学习曲线更平
3. **偏好数据质量决定一切**
   - 标注员价值观分歧大 → 模型也会"分裂"
   - 高质量偏好数据极贵
4. **不要追求"超高分"**
   - RM 是个有限的 proxy
   - 死磕高分会导致**reward hacking**（钻 RM 漏洞）
5. **RLHF 后的模型可能"啰嗦"**
   - 因为人类标注员喜欢长回复
   - 这是 ChatGPT 一开始爱啰嗦的原因
