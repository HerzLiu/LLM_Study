# 6.3.1 高效微调三大流派对比

⬅ [03-SFT实战要点](03-SFT%E5%AE%9E%E6%88%98%E8%A6%81%E7%82%B9.md)	|	➡ [05-LoRA原理深入](05-LoRA%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md)

> ⭐ **理论重点章节开始**：本节起重点放在 PEFT（**P**arameter-**E**fficient **F**ine-**T**uning）的原理对比。

---

## 🎬 故事比喻：给大学生改作文

[全参数微调](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/10-SFT%E8%AE%AD%E7%BB%83.md) = **重写整篇作文**
- 工作量巨大
- 容易把好的地方也改坏（**灾难性遗忘**）

**高效微调（PEFT）** = **只改少量字 / 加批注**：
- 保留原作 90% 内容
- 只在关键处插入或调整

→ **省钱、省显存、保留原能力**。

---

## 📊 为什么需要高效微调？

### 全参数微调的代价

| 模型 | 全参数微调显存（bf16+Adam） |
|---|---|
| 7B | **~112 GB**（需要 2× A100 80G） |
| 13B | ~208 GB |
| 70B | ~1100 GB（多机才能跑） |

→ **个人开发者 / 小团队根本玩不起**。

### 高效微调的承诺

> **训练参数量降到 0.1%~1%，显存降 80%~90%，效果只损失几个百分点。**

| 模型 | 全参数 | LoRA（r=8） | **节省** |
|---|---|---|---|
| 7B | 全部 7B | **~4M**（0.06%）| **99.94%** |
| 13B | 13B | ~6M | 99.95% |
| 70B | 70B | ~16M | 99.98% |

→ **单卡 24G 都能微调 7B**！

---

## 🌳 PEFT 三大流派

```
                  PEFT 高效微调
                        │
        ┌───────────────┼───────────────┐
        │                │                │
   Adapter Tuning   Prefix Tuning      LoRA ⭐
   (加适配器)        (加虚拟前缀)     (低秩分解)
        │                │                │
   每层插入小模块    每层加 prompt 向量  并行旁路矩阵
        │                │                │
   ❌ 推理变慢       ❌ 占用序列长度    ✅ 部署零延迟
                                       ✅ 当前主流
```

---

## 🔧 流派 1：Adapter Tuning（适配器）

### 思路

在 Transformer **每一层中插入小的"适配器模块"**，冻结原参数，只训练适配器。

```
原 Transformer 层：
   Attention → FFN → 输出

加 Adapter 后：
   Attention → Adapter → FFN → Adapter → 输出
              ↑                ↑
          训练这两个         冻结其他
```

### Adapter 模块结构

```
输入 (d 维)
   ↓
线性层 W_down: d → m   （降维，m << d，比如 d=768, m=64）
   ↓
非线性激活（如 ReLU）
   ↓
线性层 W_up: m → d     （升维回去）
   ↓
+ 残差连接（加上输入）
```

→ **瓶颈结构**：降维 → 激活 → 升维，参数量 = `2 × d × m`，远小于原层。

### 优点
- ✅ 参数少（只训 Adapter）
- ✅ 可针对不同任务保存不同 Adapter

### 缺点 ⚠️
- ❌ **推理延迟**：每层多了 Adapter 计算
- ❌ 修改了模型计算图

→ **不适合需要快速推理的生产场景**。

---

## 🔧 流派 2：Prefix Tuning（前缀微调）

### 思路

**给输入加一段"虚拟前缀"**（不在词表里），训练时只更新这些前缀的 embedding。

```
原输入：       [token1, token2, token3, ...]
加前缀后：     [P1, P2, P3, ..., Pn, token1, token2, token3, ...]
                ↑─── 训练这些 ───↑    ↑─── 冻结原模型 ───↑
```

类似的做法：**P-Tuning / Prompt Tuning** 都属于这一派。

### 思想

> 不改模型参数，而是**让前缀向量"激发"模型不同的能力**。
> 类似给模型一个 prompt，但 prompt 是连续向量而非文字。

### 优点
- ✅ 参数少（只训前缀）
- ✅ 多任务共享底模

### 缺点 ⚠️
- ❌ **占用序列长度**：原本能输入 2048 token，加 100 个前缀后只剩 1948
- ❌ 越复杂的任务需要越长前缀 → 上下文越短
- ❌ 训练不稳定

→ **现在已经较少用，被 LoRA 取代**。

---

## 🔧 流派 3：LoRA ⭐（**当前主流**）

### 一句话思路

**在每个权重矩阵 W 旁加一条"并行旁路"** $\Delta W = BA$（B 和 A 是两个低秩小矩阵），只训这个旁路。

```
原层：
   x → W → 输出

LoRA 加旁路：
   x → W (冻结) ────────┐
   ↓                       + → 输出
   x → A → B (训练) ──────┘
       (低秩分解 ΔW = BA)
```

### 三大派别核心对比

| 对比项 | Adapter | Prefix | **LoRA** ⭐ |
|---|---|---|---|
| **位置** | 每层中插入新模块 | 输入层加虚拟 token | 每个权重矩阵加旁路 |
| **训练参数** | Adapter 权重 | 前缀 embedding | 低秩矩阵 A、B |
| **推理延迟** | ❌ 慢（多了模块） | ❌ 慢（多了 token） | ✅ **零延迟**（可合并） |
| **占用序列长度** | ❌ 否 | ✅ **是**（致命） | ❌ 否 |
| **效果** | 中等 | 中等 | **好** |
| **当前流行度** | 较少用 | 较少用 | ✅ **绝对主流** |

---

## ⭐ LoRA 为什么能赢？

### 1. 零推理延迟（关键优势）

LoRA 训练好后，**可以把 BA 直接加到 W 上**：
$$W' = W + BA$$

→ 推理时**和原模型完全一样的计算图**，没有任何延迟。
→ Adapter 和 Prefix 都做不到。

### 2. 不占序列长度

→ 比 Prefix 强。

### 3. 参数高效

7B 模型只需要训 **几 M 参数**（< 0.1%）。

### 4. 与其他方法正交

- LoRA + DPO ✅
- LoRA + Quantization → **QLoRA**（4bit 量化 + LoRA）✅
- LoRA + ZeRO ✅

### 5. 生态完善

- HuggingFace **PEFT 库**封装好了
- 一行接入 Trainer

---

## 🌍 LoRA 衍生家族

| 方法 | 改进点 |
|---|---|
| **LoRA** | 经典低秩分解 |
| **QLoRA** | LoRA + 4bit 量化，**24G 可微调 65B** |
| **AdaLoRA** | 自适应分配秩 r |
| **DoRA** | 分解权重为方向 + 大小 |
| **LoRA+** | 给 A 和 B 用不同学习率 |
| **PiSSA** | 用奇异值分解初始化 |

→ 都是 LoRA 思想的延伸。

---

## ⚠️ 小白避坑

1. **PEFT ≠ 零损失**
   - 高效微调相比全参数微调**通常会有 1~3% 的效果下降**
   - 但换来 90%+ 的显存节省，**完全划算**
2. **不要用 LoRA 做"知识注入"**
   - LoRA 只调低秩矩阵，**学不会大量新知识**
   - 想注入领域知识：继续预训练（CPT） + 全参数 SFT 更靠谱
3. **r 不是越大越好**
   - r=4/8/16 是最佳区间
   - r=64+ 通常不会更好，反而过拟合
4. **Adapter 和 Prefix 在某些场景仍有价值**
   - Adapter 适合**多任务热切换**
   - Prefix 适合**few-shot 场景的快速适配**

---

## 📌 6.3.1 节要点

- 全参数微调**贵到普通人玩不起** → PEFT 应运而生
- PEFT 三大流派：**Adapter**（插模块）、**Prefix**（加前缀）、**LoRA**（加旁路）
- **LoRA 凭借"零推理延迟 + 不占序列长度 + 工具链成熟"成为当前主流**
- 衍生有 QLoRA / AdaLoRA / DoRA 等
