# 3.2.1 T5 —— 一切皆文本（大一统思想）

⬅ [04-ALBERT](04-ALBERT.md)　|	➡ [06-GPT](06-GPT.md)

> 📅 Google 2019 年发布
> 📄 论文：《Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer》
> 🎯 核心信息：**所有 NLP 任务都是"文本到文本"**

---

## 🎬 故事比喻：万物皆翻译

[BERT](02-BERT.md) 派：每个任务需要不同的 `prediction_head`，分类要分类头，NER 要标注头……
**T5 派**：太麻烦了，**统统当成"翻译"任务**！

- **情感分类**：输入 `"sentiment: 这部电影真棒"` → 输出 `"positive"`
- **机器翻译**：输入 `"translate English to French: How are you?"` → 输出 `"Comment ça va?"`
- **摘要**：输入 `"summarize: 长文章……"` → 输出 `"短摘要"`
- **问答**：输入 `"question: 谁是 Apple 的 CEO?"` → 输出 `"Tim Cook"`

→ 所有任务都是**输入文本 → 输出文本**，模型架构完全统一。
**这就是 T5 的"大一统思想"**。

T5 的全名 **T**ext-**T**o-**T**ext **T**ransfer **T**ransformer 里**有 5 个 T**，所以叫 **T5**。

---

## 🔧 模型架构：完整 Encoder-Decoder

T5 是三大流派里唯一**完整保留 Transformer 双流水线**的：

```
输入文本 ──→ Tokenizer ──→ Encoder × N ──→ Encoder 输出
                                                │
                                                ▼
目标文本 ──→ Tokenizer ──→ Decoder × N ←─ 交叉注意力
                                                │
                                                ▼
                                          生成输出文本
```

### Block 设计：像乐高一样灵活

T5 把 Encoder 和 Decoder 都拆成可堆叠的 Block：

```
┌─ Encoder Block ──────────┐    ┌─ Decoder Block ────────────┐
│ Self-Attention          │    │ Masked Self-Attention      │
│ + RMSNorm + 残差        │    │ + RMSNorm + 残差            │
│ Feed Forward            │    │ Cross-Attention（看 Encoder）│
│ + RMSNorm + 残差        │    │ + RMSNorm + 残差            │
└─────────────────────────┘    │ Feed Forward                │
                                 │ + RMSNorm + 残差            │
                                 └────────────────────────────┘
```

每个 Block 包含：
- [多头注意力](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/05-%E5%A4%9A%E5%A4%B4%E6%B3%A8%E6%84%8F%E5%8A%9B.md)
- [FFN](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/06-Encoder-Decoder.md#-%E5%89%8D%E9%A6%88%E7%A5%9E%E7%BB%8F%E7%BD%91%E7%BB%9Cffn)
- **RMSNorm**（不是 LayerNorm！见下方）

### 与原版 Transformer 的关键差异

#### 差异 1：用 RMSNorm 替代 LayerNorm

[LayerNorm](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/07-LayerNorm%E4%B8%8EBatchNorm.md) 公式：
$$\text{LN}(x) = \gamma \cdot \frac{x - \mu}{\sigma + \epsilon} + \beta$$

**RMSNorm** 公式（简化版）：
$$\text{RMSNorm}(x_i) = \gamma_i \cdot \frac{x_i}{\sqrt{\frac{1}{n}\sum_{j=1}^n x_j^2 + \epsilon}}$$

| 区别 | LayerNorm | **RMSNorm** |
|---|---|---|
| 减均值 | ✅ | ❌（去掉） |
| 除标准差 | ✅ | ❌ 改成除 RMS（均方根） |
| 仿射变换 | γ + β | 只有 γ |
| 速度 | 基线 | **快 7~64%** |
| 效果 | 基线 | 几乎一致甚至更好 |

→ **RMSNorm 是后来 LLaMA 等所有现代 LLM 的标配**（第 5 章会用到）。

#### 差异 2：相对位置编码

T5 用的是**相对位置编码（Relative Position Bias）**，而不是 [sin/cos 绝对位置编码](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/09-%E4%BD%8D%E7%BD%AE%E7%BC%96%E7%A0%81.md)。
- 把位置编码加到注意力 logits 上（而不是加到 Embedding 上）
- 能更好地处理长序列

## 🎯 预训练任务

### 任务类型：MLM 的改进版（Span Corruption）

T5 的预训练任务和 BERT 的 MLM 很像，但有改进：

|      | BERT MLM      | **T5 Span Corruption**                |
| ---- | ------------- | ------------------------------------- |
| 遮蔽对象 | 单个 token      | **连续一段 token（span）**                  |
| 输入格式 | 用 `[MASK]` 替换 | 用 `<extra_id_0>`, `<extra_id_1>` 等占位符 |
| 输出格式 | 预测被遮蔽位置       | **生成所有遮蔽片段的连续文本**                     |

#### 例子

```
原文：
  The quick brown fox jumps over the lazy dog.

遮蔽（连续 span）：
  The quick <X> over <Y> dog.

输出格式（生成式）：
  <X> brown fox jumps <Y> the lazy <Z>
```

> 这种"输入挖空 → 输出生成被挖部分"的设计，**完美适配 Encoder-Decoder 架构**：
> - Encoder 读输入（带占位符）
> - Decoder 生成被挖部分

### 预训练数据：C4

| 项 | 数值 |
|---|---|
| 数据集名称 | **C4**（Colossal Clean Crawled Corpus） |
| 大小 | **750 GB** |
| 来源 | Common Crawl 的英文部分 |
| 处理 | 去除无意义文本、重复文本等 |

> 💡 C4 后来成为很多模型的"标配数据集"。

## 🎨 大一统思想详解

### 任务前缀（Task Prefix）

T5 用**简单的英文前缀**告诉模型当前是什么任务：

| 任务 | 前缀示例 |
|---|---|
| 情感分类 | `"sentiment:"` |
| 翻译 | `"translate English to German:"` |
| 摘要 | `"summarize:"` |
| 问答 | `"question:"` |
| 相似度 | `"stsb sentence1: ... sentence2: ..."` |

### 优点

1. **架构统一** —— 一个模型搞定所有任务，省去针对每个任务的分类头
2. **多任务共训练** —— 同一模型同时学多任务，知识互相迁移
3. **泛化能力强** —— 面对新任务，只需设计新的前缀（**这就是 prompt 的雏形！**）
4. **简化部署** —— 一个权重文件搞定所有任务

### ⭐ 加深理解：T5 是 Prompt Engineering 的祖宗

T5 的"任务前缀"思想 = **现代 prompt 的原型**：

| T5 | LLM Prompt |
|---|---|
| `summarize: <长文章>` | `请总结以下文章：<长文章>` |
| `translate English to French: Hello` | `请把"Hello"翻译成法语` |

T5 用**少量训练好的固定前缀**，LLM 用**任意自然语言指令**（**Instruction Tuning**）。
本质都是"**用文本格式描述任务，让一个模型搞定一切**"。

---

## 📈 T5 的历史意义

1. **大一统思想** —— 影响了后来所有 LLM 的设计哲学
2. **C4 数据集** —— 成为业界标配
3. **RMSNorm** —— 启发了 LLaMA 等现代 LLM
4. **完整 Encoder-Decoder 的最后一次辉煌** —— 后来 Decoder-only 派崛起，T5 风格逐渐式微
5. **现存优势**：在**结构化的 Seq2Seq 任务**（如翻译、摘要）上仍有竞争力

---

## ⚠️ T5 为什么没成为主流？

虽然 T5 思想超前，但最终没能像 GPT 那样成为 LLM 主角：

| 原因           | 解释                                               |
| ------------ | ------------------------------------------------ |
| **架构复杂**     | Encoder-Decoder 两套权重 + 交叉注意力，工程难度高               |
| **训练成本高**    | 同样参数量，Encoder-Decoder 比 Decoder-only 更慢          |
| **推理成本高**    | 输入要 Encoder 编码一次，输出要 Decoder 自回归                 |
| **大模型规模化困难** | 想做到千亿参数级别，简单架构（Decoder-only）更容易                  |
| **GPT 涌现能力** | GPT-3 出现 in-context learning 后，Decoder-only 优势凸显 |

→ 详见 [为什么 Decoder-only 赢了](01-PLM%E4%B8%89%E5%A4%A7%E6%B5%81%E6%B4%BE%E5%AF%B9%E6%AF%94.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3%E4%B8%BA%E4%BB%80%E4%B9%88-decoder-only-%E6%9C%80%E7%BB%88%E8%B5%A2%E4%BA%86)

---

## ⚠️ 小白避坑

1. **T5 ≠ 翻译模型**，是**所有 NLP 任务的统一框架**
2. **"任务前缀"不是 prompt engineering 的全部** —— T5 的前缀是**训练时固化**的，LLM 的 prompt 是**推理时灵活**的
3. **T5 现在有更新版本**：mT5（多语言）、Flan-T5（指令微调）等仍在使用
4. **RMSNorm 不是 T5 独创**，但 T5 是早期采用者之一
