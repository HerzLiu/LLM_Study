# 3.0 PLM 三大流派对比（鸟瞰图）

## 🎬 故事比喻：拆工厂的三派人

[原版 Transformer 工厂](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/06-Encoder-Decoder.md)里有两条流水线：
- 🏗 **Encoder**（理解车间）：擅长把输入"嚼烂消化"
- 🏭 **Decoder**（生成车间）：擅长一个字一个字地"吐出来"

2018 年开始，三派人马把工厂拆了各自发展：

### 🅰 派别 A：理解派（Encoder-only）
**代表**：BERT、RoBERTa、ALBERT、DistilBERT、ERNIE…

> "我们不需要生成什么东西，我们要的是**听懂**人话。"

把 Encoder 堆得很厚很深，做"双向理解"。给一段文本，输出**理解结果**（分类标签、实体位置、相似度等）。

### 🅱 派别 B：转换派（Encoder-Decoder）
**代表**：T5、BART

> "万物皆可转换：分类是文本→标签转换、翻译是中文→英文转换、摘要是长→短转换。所以**Encoder 编码 + Decoder 生成**最通用。"

完整保留 Transformer 的双流水线。

### 🅲 派别 C：生成派（Decoder-only）⭐ 现代主流
**代表**：GPT 1/2/3/4、LLaMA、Qwen、ChatGLM2+、Claude、DeepSeek…

> "**只要会预测下一个词，理解就是顺带的副作用**。规模越大越神奇（涌现能力）。"

只保留 Decoder（带掩码自注意力），训练任务是"看前面预测后面"（CLM）。

| 维度           | Encoder-only                                | Encoder-Decoder              | **Decoder-only** ⭐                            |
| ------------ | ------------------------------------------- | ---------------------------- | --------------------------------------------- |
| **代表**       | BERT                                        | T5                           | GPT、LLaMA                                     |
| **保留组件**     | 只 Encoder                                   | 都保留                          | 只 Decoder                                     |
| **注意力类型**    | [双向自注意力](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/03-%E8%87%AA%E6%B3%A8%E6%84%8F%E5%8A%9B.md) | Encoder 双向 + Decoder 掩码 + 交叉 | [掩码自注意力](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/04-%E6%8E%A9%E7%A0%81%E8%87%AA%E6%B3%A8%E6%84%8F%E5%8A%9B.md) |

| **天然支持下游任务** | 需加分类头                                       | 直接生成                         | 直接生成                                          |

## 🔍 为什么是这种分化？

### 任务驱动差异

```
NLU 任务（理解）             NLG 任务（生成）
   ↓                              ↓
需要双向看上下文              天然适合从左到右生成
   ↓                              ↓
双向注意力（Encoder）         掩码注意力（Decoder）
   ↓                              ↓
BERT 系                        GPT 系
```

### 训练任务差异

| 任务              | 思路          | 数据要求      | 适合架构            |
| --------------- | ----------- | --------- | --------------- |
| **CLM**（因果语言建模） | 看前面预测下一个词   | 任意文本，无需标注 | Decoder         |
| **MLM**（掩码语言建模） | 遮一些词让模型补    | 任意文本，无需标注 | Encoder         |
| **T2T**（文本到文本）  | 任何任务都改成文本生成 | 多任务数据     | Encoder-Decoder |

## ⭐ 加深理解：为什么 Decoder-only 最终赢了？

这是面试高频题。**核心原因有 4 个**：

### 原因 1：CLM 任务最"无监督友好"
- CLM 直接从任何文本上学（互联网海量文本都能用）
- MLM 也可以，但**预训练和下游任务不一致**（推理时没 [MASK]）
- → CLM 训练和使用方式天然吻合

### 原因 2：生成能力顺带带来理解能力
- 想生成好下一个词，必须先**充分理解上下文**
- 所以 Decoder-only 模型在大规模训练后，理解能力也跟上来了
- BERT 的双向理解优势被规模碾压

### 原因 3：架构最简单 = 规模化最容易
- Encoder-Decoder 有两套权重 + 交叉注意力，工程复杂
- Decoder-only 只有一套，分布式训练、推理优化都更容易
- 千亿参数级别，简单架构 = 真金白银的成本优势

### 原因 4：涌现能力（Emergent Ability）
- GPT-3 (175B) 出现了 zero-shot / few-shot / 推理能力
- 这种"质变"在小模型上看不到
- 一旦能 in-context learning，**一个模型解决一切任务**，根本不需要微调

→ 这就是为什么 BERT 在 LLM 时代被"边缘化"，而 GPT 系列成了主角。

## 📊 历史时间线

```
2017 ────── Transformer 诞生
2018.06 ──── GPT-1（Decoder-only 试水，被忽视）
2018.10 ──── BERT 横空出世（Encoder-only 称王 3 年）
2019 ─────── RoBERTa / ALBERT / T5 / GPT-2
2020 ─────── GPT-3 175B（涌现能力出现，转折点）
2022.11 ──── ChatGPT 引爆全民认知
2023 ─────── LLaMA / ChatGLM 开源浪潮，Decoder-only 一统天下
2024+ ────── GPT-4 / Claude / Qwen / DeepSeek 持续迭代
```

## ⚠️ 小白避坑

1. **BERT 没死**
   - 在标注数据丰富、强调推理速度的 NLU 场景（如分类、检索召回），BERT 仍然是首选
   - 比如 RAG 里的 embedding 模型，几乎都是 BERT 系
2. **Encoder-Decoder 也没死**
   - 翻译、摘要等明确的 Seq2Seq 任务，T5/BART 仍有竞争力
3. **现代 LLM = Decoder-only ≠ 没有 Encoder 思想**
   - LLaMA 用的 [因果自注意力](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/04-%E6%8E%A9%E7%A0%81%E8%87%AA%E6%B3%A8%E6%84%8F%E5%8A%9B.md)，其实也是"理解前文 + 生成下一个"的过程
   - 只是没有显式分成两个模块
