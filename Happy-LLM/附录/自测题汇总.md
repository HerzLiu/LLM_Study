## 第 1 章

→ 来自 [第 1 章总览](../01-%E7%AC%AC1%E7%AB%A0-NLP%E5%9F%BA%E7%A1%80%E6%A6%82%E5%BF%B5/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

### 题目

1. 为什么 One-Hot 编码下"猫"和"狗"的相似度是 0？
2. Word2Vec 的 CBOW 和 Skip-Gram 区别是什么？哪个适合大数据集？
3. ELMo 相比 Word2Vec 最关键的进步是什么？
4. 子词切分（如 BPE）解决了什么问题？为什么 LLM 都用它？

<details>
<summary>👉 参考答案（点开）</summary>

**1.** 因为 One-Hot 每个词的"1"在不同位置，两个不同词的向量内积必然是 0，从向量层面无法体现任何语义相似性。
→ 详见 [99-代码-OneHot对比Word2Vec](../01-%E7%AC%AC1%E7%AB%A0-NLP%E5%9F%BA%E7%A1%80%E6%A6%82%E5%BF%B5/99-%E4%BB%A3%E7%A0%81-OneHot%E5%AF%B9%E6%AF%94Word2Vec.md)

**2.** CBOW 用周围词预测中间词，Skip-Gram 用中间词预测周围词；**Skip-Gram 适合大数据集**。
→ 详见 [Word2Vec](../01-%E7%AC%AC1%E7%AB%A0-NLP%E5%9F%BA%E7%A1%80%E6%A6%82%E5%BF%B5/04-%E6%96%87%E6%9C%AC%E8%A1%A8%E7%A4%BA%E6%BC%94%E8%BF%9B.md#3-word2vec2013mikolov)

**3.** ELMo 是**动态词向量** —— 同一个词在不同上下文里向量不同（解决了一词多义）；同时引入了**预训练 + 微调**的范式。
→ 详见 [ELMo](../01-%E7%AC%AC1%E7%AB%A0-NLP%E5%9F%BA%E7%A1%80%E6%A6%82%E5%BF%B5/04-%E6%96%87%E6%9C%AC%E8%A1%A8%E7%A4%BA%E6%BC%94%E8%BF%9B.md#4-elmo2018)

**4.** 子词切分解决了**生词（OOV）问题**和**词汇表过大问题**。LLM 用它是因为：(1) 词表可控（几万就够）(2) 遇到没见过的词也能拆开理解 (3) 多语言通用。
→ 详见 [子词切分](../01-%E7%AC%AC1%E7%AB%A0-NLP%E5%9F%BA%E7%A1%80%E6%A6%82%E5%BF%B5/03-NLP%E4%B9%9D%E5%A4%A7%E4%BB%BB%E5%8A%A1.md#%E2%91%A1-%E5%AD%90%E8%AF%8D%E5%88%87%E5%88%86subword--%E9%87%8D%E8%A6%81)

</details>

## 第 2 章

→ 来自 [第 2 章总览](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

### 题目

1. 注意力公式 `softmax(QK^T/√d_k)·V` 里，为什么要除以 √d_k？
2. 自注意力和普通注意力的区别是什么？
3. 掩码注意力的 mask 为什么是"上三角"而不是"下三角"？
4. 多头注意力的头数 h=8 时，为什么每头维度是 `d_model/8` 而不是 `d_model`？
5. LayerNorm 和 BatchNorm 在 NLP 任务上各自的优劣？
6. 残差连接为什么能解决梯度消失？请写出反向传播时的梯度公式。
7. 位置编码用 sin/cos 而不用简单的整数 0,1,2,... 有什么好处？
8. Pre-Norm 和 Post-Norm 的区别？现代 LLM 为什么选 Pre-Norm？

<details>
<summary>👉 参考答案（点开）</summary>

**1.** 当 `d_k` 大时 `QK^T` 方差正比于 `d_k`，值会很大，softmax 输出趋近独热，梯度饱和。除以 `√d_k` 把方差拉回 1 附近，让 softmax 工作在敏感区。
→ 详见 [为什么除以 √d_k](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/02-%E6%B3%A8%E6%84%8F%E5%8A%9B%E6%9C%BA%E5%88%B6QKV.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3%E4%B8%BA%E4%BB%80%E4%B9%88%E8%A6%81%E9%99%A4%E4%BB%A5-d_k)

**2.** 普通注意力：Q 来自一个序列，K/V 来自另一个序列（如交叉注意力）。自注意力：Q、K、V 全来自同一个输入（用不同权重矩阵投影），用于建模序列内部的依赖。
→ 详见 [03-自注意力](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/03-%E8%87%AA%E6%B3%A8%E6%84%8F%E5%8A%9B.md)

**3.** 因为通常我们把序列从前往后排，位置 i 的 token 不能看到位置 i+1 及之后（未来）。在 `(seq_len, seq_len)` 的 score 矩阵里，"位置 i 看位置 j" 对应第 `(i, j)` 格，要屏蔽的是 j>i 的部分，正好是上三角。
→ 详见 [04-掩码自注意力](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/04-%E6%8E%A9%E7%A0%81%E8%87%AA%E6%B3%A8%E6%84%8F%E5%8A%9B.md)

**4.** 拆头（`d_model/h`）能在**不增加参数量**的前提下，获得 h 倍的视角多样性。如果每头都是 `d_model` 维，参数量会爆炸为 h 倍。
→ 详见 [为什么拆维度](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/05-%E5%A4%9A%E5%A4%B4%E6%B3%A8%E6%84%8F%E5%8A%9B.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3%E4%B8%BA%E4%BB%80%E4%B9%88-d_model--h-%E8%80%8C%E4%B8%8D%E6%98%AF%E6%AF%8F%E5%A4%B4%E9%83%BD-d_model)

**5.** BatchNorm：依赖 batch 大小、不适合变长序列、训练推理不一致。LayerNorm：每个样本独立归一化、不依赖 batch、训练推理一致 —— 完美适配 NLP。
→ 详见 [07-LayerNorm与BatchNorm](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/07-LayerNorm%E4%B8%8EBatchNorm.md)

**6.** 残差层 `y = x + F(x)`，对 x 求导得 `∂y/∂x = 1 + ∂F/∂x`。这个 **+1** 保证梯度不会消失到 0，让深层网络可训练。
→ 详见 [残差与梯度](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/08-%E6%AE%8B%E5%B7%AE%E8%BF%9E%E6%8E%A5.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3%E4%B8%BA%E4%BB%80%E4%B9%88%E6%AE%8B%E5%B7%AE%E8%83%BD%E8%A7%A3%E5%86%B3%E6%A2%AF%E5%BA%A6%E6%B6%88%E5%A4%B1)

**7.** (1) 能外推到训练时没见过的长度；(2) `sin(A+B)` 展开式让 `PE(pos+k)` 能由 `PE(pos)` 线性变换得到，便于学相对位置；(3) 不同维度对应不同频率，多尺度刻画位置。整数 `0,1,2,...` 会导致位置编码的数值随长度增长无界，且不易学相对位置。
→ 详见 [为什么用 sin/cos](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/09-%E4%BD%8D%E7%BD%AE%E7%BC%96%E7%A0%81.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3%E4%B8%BA%E4%BB%80%E4%B9%88%E7%94%A8-sincos-%E8%80%8C%E4%B8%8D%E6%98%AF%E7%AE%80%E5%8D%95%E6%95%B4%E6%95%B0)

**8.** Post-Norm: `LayerNorm(x + Sublayer(x))`，归一化在残差后。Pre-Norm: `x + Sublayer(LayerNorm(x))`，归一化在残差前。Pre-Norm 训练更稳定（梯度更顺、loss 不容易炸），所以 GPT/LLaMA 都用 Pre-Norm。
→ 详见 [Pre-Norm vs Post-Norm](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/08-%E6%AE%8B%E5%B7%AE%E8%BF%9E%E6%8E%A5.md#-pre-norm-vs-post-norm)

</details>

## 第 3 章

→ 来自 [第 3 章总览](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

### 题目

1. PLM 的三大流派是什么？各自代表模型有哪些？
2. BERT 的 MLM 预训练任务里，为什么不是把所有选中的 token 都替换成 `[MASK]`，而要用 80/10/10 策略？
3. RoBERTa 相比 BERT 的三大优化是什么？最关键的发现是什么？
4. ALBERT 用什么手段减少参数？为什么参数变少了训练却没加速？
5. T5 的"大一统思想"是什么？和现代 LLM 的 prompt 有什么关系？
6. GPT 系列的三个关键模型（GPT-1/2/3）分别对应了哪些核心思想？
7. CLM 相比 MLM 在 LLM 时代的优势是什么？
8. LLaMA 相比 GPT 做了哪些架构改进？为什么这些改动如此重要？
9. GLM 的预训练任务（GLM 任务）是怎么融合 MLM 和 CLM 的？后来为什么被放弃？
10. 为什么 Decoder-only 架构最终在 LLM 时代赢了？请至少说出 3 个原因。

<details>
<summary>👉 参考答案（点开）</summary>

**1.** 三派：
- **Encoder-only**（BERT、RoBERTa、ALBERT）：擅长 NLU
- **Encoder-Decoder**（T5、BART）：擅长 Seq2Seq
- **Decoder-only**（GPT、LLaMA、GLM）：擅长 NLG，**现代 LLM 主流**
→ 详见 [01-PLM三大流派对比](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/01-PLM%E4%B8%89%E5%A4%A7%E6%B5%81%E6%B4%BE%E5%AF%B9%E6%AF%94.md)

**2.** 80% [MASK] + 10% 随机 token + 10% 不变。原因：
- **10% 不变**：缓解"预训练有 [MASK]、推理没 [MASK]"的不一致
- **10% 随机**：强迫模型对每个位置都保持注意力，不能只盯着 [MASK]
- 这样模型必须为每个 token 都保留上下文表征能力
→ 详见 [MLM 策略](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/02-BERT.md#%E5%85%B3%E9%94%AE%E6%8A%80%E5%B7%A715-%E9%81%AE%E8%94%BD--801010-%E7%AD%96%E7%95%A5)

**3.** RoBERTa 三大优化：
- ① 去掉 NSP，只用 MLM；动态遮蔽替代静态
- ② 数据量 13GB → **160GB**；batch size 256 → **8K**
- ③ Tokenizer 用 BPE 50K 替代 WordPiece 30K
**关键发现**：**BERT 远没训够**，证明了数据规模 + 大 batch 的重要性，为 LLM 时代的"力大砖飞"奠基。
→ 详见 [03-RoBERTa](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/03-RoBERTa.md)

**4.** ALBERT 两大瘦身：
- **Embedding 参数分解**：V×H 拆成 V×E + E×H（E << H）
- **跨层参数共享**：只初始化 1 层 Encoder，循环用 N 次
**速度没快的原因**：参数少了，但**计算次数没减**（仍要算 24 次 Encoder）。这告诉我们：**衡量模型成本要看 FLOPs，不是只看参数**。
→ 详见 [04-ALBERT](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/04-ALBERT.md)

**5.** T5 大一统思想 = **所有 NLP 任务都改写成"输入文本 → 输出文本"**。用任务前缀（如 `summarize:`、`translate English to French:`）告诉模型当前任务。
**和 prompt 的关系**：T5 是现代 prompt engineering 的祖宗：
- T5 用**固定的训练好的前缀**
- LLM 用**任意自然语言指令**（更灵活）
- 本质都是"用文本格式描述任务"
→ 详见 [T5 大一统](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/05-T5.md#-%E5%A4%A7%E4%B8%80%E7%BB%9F%E6%80%9D%E6%83%B3%E8%AF%A6%E8%A7%A3)

**6.** GPT 三代核心思想：
- **GPT-1**：首次提出**预训练 + 微调**（比 BERT 早 4 个月）
- **GPT-2**：**zero-shot**，引入 Pre-Norm，模型规模化
- **GPT-3**：**few-shot / In-context Learning** + 涌现能力，175B 参数，LLM 时代开启
→ 详见 [GPT 演进](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/06-GPT.md#-gpt-%E7%B3%BB%E5%88%97%E6%A8%A1%E5%9E%8B%E6%BC%94%E8%BF%9B%E6%A0%B8%E5%BF%83%E8%A1%A8%E6%A0%BC)

**7.** CLM 在 LLM 时代的优势：
- ① **训练-推理一致**：CLM 推理时也是看前文生成，完全和训练一致；MLM 推理时根本没 [MASK]
- ② **天然支持生成**：LLM 核心是对话生成，CLM 天然适合
- ③ **数据效率**：CLM 每个 token 都能产生训练信号，MLM 只有 15%
→ 详见 [CLM 优势](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/06-GPT.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3clm-%E5%87%AD%E4%BB%80%E4%B9%88%E5%87%BB%E8%B4%A5-mlm)

**8.** LLaMA 的关键改动：
- **RMSNorm** 替代 LayerNorm（速度快）
- **RoPE** 替代 sin/cos 位置编码（支持长度外推）
- **SwiGLU** 替代 GELU（效果略好）
- **GQA**（LLaMA-2 起）替代标准多头（KV-Cache 小，推理快）
- 仍用 Pre-Norm
**重要性**：这是**现代 LLM 架构的最佳实践组合**，后续几乎所有开源 LLM 都借鉴。
→ 详见 [LLaMA 架构](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/07-LLaMA.md#-%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84decoder-onlygpt-%E6%B5%81%E6%B4%BE)

**9.** GLM 任务 = **MLM 的遮蔽方式 + CLM 的生成方式**：
- 像 MLM 一样遮蔽连续 span
- 但内部用 CLM 顺序生成被遮蔽的 token
**被放弃原因**：
- CLM 在大规模下的生成能力反而能"带飞"理解能力
- GLM 任务实现复杂，预训练数据利用率低
- 现代 LLM 用 SFT + RLHF 对齐人类偏好，GLM 任务的"双向理解优势"用不上
→ 详见 [为什么放弃 GLM](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/08-GLM.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3glm-%E4%BB%BB%E5%8A%A1%E4%B8%BA%E4%BB%80%E4%B9%88%E6%9C%80%E7%BB%88%E8%A2%AB%E6%94%BE%E5%BC%83)

**10.** Decoder-only 赢的 4 大原因：
- ① **CLM 任务最无监督友好**：任意文本都能训，训练-推理完全一致
- ② **生成能力顺带带来理解能力**：想生成好，必须先理解
- ③ **架构最简单**：规模化最容易，分布式训练/推理优化都更简单
- ④ **涌现能力**：大模型下 in-context learning 解锁，一个模型搞定所有任务
→ 详见 [为什么 Decoder-only 赢了](../03-%E7%AC%AC3%E7%AB%A0-%E9%A2%84%E8%AE%AD%E7%BB%83%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/01-PLM%E4%B8%89%E5%A4%A7%E6%B5%81%E6%B4%BE%E5%AF%B9%E6%AF%94.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3%E4%B8%BA%E4%BB%80%E4%B9%88-decoder-only-%E6%9C%80%E7%BB%88%E8%B5%A2%E4%BA%86)

</details>

## 第 4 章

→ 来自 [第 4 章总览](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

### 题目

1. LLM 和传统 PLM（如 BERT）的本质区别是什么？至少说出 3 点。
2. LLM 的"四大独特能力"是什么？哪一个被认为是"区分 LLM 和 PLM 的决定性特征"？
3. 什么是"涌现能力"？它和水沸腾的相变有什么类比关系？
4. ICL（In-context Learning）为什么能引发 NLP 研究范式的变革？
5. LLM 的"幻觉"是什么？为什么无法彻底根除？业界主流缓解方案是什么？
6. 训练 LLM 的三阶段是什么？分别解决什么问题？
7. Scaling Law（OpenAI）和 Chinchilla 法则（DeepMind）的核心结论分别是什么？为什么 LLaMA-1 用 7B 参数干翻了 175B 的 GPT-3？
8. ZeRO 的三级优化分别切分了什么？为什么 ZeRO-3 显存最省但 GPU 利用率最低？
9. SFT 训练时，loss 是对整个输入序列计算的吗？为什么？
10. 多轮对话样本有三种构造方式，为什么"一次性预测每一轮"（方式 3）是最优解？
11. RLHF 的 PPO 训练需要 4 个模型，分别是什么角色？为什么需要冻结 Ref Model 和 Reward Model？
12. DPO 相比 PPO 有什么优势？为什么 DPO 能"无需 RM"就完成对齐？

<details>
<summary>👉 参考答案（点开）</summary>

**1.** LLM vs PLM 的本质区别：
- 参数量：0.1~0.3B → 10B~千亿+
- 数据量：3B → 数 T token
- 架构：Encoder-only 为主 → Decoder-only 为主
- 适配方式：每个任务都要微调 → 直接用 ICL
- 涌现能力：无 → **有**
- 任务方式：一个任务一个模型 → 一个模型搞定一切
→ 详见 [01-什么是LLM](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/01-%E4%BB%80%E4%B9%88%E6%98%AFLLM.md)

**2.** 四大能力：
- **涌现能力**（Emergent）
- **上下文学习**（ICL）
- **指令遵循**（Instruction Following）
- **逐步推理**（CoT）
**决定性特征是涌现能力** —— 这是 LLM 区别于 PLM 最显著的特征。
→ 详见 [02-LLM四大能力](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/02-LLM%E5%9B%9B%E5%A4%A7%E8%83%BD%E5%8A%9B.md)

**3.** 涌现 = 某些能力在小模型中**完全没有**，但在大模型中**突然出现**，超过随机水平。
**与相变的类比**：水 99°C 还是水，100°C 突然变蒸汽。LLM 的能力也不是平滑增长，而是"达到某规模后突然质变"。
→ 详见 [涌现能力](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/02-LLM%E5%9B%9B%E5%A4%A7%E8%83%BD%E5%8A%9B.md#-%E8%83%BD%E5%8A%9B-1%E6%B6%8C%E7%8E%B0%E8%83%BD%E5%8A%9Bemergent-abilities)

**4.** ICL 让 NLP 范式从"**预训练-微调**"变成"**Prompt Engineering**"：
- 旧：每任务标几千数据 → 微调一个模型
- 新：写几个 prompt → 一个模型搞定所有任务
→ **训练成本几乎为 0，部署成本极低，应用门槛大幅下降**
→ 详见 [ICL](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/02-LLM%E5%9B%9B%E5%A4%A7%E8%83%BD%E5%8A%9B.md#-%E8%83%BD%E5%8A%9B-2%E4%B8%8A%E4%B8%8B%E6%96%87%E5%AD%A6%E4%B9%A0in-context-learning-icl)

**5.** 幻觉 = LLM **杜撰生成虚假、错误信息**的现象。
**无法根除的原因**：
- CLM 任务本质只学"接下一个词"，不学"真实性"
- 训练数据本身有错误
- 模型不"知道自己不知道"
**主流缓解方案**：**RAG（检索增强生成）**，先检索权威资料再让 LLM 基于资料回答。
→ 详见 [幻觉](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/03-LLM%E5%9B%9B%E5%A4%A7%E7%89%B9%E7%82%B9.md#%EF%B8%8F-%E7%89%B9%E7%82%B9-4%E6%8C%A5%E4%B9%8B%E4%B8%8D%E5%8E%BB%E7%9A%84%E5%B9%BB%E8%A7%89hallucination)

**6.** 三阶段：
- **Pretrain**：海量无监督文本 + CLM 任务，**赋予能力**（学知识）
- **SFT**：指令-回复对 + 监督微调，**激发能力**（学会听人话）
- **RLHF**：偏好对 + 强化学习，**对齐能力**（懂人心，符合价值观）
→ 详见 [04-训练三阶段全景](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/04-%E8%AE%AD%E7%BB%83%E4%B8%89%E9%98%B6%E6%AE%B5%E5%85%A8%E6%99%AF.md)

**7.** Scaling Law（OpenAI）：`C ≈ 6ND`，最佳 `D ≈ 1.7N`。Chinchilla（DeepMind）：最佳 `D ≈ 20N`（数据要更多）。
**LLaMA-1 7B 用 1T token = 140× 参数**，远超 Chinchilla 的 20×，所以才能用 7B 干翻 175B 的 GPT-3（GPT-3 只训了 ~1.7× 比例的数据）。
→ 详见 [Scaling Law](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/05-Pretrain%E9%A2%84%E8%AE%AD%E7%BB%83.md#-scaling-law%E5%8F%82%E6%95%B0%E5%92%8C%E6%95%B0%E6%8D%AE%E6%80%8E%E4%B9%88%E9%85%8D)

**8.** ZeRO 三级：
- **ZeRO-1**：只切分**优化器状态**
- **ZeRO-2**：再切**梯度**
- **ZeRO-3**：再切**模型参数**
**显存与通信权衡**：ZeRO-3 切的最彻底，每张卡显存最省，但每次计算都要从其他卡通信获取参数 → 通信开销最大、GPU 利用率最低。
→ 详见 [ZeRO](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/05-Pretrain%E9%A2%84%E8%AE%AD%E7%BB%83.md#-zero-%E4%B8%8E-deepspeed)

**9.** **不是**。SFT 训练时，模型预测的是 `input + output` 的拼接，但**只对 output 部分计算 loss**，input 部分 mask 掉。
**原因**：input 是用户给的指令，不需要模型"学会生成指令"；模型只需要学会"看到这个指令该如何回复"。
→ 详见 [SFT 原理](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/06-SFT%E6%9C%89%E7%9B%91%E7%9D%A3%E5%BE%AE%E8%B0%83.md#-sft-%E8%AE%AD%E7%BB%83%E5%8E%9F%E7%90%86%E4%BB%8D%E7%84%B6%E6%98%AF-clm)

**10.** 方式 3 之所以最优，是因为 [掩码自注意力](../02-%E7%AC%AC2%E7%AB%A0-Transformer%E6%9E%B6%E6%9E%84/04-%E6%8E%A9%E7%A0%81%E8%87%AA%E6%B3%A8%E6%84%8F%E5%8A%9B.md) 的特性：每个位置只能看到前面。
- 所以 completion_2 的预测只依赖前面（prompt_1, completion_1, prompt_2），后面的 completion_3 **不会污染** completion_2 的预测
- 一次 forward 就能算多轮 loss，**等价于分轮算 + 无信息浪费 + 无计算重复**
→ 详见 [多轮对话](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/06-SFT%E6%9C%89%E7%9B%91%E7%9D%A3%E5%BE%AE%E8%B0%83.md#-%E5%A4%9A%E8%BD%AE%E5%AF%B9%E8%AF%9D%E6%80%8E%E4%B9%88%E8%AE%AD)

**11.** PPO 4 个模型：
- **Actor**（更新）：当前训练的 LLM
- **Ref**（冻结）：SFT 模型副本，作为对照防止偏移
- **Reward**（冻结）：RM，给生成的回复打分
- **Critic**（更新）：估计累积奖励
**Ref 和 Reward 必须冻结**：作为"锚点"防止 Actor 为了刷分而**钻 RM 漏洞**（reward hacking）或**丢失 Pretrain/SFT 学到的能力**。
→ 详见 [PPO](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/07-RLHF%E4%BA%BA%E7%B1%BB%E5%8F%8D%E9%A6%88%E5%BC%BA%E5%8C%96%E5%AD%A6%E4%B9%A0.md#-%E7%AC%AC%E2%91%A1%E6%AD%A5ppoproximal-policy-optimization%E8%BF%91%E7%AB%AF%E7%AD%96%E7%95%A5%E4%BC%98%E5%8C%96)

**12.** DPO 的优势：
- 只需要 **2 个模型**（Actor + Ref），而不是 4 个 → 显存大幅降低
- 训练复杂度低（就是个监督学习），不需要 RL 调参
- 工程门槛低，单机 8 卡能跑
**DPO 无需 RM 的原理**：作者通过数学推导证明，"约束奖励最大化"问题可以转化为"单阶段策略训练"问题 —— 利用奖励函数和最优策略间的映射关系，**直接从偏好数据学策略**，不需要显式训练 RM。
→ 详见 [DPO](../04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/07-RLHF%E4%BA%BA%E7%B1%BB%E5%8F%8D%E9%A6%88%E5%BC%BA%E5%8C%96%E5%AD%A6%E4%B9%A0.md#-dpodirect-preference-optimization%E4%BD%8E%E6%88%90%E6%9C%AC%E5%B9%B3%E6%9B%BF)

</details>

3. 为什么 LLaMA 的 MLP 隐藏维度计算公式有 "× 2/3" 这一步？
4. RoPE 是怎么把"绝对位置的旋转"变成"相对位置编码"的？
5. `apply_rotary_emb` 里的 4 个核心计算（`xq_out_r`、`xq_out_i` 等）对应什么数学操作？
6. 为什么 LLaMA Transformer 类要 `self.tok_embeddings.weight = self.output.weight`？省了多少参数？
7. PretrainDataset 和 SFTDataset 的 `loss_mask` 设计有什么本质区别？
8. 训练循环中为什么要用 `GradScaler`？什么时候必须用、什么时候可以不用？
9. 梯度累积的作用是什么？effective batch_size 怎么算？
10. SFT 训练相比 Pretrain 训练，代码里有哪 3 处关键差异？

12. `add_generation_prompt=True` 在 SFT 推理时起什么作用？

<details>
<summary>👉 参考答案（点开）</summary>

**1.** **GQA**（分组查询注意力）。`n_heads=16, n_kv_heads=8` 表示每 2 个 Q 头共享 1 组 K/V。好处：
- **KV cache 减半**（推理时显存大幅降低）
- **wk/wv 参数减半**
- 效果接近标准 MHA
→ 详见 [03-GQA与RoPE](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/03-GQA%E4%B8%8ERoPE.md)

**2.** 去掉了 **"减均值"** 和 **β（偏移参数）**。
原因：实验证明减均值步骤对效果几乎没贡献，真正起作用的是"归一化幅度"。去掉后：
- 计算更快（10~30%）
- 参数更少（少 β）
- 效果几乎一致
→ 详见 [为什么不减均值](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/02-RMSNorm%E4%BB%A3%E7%A0%81%E5%AE%9E%E7%8E%B0.md#-%E8%BF%9B%E9%98%B6%E4%B8%BA%E4%BB%80%E4%B9%88%E4%B8%8D%E5%87%8F%E5%9D%87%E5%80%BC%E4%B9%9F%E5%8F%AF%E4%BB%A5)

**3.** 因为 SwiGLU 比普通 FFN 多了一个 `w3` 矩阵，参数量从 `2×dim×hidden` 增加到 `3×dim×hidden`。为了**保持总参数量与普通 FFN 一致**，需要把 hidden_dim 缩小 2/3。
→ 详见 [[../05-第5章-动手搭建大模型/04-SwiGLU-MLP#关键 2：`hidden_dim` 为什么要 ×4 再 ×2/3？|为什么 × 2/3]]

**4.** RoPE 把每对维度 `(x_2i, x_2i+1)` 视为复数，按位置 `m` 旋转角度 `mθ_i`。两个位置 m 和 n 的旋转后向量做点积，由于复数乘法的性质，**结果只依赖 m-n**（相对位置差），不依赖 m 和 n 的具体值。这就是 RoPE 神奇的地方：用绝对旋转自然实现了相对编码。
→ 详见 [RoPE 原理](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/03-GQA%E4%B8%8ERoPE.md#-%E6%A8%A1%E5%9D%97-2rope%E6%97%8B%E8%BD%AC%E4%BD%8D%E7%BD%AE%E7%BC%96%E7%A0%81)

**5.** 是**二维旋转矩阵乘以复数向量**：
```
[x_r']   [cos -sin] [x_r]
[x_i'] = [sin  cos] [x_i]
```
- `xq_out_r = xq_r·cos - xq_i·sin` ← 实部
- `xq_out_i = xq_r·sin + xq_i·cos` ← 虚部
→ 详见 [RoPE 4 行核心](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/03-GQA%E4%B8%8ERoPE.md#-%E8%A7%A3%E8%AF%BB%E6%A0%B8%E5%BF%83-4-%E8%A1%8C)

**6.** 因为**词嵌入和输出层在数学上是互为转置的关系**（都是 vocab_size × dim 维度），共享权重可以节省 ~10% 参数，且效果反而更好（信息一致性）。
节省的参数：`vocab_size × dim = 6144 × 1024 ≈ 6.3M` 参数。
→ 详见 [权重共享](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/06-%E5%AE%8C%E6%95%B4LLaMA2%E6%A8%A1%E5%9E%8B.md#%E5%85%B3%E9%94%AE-1%E6%9D%83%E9%87%8D%E5%85%B1%E4%BA%ABweight-tying)

**7.** 区别：
- **PretrainDataset**：真实 token 位置 = 1，padding 位置 = 0
- **SFTDataset**：**只有 assistant 回复区间 = 1**，其他全 0（包括 user/system 部分）
本质：Pretrain 学整段文本，SFT 只学"如何回复用户"。
→ 详见 [08-数据集构造](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/08-%E6%95%B0%E6%8D%AE%E9%9B%86%E6%9E%84%E9%80%A0.md)

**8.** **GradScaler** 是 fp16 训练的关键，把 loss 放大 N 倍防止梯度下溢成 0（fp16 数值范围小）。
- **必须用**：fp16 训练
- **可以不用**：fp32 或 bf16 训练（bf16 范围与 fp32 一样，不易下溢）
→ 详见 [AMP](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/09-%E9%A2%84%E8%AE%AD%E7%BB%83%E5%BE%AA%E7%8E%AF.md#-%E6%8A%80%E5%B7%A7-1%E8%87%AA%E5%8A%A8%E6%B7%B7%E5%90%88%E7%B2%BE%E5%BA%A6amp)

**9.** 梯度累积让单卡能模拟大 batch：
- 每次 forward+backward 后**不立即更新**参数
- 累积 N 步的梯度后再 step 一次
- effective_batch = `batch_size × accumulation_steps × num_gpus`
适用：显存有限但想用大 batch 训练
→ 详见 [梯度累积](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/09-%E9%A2%84%E8%AE%AD%E7%BB%83%E5%BE%AA%E7%8E%AF.md#-%E6%8A%80%E5%B7%A7-2%E6%A2%AF%E5%BA%A6%E7%B4%AF%E7%A7%AF)

**10.** 三处差异：
- ① **加载预训练权重**：`model.load_state_dict(torch.load('pretrain.pth'), strict=False)`
- ② **用 SFTDataset 替代 PretrainDataset**
- ③ **优化器用 AdamW 替代 Adam**（带 weight decay）
其余训练循环几乎完全一样。
→ 详见 [Pretrain vs SFT](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/10-SFT%E8%AE%AD%E7%BB%83.md#-%E5%AE%8C%E6%95%B4%E5%AF%B9%E6%AF%94pretrain-vs-sft-%E4%BB%A3%E7%A0%81)

**11.** `temperature` 控制随机性：
- `temperature=0`：贪心，每次选概率最大 → 完全确定，但容易重复
- `temperature=1.5`：softmax 极度平滑 → 输出极度随机，适合创意写作但易胡言乱语
→ 详见 [采样策略](../05-%E7%AC%AC5%E7%AB%A0-%E5%8A%A8%E6%89%8B%E6%90%AD%E5%BB%BA%E5%A4%A7%E6%A8%A1%E5%9E%8B/11-%E7%94%9F%E6%88%90%E6%96%87%E6%9C%AC.md#-%E9%87%87%E6%A0%B7%E7%AD%96%E7%95%A5%E8%AF%A6%E8%A7%A3)

**12.** `add_generation_prompt=True` 会在对话模板末尾**追加 `<|im_start|>assistant\n`**，相当于提示模型"该你说了"，让模型从这里开始续写 assistant 回复。
推理必须设 True，训练（SFT）必须设 False。
→ 详见 [[../05-第5章-动手搭建大模型/11-生成文本#2. `chat_template` + `add_generation_prompt=True`|chat_template]]

</details>

## 第 6 章

→ 来自 [第 6 章总览](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

### 题目

1. HuggingFace Transformers 框架相比第 5 章的手写实现有哪些核心优势？
2. DeepSpeed ZeRO 的三个 Stage 分别切分了什么？什么场景下选 ZeRO-3？
3. SFT 训练时 `labels` 数组里把"不该算 loss 的位置"设成什么值？为什么？
4. PEFT 三大流派（Adapter / Prefix / LoRA）分别有什么核心思路？为什么 LoRA 最终成为主流？
5. LoRA 的核心数学假设是什么？请写出 LoRA 微调时的前向传播公式。
6. LoRA 初始化时为什么 A 用高斯分布、B 用全零？
7. 在 Transformer 里，LoRA 通常应用在哪些权重矩阵上？为什么不加到 FFN？
8. LoRA 的 `r` 和 `lora_alpha` 是什么关系？典型值是多少？
9. **LoRA 最致命的局限是什么？什么任务不适合用 LoRA？**
10. QLoRA 相比 LoRA 做了什么改进？为什么它能让"单卡 24G 微调 33B 模型"成为可能？

<details>
<summary>👉 参考答案（点开）</summary>

**1.** HF Transformers 的核心优势：
- **代码量减少 90%**：`AutoModel` 几行代码替代手写整个模型
- **兼容预训练权重**：可直接加载几十万个开源模型
- **Trainer 封装训练循环**：自动处理混合精度、梯度累积、分布式、checkpoint
- **生态完善**：可无缝对接 datasets、DeepSpeed、PEFT、SwanLab 等
→ 详见 [01-从手工作坊到工业流水线](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/01-%E4%BB%8E%E6%89%8B%E5%B7%A5%E4%BD%9C%E5%9D%8A%E5%88%B0%E5%B7%A5%E4%B8%9A%E6%B5%81%E6%B0%B4%E7%BA%BF.md)

**2.** ZeRO 三级：
- **ZeRO-1**：只切优化器状态（Adam 状态最大头）
- **ZeRO-2**：再切梯度
- **ZeRO-3**：再切模型参数
**选 ZeRO-3 的场景**：70B+ 超大模型，单卡显存装不下完整模型参数时（代价：速度慢，通信开销大）
→ 详见 [ZeRO Stage 选择](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/02-Trainer%E4%B8%8EDeepSpeed%E5%AE%9E%E6%88%98.md#-%E9%80%89%E5%93%AA%E4%B8%AA-zero-stage)

**3.** 设成 **`-100`**（IGNORE_TOKEN_ID）。
原因：PyTorch 的 `CrossEntropyLoss` 默认 `ignore_index=-100`，所有 labels 为 -100 的位置**不会算 loss**。这样把 system / user / padding 部分都设为 -100，只对 assistant 回复算 loss。
→ 详见 [IGNORE_TOKEN_ID](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/03-SFT%E5%AE%9E%E6%88%98%E8%A6%81%E7%82%B9.md#%E8%A6%81%E7%82%B9-1%E5%AE%9A%E4%B9%89%E7%89%B9%E6%AE%8A-token)

**4.** 三大流派：
- **Adapter**：每层插入小适配器模块（升维-激活-降维），❌ 推理延迟
- **Prefix**：输入加虚拟前缀向量，❌ 占用序列长度
- **LoRA**：在权重矩阵旁加低秩旁路 BA，✅ 零推理延迟、不占序列长度
**LoRA 胜出原因**：
- ① 零推理延迟（训完可合并到原权重）
- ② 不占序列长度
- ③ 参数高效（< 0.1%）
- ④ 与其他方法正交（可叠加 ZeRO、量化、DPO）
- ⑤ 生态完善（PEFT 库）
→ 详见 [04-高效微调三大流派](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/04-%E9%AB%98%E6%95%88%E5%BE%AE%E8%B0%83%E4%B8%89%E5%A4%A7%E6%B5%81%E6%B4%BE.md)

**5.** LoRA 核心假设：**微调时权重的变化 ΔW 是低秩的**。
基于此，LoRA 用两个小矩阵 A、B 做低秩分解 ΔW ≈ BA（其中 r << min(d, k)）。
前向传播公式：
$$h = W_0 x + B A x \cdot \frac{\alpha}{r}$$
其中 $W_0$ 冻结，只训 $A$ 和 $B$。
→ 详见 [LoRA 公式](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/05-LoRA%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md#-lora-%E6%95%B0%E5%AD%A6%E5%85%AC%E5%BC%8F)

**6.** 因为要保证**训练初始时 $\Delta W = BA = 0$**，模型行为完全等价于未加 LoRA。
- 如果 A 和 B 都零初始化：梯度恒为 0，无法训练
- 如果都随机初始化：训练一开始模型就被扰动，不稳定
- ⭐ **A 高斯 + B 零**：BA = 0 但梯度不为零，**既等价于原模型，又能训练**
→ 详见 [初始化技巧](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/06-LoRA%E4%BB%A3%E7%A0%81%E4%B8%8Epeft.md#%E5%88%9D%E5%A7%8B%E5%8C%96%E7%AD%96%E7%95%A5)

**7.** 通常应用在 **Attention 的 Q、K、V、O 四个投影矩阵**（特别是 Q 和 V 最有效）。原论文不建议加到 FFN，因为：
- FFN 参数最多，加 LoRA 后参数量会显著增加
- Attention 是模型理解任务的核心，调整这里最有效
- 实验证明 Q+V 组合效果最佳
但**现代实践中**，包含 MLP 的 `gate_proj / up_proj / down_proj` 效果会更好（参数也更多）。
→ 详见 [LoRA 应用位置](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/05-LoRA%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md#-lora-%E5%BA%94%E7%94%A8%E5%9C%A8-transformer-%E5%93%AA%E9%87%8C)

**8.** `lora_alpha` 是缩放因子的分子，实际缩放系数 `scaling = lora_alpha / r`。
- 典型值：**`r=8, alpha=16`** 或 **`r=16, alpha=32`**（保持 `alpha/r ≈ 2`）
- 改 r 时记得同步改 alpha，保持比例
→ 详见 [超参解读](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/06-LoRA%E4%BB%A3%E7%A0%81%E4%B8%8Epeft.md#-%E5%85%B3%E9%94%AE%E8%B6%85%E5%8F%82%E8%A7%A3%E8%AF%BB)

**9.** **LoRA 不适合"知识注入"任务**。
原因：
- 知识存储主要在模型权重的**高秩分量**
- LoRA 只调低秩矩阵 → 没法影响高秩分量
- 想注入大量新知识（如医学领域知识），必须**全参数继续预训练（CPT）**，LoRA 效果差
**适合的任务**：学对话风格、学输出格式、学指令遵循
**不适合的任务**：学新知识、CPT
→ 详见 [LoRA 局限](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/05-LoRA%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md#%EF%B8%8F-lora-%E7%9A%84%E5%B1%80%E9%99%90%E6%80%A7)

**10.** QLoRA = **LoRA + 4bit 量化**：
- 把基座模型权重**量化到 4bit**（用 NF4 量化方案）
- 再加 LoRA 训练（A、B 保持 bf16）
- 关键技术：4-bit NormalFloat、Double Quantization、Paged Optimizer
**显存对比**：
| 7B 模型 | 全参数 | LoRA | **QLoRA** |
| --- | --- | --- | --- |
| 显存 | ~112 GB | ~20 GB | **~7 GB** |
→ 详见 [QLoRA](../06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/05-LoRA%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md#-%E8%BF%9B%E9%98%B6qlora%E7%AA%81%E7%A0%B4%E6%80%A7%E4%BC%98%E5%8C%96)

</details>

## 第 7 章

→ 来自 [第 7 章总览](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

### 题目

1. LLM 评测的三大主流榜单是哪些？它们各自的特点是什么？
2. 评估 LLM 数学能力用什么数据集？评估代码能力用什么？
3. RAG 的"三步原理"是什么？它解决了 LLM 的哪些痛点？
4. Embedding 是什么？余弦相似度怎么算？为什么用余弦而不用欧氏距离？
5. RAG 和微调（Fine-tuning）分别解决什么问题？什么时候选哪个？
6. LLM Agent 的 5 大核心能力是什么？
7. Agent 的 4 大类型分别是什么？各自适用什么场景？
8. ReAct 框架的核心循环是什么？为什么"先思考再行动"很重要？
9. 实现 Agent 的关键技术 Function Calling 是怎么工作的？为什么需要"两次 LLM 调用"？
10. RAG、Agent、Chatbot 三者的关系是什么？为什么说三者递进？

<details>
<summary>👉 参考答案（点开）</summary>

**1.** 三大榜单：
- **Open LLM Leaderboard**（HuggingFace）：开源 LLM 综合榜，覆盖 MMLU/GSM8K 等多个 benchmark
- **Lmsys Chatbot Arena**：真实用户**盲测投票**，Elo 评分，最接近真实使用感受
- **OpenCompass**（上海 AI Lab）：国内权威，**重点关注中文场景**，100+ 评测集
→ 详见 [三大榜单](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/01-LLM%E8%AF%84%E6%B5%8B%E4%BD%93%E7%B3%BB.md#-712-%E4%B8%89%E5%A4%A7%E4%B8%BB%E6%B5%81%E6%A6%9C%E5%8D%95)

**2.** 数学：**GSM8K**（小学应用题）、**MATH**（高中竞赛题）
代码：**HumanEval**（OpenAI 出品，164 题）、**MBPP**、**LiveCodeBench**
→ 详见 [评测数据集](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/01-LLM%E8%AF%84%E6%B5%8B%E4%BD%93%E7%B3%BB.md#-711-%E4%B8%BB%E6%B5%81%E8%AF%84%E6%B5%8B%E6%95%B0%E6%8D%AE%E9%9B%86%E6%8C%89%E8%83%BD%E5%8A%9B%E5%88%86%E7%B1%BB)

**3.** RAG 三步原理：
- **① 索引（Index）**：文档切分 + Embedding 向量化 + 存入向量库
- **② 检索（Retrieval）**：根据问题，用余弦相似度找出 top-k 相关文档
- **③ 生成（Generation）**：把检索到的文档拼到 prompt，LLM 基于上下文生成
**解决的痛点**：
- **幻觉**：回答基于真实文档，可追溯
- **知识过时**：知识库可随时更新
- **缺乏领域专业知识**：领域知识库塞给 LLM，不用重训
→ 详见 [02-RAG原理深入](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/02-RAG%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md)

**4.** **Embedding**：把文本变成稠密向量（如 1024 维），**语义相近的文本向量距离近**。
**余弦相似度公式**：$\text{cos\_sim}(\vec{a},\vec{b}) = \frac{\vec{a}\cdot\vec{b}}{\|\vec{a}\|\cdot\|\vec{b}\|}$
**为什么用余弦**：只关心**方向**不关心长度，更符合"语义相似"的直觉。两个向量的"模"（长度）可能因为文本长度不同而差异大，但只要方向一致（讲同一件事），就该相似。
→ 详见 [关键概念](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/02-RAG%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md#-%E5%85%B3%E9%94%AE%E6%A6%82%E5%BF%B5%E6%B7%B1%E5%85%A5)

**5.** 区别：
- **RAG**：解决"**知识**不足"问题（让 LLM 知道更多事实）
- **微调**：解决"**风格/格式/任务能力**"问题（让 LLM 输出特定风格）
**选型**：
- 想让模型回答某专业领域问题 → RAG
- 想让模型学某角色风格、特定输出格式 → SFT/LoRA
- **二者互补**，生产中常组合使用：**微调 + RAG**
→ 详见 [RAG vs 微调](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/02-RAG%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md#-rag-vs-%E5%BE%AE%E8%B0%83fine-tuning)

**6.** Agent 5 大核心能力：
- **目标理解**（Goal Understanding）：接收复杂高层目标
- **自主规划**（Planning）：把大目标拆解成子任务
- **记忆**（Memory）：短期对话上下文 + 长期知识库
- **工具使用**（Tool Use）：调 API / 插件 / 代码
- **反思与迭代**（Reflection & Iteration）：评估自己的行为，失败时调整
→ 详见 [Agent 5 大能力](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/04-LLM-Agent%E5%8E%9F%E7%90%86.md#-731-%E4%BB%80%E4%B9%88%E6%98%AF-llm-agent)

**7.** Agent 4 大类型：
- **任务导向型**：专注特定领域、定义明确的任务（如客服、订餐机器人、GitHub Copilot）
- **规划推理型** ⭐：自主分解复杂任务、多步规划，用 ReAct / CoT 等（如研究型 Agent）
- **多 Agent 系统**：多个 Agent 协作（如 AutoGen 模拟软件开发团队）
- **探索学习型**：在交互中学习新技能（如自主探索软件的 Agent，前沿研究）
→ 详见 [4 大类型](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/04-LLM-Agent%E5%8E%9F%E7%90%86.md#-732-agent-%E5%9B%9B%E5%A4%A7%E7%B1%BB%E5%9E%8B)

**8.** ReAct 核心循环：**Thought → Action → Observation**
- **Thought**：LLM 先思考当前情况和该做什么
- **Action**：执行工具调用
- **Observation**：观察工具返回结果
- 然后回到 Thought，循环直到任务完成
**重要性**：让 LLM 的行为**可解释、可控、可调试**，避免"直接给答案"的黑盒，每一步都有清晰的推理依据。
→ 详见 [ReAct 框架](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/04-LLM-Agent%E5%8E%9F%E7%90%86.md#-%E7%B1%BB%E5%9E%8B-2%E8%A7%84%E5%88%92%E4%B8%8E%E6%8E%A8%E7%90%86%E5%9E%8Bplanning--reasoning-agents)

**9.** Function Calling 工作流程：
1. 把工具函数转成 JSON Schema 描述（含函数名、参数、用途）
2. **第 1 次 LLM 调用**：把用户问题 + 工具列表给 LLM，LLM 决定要不要调工具，返回 `tool_calls`
3. 执行被调用的工具，得到结果
4. **第 2 次 LLM 调用**：把工具结果加进 messages，让 LLM 生成最终回答
**为什么两次**：第 1 次 LLM 决策"调什么工具"，第 2 次 LLM "用工具结果说人话"。把"决策"和"表达"分离。
→ 详见 [两次 LLM 调用](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/05-Tiny-Agent%E5%AE%9E%E6%88%98%E9%80%9F%E8%A7%88.md#-%E6%A0%B8%E5%BF%83%E7%90%86%E8%A7%A3%E4%B8%A4%E6%AC%A1-llm-%E8%B0%83%E7%94%A8)

**10.** **Chatbot ⊂ RAG ⊂ Agent**（递进关系）：
- **Chatbot**：只会对话（凭训练知识答题）
- **RAG = Chatbot + 检索能力**：会查资料后再答
- **Agent = RAG + 工具 + 规划 + 反思**：能办事
为什么递进：每一层都比上一层多了**主动行为能力**。Chatbot 被动响应，RAG 主动查资料，Agent 主动规划执行。
→ 详见 [三者对比](../07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/04-LLM-Agent%E5%8E%9F%E7%90%86.md#-%E5%8A%A0%E6%B7%B1%E7%90%86%E8%A7%A3agent-vs-chatbot-vs-rag)

</details>
