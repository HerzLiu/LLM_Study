# RL 任务与验证器数据

⬅ [03-SFT轨迹数据](03-SFT%E8%BD%A8%E8%BF%B9%E6%95%B0%E6%8D%AE.md) | ➡ [01-Pre-train](../03-%E8%AE%AD%E7%BB%83%E9%98%B6%E6%AE%B5/01-Pre-train.md)

## 目标

给模型一个可执行环境，让它自己 rollout 轨迹，并用验证器把结果转成 reward。

## 数据形态

RL 数据不含答案轨迹：

```json
{
  "problem_statement": "修复 requests 库 timeout=0 永久阻塞的 bug",
  "repo": "psf/requests",
  "base_commit": "abc123",
  "FAIL_TO_PASS": ["test_timeout_zero"],
  "PASS_TO_PASS": ["test_normal_request"],
  "docker_image": "requests-env:latest"
}
```

## 验证器类型

| 任务域 | 验证器 |
|---|---|
| SWE 修 bug | FAIL_TO_PASS + PASS_TO_PASS 测试 |
| 代码理解 | 路径、符号、答案精确匹配 |
| Terminal | 检查文件、stdout、进程、退出码 |
| WebCoding | 浏览器渲染 + 规则/视觉评分 |
| 代码补全 | hidden unit tests |

## 任务筛选

RL 任务要保留有区分度的样本：

- 全对：太简单，几乎没有梯度价值。
- 全错：太难，reward 太稀疏。
- 30% 到 70% pass 率：更适合训练。
