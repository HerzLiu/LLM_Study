# 术语表

⬅ [02-GRPO与长轨迹稳定性](../05-Reward%E4%B8%8E%E7%A8%B3%E5%AE%9A%E6%80%A7/02-GRPO%E4%B8%8E%E9%95%BF%E8%BD%A8%E8%BF%B9%E7%A8%B3%E5%AE%9A%E6%80%A7.md) | ➡ [跨库索引](%E8%B7%A8%E5%BA%93%E7%B4%A2%E5%BC%95.md)

| 术语 | 解释 |
|---|---|
| Code LLM | 擅长代码生成、补全、解释的语言模型 |
| Code Agent | 能使用工具在仓库中完成软件工程任务的 agent |
| Coder Model | 被训练成适合 Code Agent 闭环的模型 policy |
| FIM | Fill-in-the-Middle，让模型根据前后文补中间代码 |
| Repo-level 训练 | 多文件按依赖顺序拼接，让模型学习跨文件关系 |
| Mid-train | 预训练后、SFT 前的继续预训练 / 退火阶段 |
| Trajectory | agent 多轮行动、观察、patch、测试结果组成的轨迹 |
| Scaffold | agent loop 和工具协议框架 |
| Sandbox | 隔离执行代码和测试的环境 |
| Proxy | 拦截 scaffold LLM 请求并转发到 rollout 模型的代理层 |
| F2P | FAIL_TO_PASS，修复后应该从失败变通过的测试 |
| P2P | PASS_TO_PASS，修复后必须保持通过的回归测试 |
| RLVR | Reinforcement Learning with Verifiable Rewards |
| GRPO | Group Relative Policy Optimization，组内相对优势优化 |
| Reward hacking | 模型利用 reward 漏洞拿高分但没有真正完成任务 |
