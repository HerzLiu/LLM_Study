# 1.3 训练集 / 验证集 / 测试集

⬅ [02-监督-无监督-强化学习三大范式](02-%E7%9B%91%E7%9D%A3-%E6%97%A0%E7%9B%91%E7%9D%A3-%E5%BC%BA%E5%8C%96%E5%AD%A6%E4%B9%A0%E4%B8%89%E5%A4%A7%E8%8C%83%E5%BC%8F.md) | ➡ [04-过拟合欠拟合与正则化](04-%E8%BF%87%E6%8B%9F%E5%90%88%E6%AC%A0%E6%8B%9F%E5%90%88%E4%B8%8E%E6%AD%A3%E5%88%99%E5%8C%96.md)

---

## 🎬 故事比喻：学生备考三阶段

```
你备考 GRE：

  训练集 (train set) = 你天天刷的习题册
                      ─ 反复做、看答案
                      ─ "学"用的

  验证集 (validation set / dev set) = 模拟考
                      ─ 不告诉你答案
                      ─ 看你水平怎么样、调整复习策略
                      ─ "调参"用的

  测试集 (test set) = 真考试
                      ─ 只能看一次
                      ─ 决定你的真实水平
                      ─ "汇报"用的

如果用真考试题反复刷 → 高分但不代表真水平（作弊）
所以三套必须严格分开。
```

> 这一节解释为什么 ML 必须分 train/val/test，以及为什么 SWE-bench 必须有 Verified 子集（agentic-rl §4.5）。

---

## 📐 1.3.1 三集的作用

| 集合                       | 比例（典型） | 干什么                                    | 谁能看        |
| ------------------------ | ------ | -------------------------------------- | ---------- |
| **训练集** train            | 70-80% | 模型用这个**更新参数**（gradient descent）        | 模型一直看      |
| **验证集** validation / dev | 10-15% | **调超参**（lr, dropout, 模型大小）+ early stop | 人看 + 模型间接看 |
| **测试集** test             | 10-15% | **最终评估**模型，**不能用来调参**                  | **只能看一次**  |

**严格原则**：

> **训练集和测试集必须不相交**。
> **测试集用过就"消耗"了**——之后用同样模型架构再训，结果可能没意义。

---

## 🆚 1.3.2 为什么 train ≠ test？

**反例**：你用考试原题训练，考试肯定满分。但**真考新题**时崩。

**ML 里同理**：

```
错误做法（无 test set）:
  在所有 100 个样本上训练 → 在所有 100 个样本上评估 → 准确率 99%

  问题: 模型可能"记住了"每个样本，但**没真学会泛化**
        给个新样本（第 101 个）→ 可能完全错

正确做法:
  在 80 个样本上训练 → 在剩 20 个**没见过**的样本上评估 → 真实准确率
```

→ **测试集 = 模拟"未来真实数据"的代理**。

---

## 🤔 1.3.3 为什么还要 validation set？

**反例**：只用 train + test：

```
1. 用 train 训模型
2. 在 test 上评 → accuracy 85%
3. 觉得不够好，调超参（lr 改成 1e-4）
4. 重训 + 评 test → 87%
5. 再调（加 Dropout）+ 评 test → 89%
6. ... 调 100 次 → test acc 95%

问题: 你**间接用 test set 调超参**了！
      → 模型隐式 overfit 到 test set
      → 真上线还是会崩
```

**正确做法**：

```
1. 用 train 训
2. 在 val 上评 → 调超参
3. 反复迭代直到 val 满意
4. **最后**用 test 评一次，作为最终汇报
   ↑
   test 全程没碰过
```

→ **val 是"中间反馈"，test 是"最终裁判"**。

---

## 📊 1.3.4 经典划分比例

| 数据规模 | 典型划分 |
|---|---|
| **小数据**（< 10K） | 60 / 20 / 20 |
| **中等**（10K - 1M） | 80 / 10 / 10 |
| **大数据**（> 1M） | 98 / 1 / 1（val/test 不需要太多，1% 就够） |
| **超大数据**（LLM 预训练） | 99.9 / 0.05 / 0.05 |

→ **数据越多，val/test 比例可越小**——绝对数量够就行。

---

## 🔄 1.3.5 K 折交叉验证（K-fold Cross Validation）

**适用**：数据少，分一次 val 不稳。

**做法**：

```
把 train 切成 K 份（K 常 5 或 10）：

第 1 轮: [val][train][train][train][train] → val acc_1
第 2 轮: [train][val][train][train][train] → val acc_2
第 3 轮: [train][train][val][train][train] → val acc_3
第 4 轮: [train][train][train][val][train] → val acc_4
第 5 轮: [train][train][train][train][val] → val acc_5

最终 val acc = mean(acc_1..5)
```

**优势**：评估更稳定（不被单次划分运气影响）
**代价**：训练 K 次 → **K 倍时间**

**用在哪**：
- ✅ 传统 ML（少量数据）
- ❌ DL **几乎不用**（训一次都几小时-几天，跑 K 次太贵）

---

## ⚠️ 1.3.6 数据泄漏（Data Leakage）❗ 最常见的坑

**症状**：训出来 val acc 99%，部署到生产 acc 50%。
**原因**：训练集里**偷偷混了**测试信息。

### 常见泄漏模式

| 模式          | 例子                                                           |
| ----------- | ------------------------------------------------------------ |
| **直接混入**    | val 样本不小心进了 train                                            |
| **时间穿越**    | 用未来数据预测过去（股票场景常见）                                            |
| **统计量泄漏**   | 在**全数据**上算 normalize（均值方差），然后 split → val/test 的统计量泄到了 train |
| **特征泄漏**    | 特征本身含目标信息（如"是否还款" 特征里包含"已还款金额"）                              |
| **重复数据**    | 同一条记录出现在 train 和 val                                         |
| **预训练数据污染** | LLM 预训练数据包含了 benchmark 测试集（SWE-bench / GSM8K 都被污染过）          |

### 防泄漏检查

```python
# 1. 严格 split 之后才做特征工程
train, val = split(data, test_size=0.2)
mean, std = train.mean(), train.std()         # ← 只用 train 算
train_norm = (train - mean) / std
val_norm = (val - mean) / std                  # ← val 用 train 的统计量

# 2. 时间序列: 严格按时间 split
# WRONG: random_split → 用未来训预测过去
# RIGHT: 按日期 split → train=2024 之前，test=2024 之后

# 3. 检查重复
assert len(set(train_ids) & set(val_ids)) == 0
```

→ 详细 LLM benchmark 污染问题见 [§4.8 B Benchmark Overfitting](../../agentic-rl-knowledge-base/04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/08-Reward-Hacking%E4%B8%8ESandbox%E5%AE%89%E5%85%A8.md)。

## 🆚 1.3.7 在 LLM 里对应什么

| ML 概念 | LLM 训练里对应                                           |
| ----- | --------------------------------------------------- |
| 训练集   | Pretrain 语料 / SFT 数据 / 偏好对                          |
| 验证集   | dev set，监控 train loss/val loss                      |
| 测试集   | **SWE-bench Verified / MMLU / GSM8K** 等公开 benchmark |
| 数据泄漏  | **LLM 预训练数据可能包含 benchmark** → 报告分数虚高                |
| 时间切分  | **LiveCodeBench** 用日期切，防 LLM 预训练污染                  |

→ 详见 [§4.6 LiveCodeBench](../../agentic-rl-knowledge-base/04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/06-%E5%BC%BA%E6%8E%A8%2B%E5%8F%AF%E9%80%89%E8%AE%BA%E6%96%87%E7%B4%A2%E5%BC%95%EF%BC%88SWE-Gym-SWE-RL%E7%AD%89%EF%BC%89.md)。

## 📌 1.3 节要点

| 集合 | 用途 | 看几次 |
|---|---|---|
| **train** | 训参数 | 无数次 |
| **val** | 调超参 + early stop | 多次 |
| **test** | 最终汇报 | **1 次** |

**3 个铁律**：

1. **train ∩ test = ∅**（严格不相交）
2. **任何 normalize / 特征工程必须在 split 之后**
3. **不用 test set 调任何东西**——否则它就成了 val
