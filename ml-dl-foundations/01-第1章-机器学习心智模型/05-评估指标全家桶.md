# 1.5 评估指标全家桶

⬅ [04-过拟合欠拟合与正则化](04-%E8%BF%87%E6%8B%9F%E5%90%88%E6%AC%A0%E6%8B%9F%E5%90%88%E4%B8%8E%E6%AD%A3%E5%88%99%E5%8C%96.md) | ➡ [00-章节总览](../02-%E7%AC%AC2%E7%AB%A0-%E6%95%B0%E5%AD%A6%E6%9C%80%E5%B0%8F%E5%BF%85%E8%A6%81%E5%9F%BA%E7%A1%80/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

## 🎬 故事比喻：一份模型的"成绩单"

```
模型考完试要看分数。
不同任务用不同评分标准：

  分类任务: accuracy / precision / recall / F1
  回归任务: MSE / MAE / R²
  排序任务: AUC / MRR / NDCG
  生成任务: BLEU / ROUGE / Perplexity
  代码任务: pass@k / resolved_rate ← 你已学过
  RL 任务:  累积 reward / success rate
```

> 这一节给你一张评估指标速查表。**Loss 是训练用的（要可微），指标是评估用的（要直观）**——两个概念。

---

## ⚠️ 1.5.1 Loss vs 指标 的区别

| | Loss | 评估指标 |
|---|---|---|
| 用途 | 训练（梯度下降） | 评估（汇报结果） |
| 必须可微？ | **✅ 必须** | ❌ 不需要 |
| 例子 | CE / MSE | Accuracy / F1 / BLEU |
| 谁看 | 模型（更新参数） | 人（决定 deploy） |

→ 这就是为什么分类任务**训练用 CE loss，评估用 accuracy**——CE 可导能训，accuracy 直观但不可导。

---

## 🎯 1.5.2 分类指标（最常见）

### 混淆矩阵（二分类）

|  | 预测=1 (Positive) | 预测=0 (Negative) |
|---|---|---|
| **真实=1** | **TP** (True Positive) | **FN** (False Negative) |
| **真实=0** | **FP** (False Positive) | **TN** (True Negative) |

### 4 个核心指标

**Accuracy（准确率）**：

$$\text{Acc} = \frac{TP + TN}{TP + TN + FP + FN}$$

"答对的比例"。问题：**不平衡数据下骗人**（99% 负样本，全猜 0 也 99%）。

**Precision（精确率）**：

$$\text{Precision} = \frac{TP}{TP + FP}$$

"预测为正的，有多少真的正"。**反 FP**。

**Recall（召回率）**：

$$\text{Recall} = \frac{TP}{TP + FN}$$

"真正的正样本，找到了多少"。**反 FN**。

**F1**：

$$F_1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$$

Precision 和 Recall 的**调和平均**。两者都高才高。

### 数值小例子

100 条邮件，10 条垃圾，90 条正常。模型预测：

|  | 预测 = 垃圾 | 预测 = 正常 |
|---|---|---|
| 真实 = 垃圾 | TP = 8 | FN = 2 |
| 真实 = 正常 | FP = 5 | TN = 85 |

| 指标 | 计算 | 值 |
|---|---|---|
| Accuracy | (8+85)/100 | 0.93 |
| Precision | 8/(8+5) | 0.62 |
| Recall | 8/(8+2) | 0.80 |
| F1 | 2·0.62·0.80/(0.62+0.80) | 0.70 |

→ Accuracy 高但 Precision 低——**很多被标"垃圾"的其实正常**。

### 应用：哪种场景看哪个

| 场景 | 看哪个 | 为什么 |
|---|---|---|
| 垃圾邮件检测 | **Precision** | 错杀正常邮件代价大 |
| 疾病筛查 | **Recall** | 漏掉病人代价大 |
| 综合考量 | **F1** | 平衡 |
| 类别均衡 | **Accuracy** | 直观 |

## 📊 1.5.3 ROC / AUC（按 threshold 评估）

模型输出**概率** $\hat{p}$，传统 threshold = 0.5 划界。但 threshold 可以调。

**ROC 曲线**：横轴 FPR，纵轴 TPR（不同 threshold 下两者的关系）。

**AUC**（Area Under Curve）：ROC 曲线下面积。**值在 [0, 1]，越大越好**。

| AUC | 含义 |
|---|---|
| 0.5 | 随机猜 |
| 0.7-0.8 | 还行 |
| 0.8-0.9 | 不错 |
| 0.9+ | 很好 |
| 1.0 | 完美（罕见，可能数据泄漏） |

**优势**：和 threshold 无关，整体看模型排序能力。

**用在哪**：
- ✅ 二分类（特别是不均衡数据）
- ✅ 推荐系统、CTR 预测

---

## 📈 1.5.4 回归指标

| 指标 | 公式 | 特点 |
|---|---|---|
| **MSE** | $\frac{1}{N}\sum (\hat{y} - y)^2$ | 重罚大误差 |
| **RMSE** | $\sqrt{\text{MSE}}$ | 单位和 y 一致 |
| **MAE** | $\frac{1}{N}\sum \lvert \hat{y} - y \rvert$ | 不重罚 outlier |
| **R²** | $1 - \frac{\sum(\hat{y}-y)^2}{\sum(y-\bar{y})^2}$ | 0=瞎猜, 1=完美 |

## 📝 1.5.5 生成任务指标（NLP）

### Perplexity（困惑度）⭐ LLM 评估首选

$$\text{PPL}(y) = \exp\left(-\frac{1}{T}\sum_{t=1}^{T} \log p(y_t \mid y_{<t})\right) = \exp(\text{avg NLL})$$

**直觉**：模型在每个位置"平均有多少候选"——**越低越好**。

| PPL   | 含义                 |
| ----- | ------------------ |
| 1     | 完美（模型完全确定下一 token） |
| 10    | "平均 10 个候选"        |
| 100   | "平均 100 个候选"       |
| 10000 | 几乎随机               |

**例子**：
- GPT-3 在 WikiText 上 PPL ≈ 20-30
- 训练失败 / 随机初始化的模型 PPL > 10000

→ 详见 [05-Pretrain预训练](../../Happy-LLM/04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/05-Pretrain%E9%A2%84%E8%AE%AD%E7%BB%83.md)。

### BLEU / ROUGE（翻译/摘要）

- **BLEU**：n-gram 重叠比例（机器翻译）
- **ROUGE**：n-gram 召回（摘要）

**问题**：不懂语义。"今天好热" 和 "今天非常热" BLEU 差很多但语义同。

→ 现代 LLM 评估更倾向用 **LLM-as-judge**（GPT-4 当评委）。

## 💻 1.5.6 代码任务指标（你已学过）

### Pass@k

$$\text{pass@}k = \mathbb{E}_{\text{tasks}}\left[1 - \frac{\binom{n - c}{k}}{\binom{n}{k}}\right]$$

**直觉**：sample n 个候选里至少有 1 个对的概率。

→ 详见 [agentic-rl §4.8 B.3](../../agentic-rl-knowledge-base/04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/08-Reward-Hacking%E4%B8%8ESandbox%E5%AE%89%E5%85%A8.md#b3-%E5%85%B3%E9%94%AE%E8%AF%84%E6%B5%8B%E6%8C%87%E6%A0%87%E7%9A%84%E7%B2%BE%E7%A1%AE%E6%95%B0%E5%AD%A6%E5%AE%9A%E4%B9%89)。

### Resolved Rate（SWE-bench）

$$\text{resolved\_rate} = \frac{1}{N}\sum_i \mathbb{1}[\text{F2P all pass} \land \text{P2P all pass}]$$

→ 详见 [同上](../../agentic-rl-knowledge-base/04-%E7%AC%AC4%E7%AB%A0-Code-Agentic-RL%E4%B8%93%E9%A2%98/08-Reward-Hacking%E4%B8%8ESandbox%E5%AE%89%E5%85%A8.md#b3-%E5%85%B3%E9%94%AE%E8%AF%84%E6%B5%8B%E6%8C%87%E6%A0%87%E7%9A%84%E7%B2%BE%E7%A1%AE%E6%95%B0%E5%AD%A6%E5%AE%9A%E4%B9%89)。

## 🎮 1.5.7 RL 指标

| 指标 | 含义 |
|---|---|
| **Cumulative Reward** $G$ | $\sum_t \gamma^t r_t$，一个 episode 总奖励 |
| **Success Rate** | 完成任务的比例 |
| **Sample Efficiency** | 多少 episode 能达到某成功率 |
| **OOD Performance** | 训练外任务表现（防 reward hacking 关键） |

→ 详见 [01-MDP与轨迹（用Agent语言讲RL）](../../agentic-rl-knowledge-base/01-%E7%AC%AC1%E7%AB%A0-RL%E6%9C%80%E5%B0%8F%E5%BF%85%E8%A6%81%E5%9F%BA%E7%A1%80/01-MDP%E4%B8%8E%E8%BD%A8%E8%BF%B9%EF%BC%88%E7%94%A8Agent%E8%AF%AD%E8%A8%80%E8%AE%B2RL%EF%BC%89.md)。

## 📊 1.5.8 全家速查表

| 任务 | 训练 loss | 评估指标 |
|---|---|---|
| 二分类 | BCE | Accuracy / Precision / Recall / F1 / AUC |
| 多分类 | CE | Accuracy / per-class F1 |
| 回归 | MSE | RMSE / MAE / R² |
| 排序 | Pairwise BCE / InfoNCE | NDCG / MRR / MAP / AUC |
| **LLM 预训练** | **CE (next-token)** | **Perplexity** |
| LLM SFT | CE (assistant only) | Eval set loss / 人工评估 / LLM-as-judge |
| 翻译/摘要 | CE | BLEU / ROUGE / LLM-as-judge |
| 代码生成 | CE | **pass@k** |
| 代码 Agent | RLVR reward | **resolved_rate** |
| RL | $\sum \gamma^t r_t$ | Cumulative reward / Success rate |

## ⚠️ 1.5.9 常见误解

| 误解 | 真相 |
|---|---|
| "Accuracy 越高越好" | 不均衡数据上**会骗人**（99% 负，全猜 0 也 99%） |
| "Loss 低 = 准确率高" | **不一定**——loss 数值和指标无线性关系 |
| "F1 一定比 Accuracy 好" | 看场景。均衡数据 Accuracy 就够 |
| "Perplexity 越低越好" | 是，**但** 训练集 PPL 极低可能 overfit |
| "pass@1 = accuracy" | 几乎，但 pass@k 是**多次采样**的无偏估计 |
| "AUC 1.0 太好了" | **小心数据泄漏**——真任务 AUC 1.0 极罕见 |
| "用 LLM 当评委一定好" | LLM-as-judge 有**位置偏差/长度偏差**等问题 |

---

## 📌 1.5 节要点

| 任务 | 主要指标 |
|---|---|
| 分类 | F1（不均衡）/ Accuracy（均衡） |
| 回归 | RMSE / MAE |
| LLM 预训练 | **Perplexity** |
| LLM 微调 / 对话 | LLM-as-judge / 人工评估 |
| 代码生成 | **pass@k** |
| 代码 Agent | **resolved_rate** |
| RL | 累积 reward + success rate |

**最重要的 2 件事**：
1. **Loss 训练用，指标评估用** —— 两者不同
2. **看任务选指标** —— 不均衡数据别看 accuracy
