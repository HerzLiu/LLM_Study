# 6.2 混合精度训练 fp16 / bf16

⬅ [01-超参数调优体系](01-%E8%B6%85%E5%8F%82%E6%95%B0%E8%B0%83%E4%BC%98%E4%BD%93%E7%B3%BB.md) | ➡ [03-分布式与显存优化](03-%E5%88%86%E5%B8%83%E5%BC%8F%E4%B8%8E%E6%98%BE%E5%AD%98%E4%BC%98%E5%8C%96.md)

---

## 🎬 故事比喻：用小数尺子省纸

```
你做工程图纸:
  - 用 32 位小数（fp32）: 精确到 0.0000001m，纸张占满
  - 用 16 位小数（fp16）: 精确到 0.01m，纸张省一半，速度快

DL 训练:
  - 用 fp32: 精确但占显存 + 算得慢
  - 用 fp16: 省一半显存 + GPU 算得快 2-4 倍
  - 但 fp16 精度不够，loss 容易溢出 → AMP（混合精度）解决
```

> 这一节解释 Happy-LLM 训练代码里 `scaler = GradScaler()` 在做什么。

---

## 📐 6.2.1 浮点数精度速查

| 精度 | 位数 | 数值范围 | 精度 | 显存 |
|---|---|---|---|---|
| **fp32** | 32 位（1 + 8 + 23）| ±3.4e38 | 高 | **4 字节/数** |
| **fp16** | 16 位（1 + 5 + 10）| ±6.5e4 | 中 | **2 字节/数** ⭐ 省一半 |
| **bf16** | 16 位（1 + 8 + 7）| ±3.4e38 | **比 fp16 低** | 2 字节/数 |
| **int8** | 8 位 | -128 ~ 127 | 极低 | 1 字节/数 |
| **fp4** | 4 位 | ... | 极低 | 0.5 字节/数 |

**fp16 vs bf16**：

- **fp16**：精度高，范围小（±65504）→ 容易溢出
- **bf16**：精度低，**范围和 fp32 一样**（关键！）→ 不易溢出

→ 现代 LLM 训练**几乎全用 bf16**（A100/H100 原生支持）。

---

## 🚨 6.2.2 fp16 的核心问题：数值溢出

**问题**：fp16 最大表示 ±65504。

```
两个大数相乘 (3 万 × 3 万 = 9 亿) 
→ fp16 表示不了 → inf → NaN
```

**训练时常见**：

- Loss 累加变 inf
- 梯度乘 lr 后下溢成 0
- 模型权重 inf / NaN

→ 这就是为什么 fp16 训练**没那么好用**。

---

## 🛡 6.2.3 GradScaler（fp16 的关键救星）

**思路**：算 loss 后**放大 N 倍**，反向传播后**缩回去**——避免梯度下溢成 0。

```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()

for batch in dataloader:
    optimizer.zero_grad()
    with autocast():                          # fp16 前向
        output = model(batch)
        loss = loss_fn(output, target)

    scaler.scale(loss).backward()             # 放大 loss 反向
    scaler.step(optimizer)                    # 缩回，更新
    scaler.update()                           # 动态调整 scale
```

→ 这就是 Happy-LLM `scaler.scale(loss).backward()` 的来由。

---

## ⭐ 6.2.4 bf16（现代 LLM 的选择）

**bf16 范围 = fp32 范围**（指数位 8 位，和 fp32 一样）：

```
fp32:  S | EEEEEEEE | MMMMMMMMMMMMMMMMMMMMMMM  (1+8+23)
bf16:  S | EEEEEEEE | MMMMMMM                  (1+8+7)
fp16:  S | EEEEE    | MMMMMMMMMM               (1+5+10)
```

**对比**：

| 维度 | fp16 | bf16 |
|---|---|---|
| 范围 | ±65504 | ±3.4e38（=fp32） |
| 精度 | 高（10 位尾数） | 低（7 位尾数） |
| 易溢出？ | **是** | **几乎不会** |
| 需要 GradScaler？ | **是** | **不需要** |
| 硬件支持 | V100+ | A100+, H100, TPU |

→ 现代 GPU 都支持 bf16，**直接用 bf16 比 fp16 + GradScaler 简单**。

---

## 💻 6.2.5 PyTorch AMP 代码

### fp16（带 GradScaler，老办法）

```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()
for batch in dataloader:
    optimizer.zero_grad()
    with autocast(dtype=torch.float16):
        output = model(batch)
        loss = loss_fn(output, target)
    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()
```

### bf16（推荐，A100+）

```python
for batch in dataloader:
    optimizer.zero_grad()
    with autocast(dtype=torch.bfloat16):
        output = model(batch)
        loss = loss_fn(output, target)
    loss.backward()                  # ← 不需要 scaler
    optimizer.step()
```

### Hugging Face Trainer

```python
training_args = TrainingArguments(
    bf16=True,      # 用 bf16
    # 或 fp16=True,  # 用 fp16 (Trainer 自动处理 scaler)
)
```

## 🎯 6.2.6 混合精度怎么"混"？

不是所有计算都 fp16/bf16。**关键操作仍用 fp32**：

| 操作 | 精度 | 为什么 |
|---|---|---|
| Forward（大多数） | fp16/bf16 | 快、省 |
| Backward（梯度） | fp16/bf16 | 快、省 |
| **Loss 累加** | **fp32** | 累加多次易溢出 |
| **Softmax** | **fp32** | 数值稳定 |
| **LayerNorm** | **fp32** | 同上 |
| 优化器状态（Adam m, v） | **fp32** | 精度要求高 |
| Master weights | **fp32** | 防累计误差 |

→ AMP 自动判断哪些操作用 fp32。

---

## 📊 6.2.7 收益对比

训练 LLaMA-7B 同样数据：

| 配置 | 训练时间 | 显存 |
|---|---|---|
| fp32 | 10h | 80 GB → OOM |
| **fp16 + AMP** | **4-5h** | 40 GB |
| **bf16** | **4-5h** | 40 GB |

→ 混合精度**节省 50% 显存 + 加速 2 倍**。**LLM 训练必用**。

---

## ⚠️ 6.2.8 常见误解

| 误解 | 真相 |
|---|---|
| "fp16 比 fp32 不准" | 是。但 AMP/bf16 实际效果几乎一样 |
| "bf16 没 GradScaler 是不是不稳" | **不需要**——bf16 范围足够大 |
| "全 fp16 就行" | **不！** 必须混合，否则关键操作崩 |
| "AMP 一定快 2 倍" | 不一定，看模型 / 数据加载瓶颈 |
| "可以同时用 fp16 + bf16" | **不能**——选一个 |
| "推理也用 GradScaler" | **不**——推理无梯度 |

---

## 📌 6.2 节要点

| 选择 | 用 |
|---|---|
| **A100 / H100 / TPU** | **bf16**（推荐） |
| 老 GPU（V100, T4, RTX） | fp16 + GradScaler |
| 训练崩 / 精度敏感 | fp32（默认） |

**3 个关键事实**：

1. **bf16 范围 = fp32 范围**，**精度比 fp16 低**
2. **fp16 易溢出**，必须配 GradScaler
3. **AMP 自动管理"哪些操作用哪个精度"**
