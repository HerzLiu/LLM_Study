## 🚨 6.5.1 症状快速索引

| 症状 | 跳转 |
|---|---|
| Loss 立刻 NaN | §6.5.2 |

---

## 💀 6.5.2 Loss 立刻 NaN

**可能原因**（按概率）：

| 原因 | 验证 | 修复 |
|---|---|---|
| 数据含 NaN | `torch.isnan(x).any()` | 清洗数据 |
| lr 太大 | 看 lr 配置 | lr 减 10 倍 |
| 初始化太大 | 看权重 std | 用 `nn.init.normal_(std=0.02)` |
| log(0) | 看 loss 公式 | 加 `+ 1e-8` |
| 除以 0 | 看 attention scale | 检查 `1/sqrt(d_k)` |
| fp16 溢出 | 训练用 fp16？ | 换 bf16 |

---

## 🐌 6.5.3 Loss 不下降

| 原因 | 验证 | 修复 |
|---|---|---|
| lr 太小 | 看 lr 值 | lr × 10 |
| 模型太小 | 模型参数量 | 加层/加宽 |
| 数据有 bug | 抽几个样本看 | 检查 dataloader |
| 优化器错 | 用了 SGD 训 LLM？ | 换 AdamW |
| 标签错位 | 看 loss_mask | 检查 SFT 的 mask |
| Forward 算错 | 打印中间值 | 单步 debug |

---

## 🎭 6.5.4 Train 好 Val 差（过拟合）

| 原因 | 修复 |
|---|---|
| 数据少 | 加数据 / 数据增强 |
| 模型太大 | 减容量 / 加正则化 |
| 训练太久 | early stopping |
| 没有 dropout | 加 dropout（LLM 微调时） |
| 没有 weight_decay | AdamW 加 weight_decay=0.01 |
| 数据泄漏 | 检查 train/val 是否重叠 |

→ 详见 [04-过拟合欠拟合与正则化](../01-%E7%AC%AC1%E7%AB%A0-%E6%9C%BA%E5%99%A8%E5%AD%A6%E4%B9%A0%E5%BF%83%E6%99%BA%E6%A8%A1%E5%9E%8B/04-%E8%BF%87%E6%8B%9F%E5%90%88%E6%AC%A0%E6%8B%9F%E5%90%88%E4%B8%8E%E6%AD%A3%E5%88%99%E5%8C%96.md)。

---

## 🌊 6.5.5 Loss 反复震荡

| 原因 | 修复 |
|---|---|
| **lr 太大** | **减半**（最常见原因） |
| batch_size 太小 | 加大 / 梯度累积 |
| 数据没 shuffle | shuffle |
| 数据不均 | 看类别分布 |
| 梯度爆炸 | 加梯度裁剪 |

---

## 💣 6.5.6 训练突然崩（前 N 步好，后面崩）

| 原因 | 验证 | 修复 |
|---|---|---|
| 梯度爆炸 | 看 gradient_norm 曲线 | 加梯度裁剪 |
| 学习率上升期太短 | 看 lr 曲线 | warmup 拉长 |
| 数据某一 batch 异常 | 找崩的 batch | 数据清洗 |
| 数值溢出 | fp16 训练？ | 换 bf16 |

---

## 📉 6.5.7 OOM（Out of Memory）

| 修复（按代价从小到大） | 收益 |
|---|---|
| 减 batch_size | 立竿见影 |
| 减 max_length（序列长度） | 二次方收益（attention $O(T^2)$） |
| **梯度累积** | 同等效 batch，少显存 |
| **gradient_checkpointing** | 省 50%（慢 25%） |
| **bf16 / fp16** | 省 50% |
| **LoRA** | 大模型必备 |
| **ZeRO-2 / FSDP** | 多卡分片 |
| **CPU offload** | 慢但能跑超大模型 |

详见 [03-分布式与显存优化](03-%E5%88%86%E5%B8%83%E5%BC%8F%E4%B8%8E%E6%98%BE%E5%AD%98%E4%BC%98%E5%8C%96.md)。

---

## 🐢 6.5.8 训练慢得离谱

| 瓶颈 | 验证 | 修复 |
|---|---|---|
| 数据加载 | `time.time()` 看每步 IO 时间 | `num_workers=4-8`, `pin_memory=True` |
| GPU 未用 | `nvidia-smi` 看利用率 | 数据要 `.to(device)` |
| 没用 mixed precision | 看训练配置 | 加 bf16 |
| Batch 太小 | 看 batch_size | 加大 / 梯度累积 |
| 单卡 | 看 GPU 数 | 用 DDP 多卡 |
| 没用 Flash Attention | 看 attention 实现 | `F.scaled_dot_product_attention` |

---

## ☠️ 6.5.9 模型权重 NaN

通常是梯度爆炸的后果。

```python
# 检查
for name, p in model.named_parameters():
    if torch.isnan(p).any() or torch.isinf(p).any():
        print(f"NaN/Inf in {name}")

# 防止
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

# 紧急救援
# 1. 回到上一个好的 checkpoint
# 2. lr 减半
# 3. 加 warmup
# 4. 换 bf16
```

---

## 🚩 6.5.10 Eval Acc 异常高（> 99%）

**警告**：可能是数据泄漏！

```
检查清单:
[ ] train 和 test 完全不相交吗？
[ ] 特征里有没有"答案泄漏"？
   （如分类任务，特征里含了类别信息）
[ ] LLM 预训练数据是否包含 test set？
   （SWE-bench / GSM8K 多次被污染）
[ ] 时间序列是否"用未来训预测过去"？
[ ] eval 数据预处理是否和 train 一致？
```

详见 [§1.3 数据泄漏](../01-%E7%AC%AC1%E7%AB%A0-%E6%9C%BA%E5%99%A8%E5%AD%A6%E4%B9%A0%E5%BF%83%E6%99%BA%E6%A8%A1%E5%9E%8B/03-%E8%AE%AD%E7%BB%83%E9%AA%8C%E8%AF%81%E6%B5%8B%E8%AF%95%E9%9B%86.md)。

## 🆘 6.5.11 紧急救援流程

凌晨 3 点训练崩 → 按这个清单：

```
1. Ctrl+C 停训（防止继续浪费 GPU）
2. 看最近的 wandb/tensorboard 曲线
   - KL 暴炸？loss NaN？lr 异常？
3. 检查 OOM 日志: dmesg | grep -i "killed process"
4. 回到上一个好 checkpoint
5. 排查改了什么:
   - 数据有变化？
   - 超参改了？
   - 代码有 bug？
6. 调参重启（lr 减半 / 加梯度裁剪 / 换 bf16）
7. 写事故记录
```

---

## 📌 6.5 节要点

**最常见 3 个问题 + 3 招万能药**：

| 问题 | 万能药 |
|---|---|
| Loss NaN | bf16 + 梯度裁剪 1.0 + 减 lr |
| 训练崩 | warmup + checkpoint 回滚 |
| OOM | LoRA + 梯度累积 + bf16 |

**最重要的事**：
> **每次训练都监控**：train_loss / val_loss / gradient_norm / lr
> **每次重要训练都 checkpoint**：每 N 步保存
