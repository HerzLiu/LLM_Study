# 6.3 分布式与显存优化

⬅ [02-混合精度训练-fp16-bf16](02-%E6%B7%B7%E5%90%88%E7%B2%BE%E5%BA%A6%E8%AE%AD%E7%BB%83-fp16-bf16.md) | ➡ [04-梯度问题诊断](04-%E6%A2%AF%E5%BA%A6%E9%97%AE%E9%A2%98%E8%AF%8A%E6%96%AD.md)

## 🎬 故事比喻：单人 vs 团队搬砖

```
单卡训练: 一个人搬 1000 块砖, 慢 + 累 + 砖太多塞不下
多卡训练: 8 个人分着搬, 快 + 每人显存压力小

但要解决:
  - 每人搬哪些？(数据 / 模型 / 优化器状态怎么切)
  - 怎么同步进度？(梯度怎么汇总)
  - 别人闲着浪费？(负载平衡)
```

> 这一节解释 Happy-LLM 训练用的 DeepSpeed / ZeRO 在做什么。

---

## 📊 6.3.1 训练 LLM 显存占用拆解

一个 7B 模型用 AdamW + bf16 训练：

| 项 | 显存 | 备注 |
|---|---|---|
| 模型参数 (bf16) | **14 GB** | 7B × 2 字节 |
| 梯度 (bf16) | **14 GB** | 同模型 |
| 优化器状态 m, v (fp32) | **56 GB** | 7B × 4 字节 × 2 |
| Master weights (fp32) | **28 GB** | 7B × 4 字节 |
| 激活值（中间结果） | **几十 GB** | 看 batch 和长度 |
| **合计** | **>150 GB** | **一张 80GB 卡装不下** |

→ 这就是为什么 LLM 训练**必须多卡**。

---

## 🎯 6.3.2 4 种分布式策略

### 1. DataParallel（DP，最简单）

每卡放一份完整模型，每卡处理不同 batch：

```
GPU 0: 模型完整 + batch[0:32]
GPU 1: 模型完整 + batch[32:64]
...
GPU 7: 模型完整 + batch[224:256]

→ 同步梯度 → 更新
```

**问题**：每卡都要放完整模型，**大模型 OOM**。

### 2. DistributedDataParallel（DDP，PyTorch 标准）

类似 DP 但更高效（NCCL backend，没有主节点瓶颈）。

**仍然**：每卡完整模型。
**适合**：模型够小能放下，只缺训练速度。

### 3. ZeRO（Zero Redundancy Optimizer，DeepSpeed）⭐ LLM 训练标配

**思路**：把模型的"3 个东西"分片到不同卡——**模型参数 / 梯度 / 优化器状态**。

| 阶段 | 切什么 | 显存节省 | 通信代价 |
|---|---|---|---|
| **ZeRO-1** | 优化器状态 | ~4x | 低 |
| **ZeRO-2** | + 梯度 | ~8x | 中 |
| **ZeRO-3** | + 模型参数 | **~Nx** | 高（每层都要 all-gather） |

→ 详见 [05-Pretrain预训练](../../Happy-LLM/04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/05-Pretrain%E9%A2%84%E8%AE%AD%E7%BB%83.md) § ZeRO。

**ZeRO-3 例子**：8 卡训 7B 模型：

- 每卡放：7B/8 = 0.875B 参数 + 同样比例梯度 + 优化器状态
- 显存压力降到 1/8

### 4. FSDP（Fully Sharded Data Parallel，PyTorch 原生）

PyTorch 2.0+ 的**官方 ZeRO-3 等价物**。

**优势**：不用装 DeepSpeed，原生支持。

---

## 📊 6.3.3 速查表

| 场景 | 用什么 |
|---|---|
| 单卡能放模型 | DDP（多卡纯加速） |
| 模型 7B 单卡放不下 | **ZeRO-2 / FSDP** |
| 模型 70B+ | **ZeRO-3 / FSDP** |
| 100B+ 超大模型 | **ZeRO-3 + offload to CPU** |
| 资源紧张 | **LoRA**（只训少量参数） |

## 💰 6.3.4 其它显存优化技巧

### 1. Gradient Checkpointing

**问题**：前向时所有中间激活都要存（反向时用）。

**解**：**不存中间激活**，反向时**重新前向算**一次。

**收益**：显存减半。
**代价**：训练时间 +25%。

```python
from torch.utils.checkpoint import checkpoint

def forward(x):
    x = checkpoint(layer1, x)   # ← 这层激活不存
    x = checkpoint(layer2, x)
    return x

# 或 Hugging Face
model.gradient_checkpointing_enable()
```

→ Happy-LLM §6.2 用过。

### 2. LoRA（Low-Rank Adaptation）⭐

**问题**：训整个 7B 模型贵。

**解**：冻结模型，只训"低秩矩阵 A B"（参数量减少 99%）：

```
W' = W + AB
↑        ↑
冻结    只训这两个小矩阵
```

→ 详见 [05-LoRA原理深入](../../Happy-LLM/06-%E7%AC%AC6%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%B5%81%E7%A8%8B%E5%AE%9E%E8%B7%B5/05-LoRA%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md)。

### 3. 量化（Quantization）

**训练时**：QLoRA（4bit 量化 + LoRA）
**推理时**：int8 / int4 量化

→ 7B 模型 14GB → 4bit 量化后只要 **3.5GB**，能在消费级 GPU 上推理。

### 4. CPU Offload

**把不常用的张量**（如优化器状态）放到 CPU 内存。

**代价**：通信慢，训练时间增加。
**收益**：能训**比 GPU 显存大得多**的模型。

→ DeepSpeed `offload_optimizer`、`offload_param`。

## 💻 6.3.5 PyTorch 代码（速览）

### DDP

```python
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP

dist.init_process_group("nccl")
model = DDP(model.to(rank), device_ids=[rank])

# 训练循环同单卡
```

### FSDP（PyTorch 原生 ZeRO-3）

```python
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP

model = FSDP(model)
# 训练循环同单卡
```

### DeepSpeed

```python
import deepspeed

# 配置文件 ds_config.json:
# {
#   "zero_optimization": {"stage": 3},
#   "bf16": {"enabled": true}
# }

model_engine, optimizer, _, _ = deepspeed.initialize(
    model=model,
    config="ds_config.json",
)

# 训练
model_engine.backward(loss)
model_engine.step()
```

→ Happy-LLM §6.2 详细 DeepSpeed 实战。

## 🆚 6.3.6 LoRA vs 全量训练

| 维度 | 全量 SFT | LoRA SFT |
|---|---|---|
| 训参数 | 全部 7B | **<1%**（如 16M） |
| 显存 | 80GB+ | **24GB 够** |
| 速度 | 慢 | **快 3-5 倍** |
| 效果 | 略好 | 接近 |
| 多任务 | 切模型 | **只切 LoRA**（小） |

→ **资源紧张优先 LoRA**。

---

## ⚠️ 6.3.7 常见误解

| 误解 | 真相 |
|---|---|
| "DDP 能训大模型" | **不能**——DDP 每卡完整模型，要 ZeRO/FSDP |
| "ZeRO-3 一定最快" | **不！** ZeRO-3 通信多，小模型反而慢 |
| "LoRA 效果远不如全量" | 接近，**有些任务还更好**（不易过拟合） |
| "量化 = 性能损失" | 4bit + 好的量化算法（GPTQ/AWQ）几乎无损 |
| "DeepSpeed = PyTorch" | 是 PyTorch 插件，但 Microsoft 维护 |
| "多卡训练自动加速" | 不！数据加载/同步可能是瓶颈 |

---

## 📌 6.3 节要点

| 工具 | 用途 |
|---|---|
| **DDP** | 多卡纯加速（模型放得下） |
| **FSDP / ZeRO** | 模型放不下时分片 |
| **Gradient Checkpointing** | 时间换显存 |
| **LoRA** | 只训低秩矩阵，显存暴减 |
| **量化** | 推理时省显存 |
| **CPU Offload** | 显存不够，慢但能跑 |

**LLM 训练标配**：
- 单卡（≤7B + LoRA）：**bf16 + LoRA + GradCheckpoint**
- 多卡（7B-70B 全量）：**bf16 + ZeRO-2/3 + GradCheckpoint**
- 超大（100B+）：**bf16 + ZeRO-3 + CPU Offload**
