## 🎬 故事比喻：菜谱调味

```
你已经会做"红烧肉"（DL 训练）。
但每次味道不太一样，主要是 5 个调味品没调好：

  学习率 lr    = 火候大小
  batch_size  = 一锅煮多少肉
  epoch       = 烧多长时间
  weight_decay= 盐放多少（防齁）
  优化器      = 用什么锅（铁锅/不粘锅）
```

> 这一节告诉你这些超参怎么联动调，以及典型 LLM 训练的"调味配方"。

## 🎛 6.1.1 5 大核心超参

| 超参 | 含义 | 典型范围 |
|---|---|---|
| **lr** (learning rate) | 每步更新幅度 | 1e-6 ~ 1e-3 |
| **batch_size** | 每步用多少样本算梯度 | 1 ~ 4096 |
| **epoch** | 整个数据集过几轮 | 1 ~ 100 |
| **weight_decay** | 正则化强度 | 0 ~ 0.1 |
| **optimizer** | 哪个优化器 | AdamW（LLM）/ SGD（CNN） |

## 📊 6.1.2 batch_size 怎么选？

### 影响

| batch_size | 影响 |
|---|---|
| **小**（1-16） | 梯度噪声大，泛化可能好，慢 |
| **中**（32-256） | 平衡，DL 常用 |
| **大**（1024+） | 梯度稳，训练快，但泛化可能差，**OOM 风险** |

### 硬约束：显存

每个 sample 显存 ≈ 模型参数 + 中间激活。
GPU 显存 24GB / 80GB 限制了 batch_size 上限。

### 经验值

| 场景 | batch_size |
|---|---|
| 图像分类（ResNet, GPU 8GB） | 32-128 |
| BERT 微调（GPU 8GB） | 8-16 |
| LLM SFT 7B (GPU 24GB) | 1-2 + 梯度累积 |
| LLM Pretrain（多卡 / TPU） | 1024-4096+ |

### 梯度累积（Gradient Accumulation）⭐ 单卡训大模型必用

**问题**：单卡显存只能放 batch=2，但实验需要 batch=32。

**解**：累积 16 步梯度再更新一次：

```python
accum_steps = 16
for i, batch in enumerate(dataloader):
    loss = model(batch) / accum_steps  # ← 除以 accum_steps
    loss.backward()                     # 梯度累积
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

→ "**等效 batch_size = 物理 batch × accum_steps**"。
→ Happy-LLM §5.9 用过这个技巧。

## 🔥 6.1.3 lr 和 batch_size 的关系

### 经验：batch_size 翻倍 → lr 翻倍（线性 scaling 法则）

```
batch=32, lr=1e-4   →  batch=64, lr=2e-4
                    →  batch=128, lr=4e-4
```

**直觉**：batch 大 → 梯度噪声小 → 可以走大步。

**但**：超大 batch（> 4096）线性 scaling 失效，需要 warmup 拉长。

### LLM 训练典型搭配

| 阶段 | lr | batch | epoch |
|---|---|---|---|
| Pretrain | 1e-4 ~ 3e-4 | 1M-4M tokens | 1（数据多） |
| SFT | 5e-5 ~ 1e-4 | 32-128 samples | 1-3 |
| LoRA SFT | 1e-4 ~ 5e-4 | 16-32 | 3-5 |
| RLHF/PPO | 1e-6 ~ 1e-5 | 16-64 | 1-2 |
| GRPO | 1e-6 ~ 5e-6 | 8-32（含 K 采样） | 1 |

→ 注意 **RL 阶段 lr 比 SFT 小 10 倍**——怕一脚踩空破坏已学好的能力。

## 🔄 6.1.4 调超参的"贝叶斯精神"

### 错误做法：网格搜索

```
lr ∈ {1e-5, 5e-5, 1e-4, 5e-4}
batch ∈ {16, 32, 64, 128}
dropout ∈ {0, 0.1, 0.2}
→ 4×4×3 = 48 组合，每组训一遍

成本: 48 倍训练时间，对 LLM 不可能
```

### 推荐做法：从基线出发，一次改一个

```
Step 1: 用经验值跑一遍 baseline
Step 2: 看 train/val loss 曲线
Step 3: 诊断问题（过拟合 / 欠拟合 / NaN）
Step 4: 改一个超参（如 lr 减半）
Step 5: 重训
```

→ DL 时代**手动 + 直觉**比网格搜索高效。

### 工具

| 工具 | 用途 |
|---|---|
| **W&B (wandb)** | 实时监控 loss / lr / 梯度范数 |
| **TensorBoard** | 同上（PyTorch 原生） |
| **Optuna** | 自动超参搜索（小模型用） |
| **Ray Tune** | 大规模分布式超参搜索 |

## 📈 6.1.5 超参敏感性排序（LLM 训练）

按"调错代价"排序：

1. **lr**（最敏感）→ 调错直接崩
2. **优化器**（AdamW 选错就完）
3. **warmup steps**（太短易崩）
4. **batch_size**（影响泛化和速度）
5. **weight_decay**（过拟合时调）
6. **dropout**（小数据时调）
7. **epoch**（看 val loss 决定）

→ **重点调 lr + 优化器 + warmup**。

---

## 💡 6.1.6 实战 checklist

训练前问自己：

```
[ ] 学习率：参考类似任务经验值（不要随便填）
[ ] batch_size：算显存（或用梯度累积）
[ ] warmup_steps：总步数的 1-10%
[ ] lr_scheduler：cosine 衰减
[ ] 优化器：LLM 用 AdamW，β1=0.9, β2=0.95-0.999
[ ] weight_decay：0.01 (LLM 经验值)
[ ] gradient_clip：1.0（防梯度爆炸）
[ ] 混合精度：bf16（如果 GPU 支持）
[ ] 监控：wandb / tensorboard 看 loss + lr
[ ] checkpoint：每 N 步保存
[ ] 验证：每 epoch 评估 val loss
```

## ⚠️ 6.1.7 常见坑

| 坑 | 排查 |
|---|---|
| Loss 立刻 NaN | lr 太大 / 初始化差 / 数据有 NaN |
| Loss 不下降 | lr 太小 / 模型太小 / 数据有 bug |
| Train 好 val 差 | 过拟合 / 数据泄漏 / 数据分布不同 |
| 训练突然崩 | 梯度爆炸（看 gradient_norm 曲线）|
| OOM | 减 batch / 用梯度累积 / 用 LoRA |
| 慢得离谱 | 数据加载瓶颈（用 `num_workers > 0`）/ 没用 GPU |

→ 详细见 [05-训练诊断手册](05-%E8%AE%AD%E7%BB%83%E8%AF%8A%E6%96%AD%E6%89%8B%E5%86%8C.md)。

## 📌 6.1 节要点

| 超参 | 调原则 |
|---|---|
| lr | 参考经验值，不行减半 |
| batch_size | 看显存，结合梯度累积 |
| epoch | 看 val loss 早停 |
| weight_decay | 0.01 是 LLM 经验值 |
| 优化器 | LLM 几乎一定 AdamW |

**最重要的一句**：
> **DL 训练 90% 时间在调 lr 和诊断 loss 曲线**——这两件做对，模型几乎一定能训。
