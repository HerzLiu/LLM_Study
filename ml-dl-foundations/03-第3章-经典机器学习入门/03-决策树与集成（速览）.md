## 🎬 故事比喻：if-else 自动版

```
你判断"今天去不去打球":

  if 天气 == 晴:
      if 风力 < 3级: 去
      else: 不去
  elif 天气 == 多云: 去
  elif 天气 == 雨: 不去

这就是一棵决策树。
决策树算法 = "自动找最好的 if-else 结构"。
```

> 这一节是**速览**——你的目标是 LLM/Agent，决策树用得少。**知道存在 + 大致原理就行**。

---

## 🌳 3.3.1 决策树（Decision Tree）

### 工作方式

```
                根: 天气?
              /    |    \
           晴/   多云\    雨\
           /        |        \
         风力?      去         不去
         / \
       <3  ≥3
       /     \
      去      不去
```

每个**内部节点** = 一个特征的判断
每个**叶子节点** = 最终预测

### 怎么训练？

**贪心算法**：每个节点选**最能分开数据**的特征 + 阈值。

**"最能分开"用什么衡量？**

- **信息增益**（ID3）：基于信息熵
- **Gini 不纯度**（CART）：$\text{Gini} = 1 - \sum p_i^2$

→ 公式不细推（不重要），知道是这个套路就行。

### 优势

- ✅ **可解释**（人能读懂规则）
- ✅ **不需要特征 normalize**（每个特征独立判断）
- ✅ 处理类别特征（不需要 one-hot）
- ✅ 快、简单

### 劣势

- ❌ **过拟合**（一棵深树能记住训练集）
- ❌ 单棵树准确率有限
- ❌ 不擅长复杂非线性

## 🌲 3.3.2 随机森林（Random Forest）

**思想**：训 N 棵树（多样性），预测时**投票**。

```
树1 → 预测: 类A
树2 → 预测: 类B
树3 → 预测: 类A
...
树100 → 预测: 类A

→ 投票: 类A 60票, 类B 40票 → 输出 A
```

**多样性怎么来？**

1. **Bagging**：每棵树用**不同的随机子集训练**（有放回采样）
2. **特征随机**：每个节点分裂时只考虑**随机一部分特征**

**优势**：
- ✅ 准确率 >> 单棵树
- ✅ 不容易过拟合
- ✅ 几乎没超参要调

**劣势**：
- ❌ 慢、占内存
- ❌ 不可解释（100 棵树投票，没法说"为什么"）

---

## 🚀 3.3.3 XGBoost / LightGBM（Boosting）⭐ 工业界明星

**思想**：和随机森林不同——**串行**训练，每棵新树**纠正前面所有树的错误**。

```
树1 → 预测 (有误差 e1)
树2 → 学着拟合 e1 → 预测 (剩余误差 e2)
树3 → 学着拟合 e2 → 预测 (剩余误差 e3)
...
合并: 树1 + 树2 + 树3 + ... = 最终预测
```

**优势**：
- ✅ **结构化数据（表格）准确率王者**
- ✅ 实践中常**击败神经网络**（在表格数据上）
- ✅ Kaggle 比赛常胜
- ✅ 工业界推荐 / CTR 预测主力

**用在哪**：
- Kaggle、推荐系统、风控、销量预测、CTR
- ❌ **不适合**：图像、文本、序列（这些 DL 更强）

---

## 🆚 3.3.4 决策树家族对比

| 算法 | 思路 | 速度 | 准确率 | 用在哪 |
|---|---|---|---|---|
| 单棵决策树 | 贪心分裂 | 快 | 一般 | 教学 / 可解释场景 |
| 随机森林 | Bagging（并行多棵） | 中 | 好 | 通用 baseline |
| **XGBoost** | Boosting（串行纠错） | 慢一些 | **极好** | 表格数据王者 |
| LightGBM | 类似 XGBoost，优化速度 | 快 | 极好 | 大数据表格 |
| CatBoost | 类似 + 类别特征优化 | 快 | 极好 | 含大量类别特征 |

---

## 💡 3.3.5 何时用决策树家族 vs DL？

| 场景 | 推荐 |
|---|---|
| **表格数据**（行列结构，含数值/类别特征） | **XGBoost** |
| 推荐系统（特征工程） | XGBoost / DNN 都试 |
| **图像** | DL（CNN / ViT） |
| **文本 / 序列** | DL（Transformer / LLM） |
| 时间序列 | XGBoost 或 LSTM 或 Temporal Fusion Transformer |
| 数据量小（< 10k） | 决策树家族 |
| 数据量大（> 1M） | DL |
| 需要可解释 | 单棵决策树 / GAM |

→ **不要无脑用 DL**。XGBoost 在表格上常碾压神经网络。

## 💻 3.3.6 sklearn 代码（速览，不细讲）

```python
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier
import xgboost as xgb

# 决策树
clf = DecisionTreeClassifier(max_depth=5)
clf.fit(X_train, y_train)

# 随机森林
rf = RandomForestClassifier(n_estimators=100, max_depth=10)
rf.fit(X_train, y_train)

# XGBoost
xgb_clf = xgb.XGBClassifier(n_estimators=100, max_depth=6, learning_rate=0.1)
xgb_clf.fit(X_train, y_train)
```

→ 几行就能跑通。
→ **不用 PyTorch**——决策树和神经网络是两个生态。

## ⚠️ 3.3.7 常见误解

| 误解 | 真相 |
|---|---|
| "XGBoost 是神经网络" | **不！** 是决策树的集成 |
| "决策树过时了" | **不！** 表格数据上仍是 SOTA |
| "DL 一定比 XGBoost 强" | **错**！表格数据上常输 |
| "随机森林 = XGBoost" | 不！前者 bagging，后者 boosting |
| "决策树可微" | **不可微**——所以不能和 DL 一起反向传播 |

## 📌 3.3 节要点

| 算法 | 一句话 |
|---|---|
| 决策树 | 自动学 if-else 规则 |
| 随机森林 | N 棵树投票（Bagging） |
| **XGBoost** | 串行训纠错（Boosting，表格数据王者） |

**对你的建议**：
- 知道 XGBoost 存在 + 适用表格数据
- 不需要深究算法细节
- **目标是 LLM/Agent，本节速览即可**
