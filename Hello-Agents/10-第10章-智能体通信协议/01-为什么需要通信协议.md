## 🎬 故事比喻:USB-C 之前 vs 之后

**USB-C 之前**:
- iPhone 用 Lightning
- 安卓用 Micro-USB / USB-C
- 笔记本用各种花式接口
- → **充电线带一堆**

**USB-C 之后**:
- **一根线全搞定**
- → **统一标准的威力**

→ **MCP 之于 Agent**,**就是 USB-C 之于充电**。

## ❌ 10.1.1 单体 Agent 的 3 大限制

### 限制 1:**工具集成困境**

```python
# 传统方式:每个服务都要写一个 Tool 适配器
class GitHubTool(BaseTool):
    """需要手写 GitHub API 适配器"""
    def run(self, repo_url):
        # 大量 API 调用代码...

class DatabaseTool(BaseTool):
    """需要手写数据库适配器"""
    def run(self, query):
        # 数据库连接和查询代码...

class WeatherTool(BaseTool):
    """需要手写天气 API 适配器"""
    def run(self, location):
        # 天气 API 调用代码...

# 每个新服务都要重复...
```

**痛点**:
- 大量**重复**(HTTP / 错误处理 / 认证)
- **难维护**(API 变更影响所有相关工具)
- **无法复用**(其他开发者的工具用不了)
- **扩展性差**(加新服务要大量编码)

### 限制 2:**能力扩展瓶颈**

```
Agent 能力 = 预定义工具集
   ↓
无法动态发现新服务
无法在运行时扩展能力
```

### 限制 3:**协作的缺失**

```
复杂任务 (如: 研究员 + 撰写员 + 编辑)
   ↓
只能 手动编排
   ↓
扩展性差,容易混乱
```

---

## ✨ 10.1.2 通信协议的核心价值

> **通信协议 = Agent 圈的 TCP/IP**

```
有通信协议后:
- 标准化接口     → 不同服务统一访问方式
- 互操作性       → 不同开发者的工具无缝集成
- 动态发现       → 运行时发现新服务
- 可扩展性       → 轻松添加新功能模块
```

### 示例对比

```python
# ❌ 传统:每个服务都自己写
agent.add_tool(GitHubTool())
agent.add_tool(DatabaseTool())
agent.add_tool(WeatherTool())   # 大量重复劳动

# ✅ 用 MCP:连一下就有
agent.add_tool(MCPTool())   # 内置工具
agent.add_tool(MCPTool(server_command=["npx", "-y", "@modelcontextprotocol/server-github"]))
agent.add_tool(MCPTool(server_command=["python", "database_mcp_server.py"]))
# → 自动获得所有能力,无需手写适配器
```

## 🌐 10.1.3 三大协议总览

> 通信协议**不是单一方案**,**针对不同场景**有不同协议。

### MCP(Model Context Protocol)—— 智能体与工具的桥梁

| 维度 | 描述 |
|---|---|
| **出品方** | **Anthropic** |
| **关注点** | 智能体 ↔ **外部工具/资源** |
| **设计哲学** | **"上下文共享"**(不只是 RPC) |
| **状态** | **生态最成熟** |

**比喻**:**USB-C 标准** —— 不同设备(工具)统一接入方式。

### A2A(Agent-to-Agent Protocol)—— 智能体间的对话

| 维度 | 描述 |
|---|---|
| **出品方** | **Google** |
| **关注点** | 智能体 ↔ **智能体** |
| **设计哲学** | **"对等通信"**(P2P) |
| **状态** | 开始落地 |

**比喻**:**Slack/电话** —— Agent 之间直接对话协作。

### ANP(Agent Network Protocol)—— 大规模 Agent 网络的基础设施

| 维度 | 描述 |
|---|---|
| **出品方** | **社区**(早期阶段) |
| **关注点** | 智能体 ↔ **网络发现** |
| **设计哲学** | **"去中心化服务发现"** |
| **状态** | **概念性框架**,生态未成熟 |

**比喻**:**DNS + 黄页** —— Agent 网络中如何找到所需服务。

---

## 📊 10.1.4 三协议完整对比

| 维度 | **MCP** | **A2A** | **ANP** |
|---|---|---|---|
| **核心问题** | 如何访问工具? | 如何与其他 Agent 对话? | 如何在大规模网络中发现 Agent? |
| **出品方** | Anthropic | Google | 社区 |
| **架构** | Client-Server | P2P 对等 | 分布式服务发现 |
| **核心抽象** | Tools / Resources / Prompts | Task / Artifact | 服务注册 / 路由 |
| **典型场景** | 文件/数据库/API 访问 | 多 Agent 协作 | 大规模 Agent 网络 |
| **生态成熟度** | ⭐⭐⭐⭐⭐ 最成熟 | ⭐⭐⭐ 发展中 | ⭐⭐ 早期 |
| **学习优先级** | **最高** | 中 | 低 |

---

## 🎯 10.1.5 如何选择合适的协议?

### 决策树

```
你的需求是?
   │
   ├── Agent 需要访问外部服务(文件/数据库/API)?
   │   └──→ ⭐ MCP (生态成熟,先用这个)
   │
   ├── 多个 Agent 需要相互协作完成任务?
   │   └──→ A2A
   │
   └── 构建大规模 Agent 生态系统?
       └──→ ANP (概念框架,实战参考社区进展)
```

### 真实场景对应

| 场景 | 协议 |
|---|---|
| **代码助手访问 GitHub** | MCP |
| **客服 Agent 查数据库** | MCP |
| **AI Agent 自动操作浏览器** | MCP (如 Playwright MCP) |
| **多 Agent 写论文(研究员+撰写员+编辑)** | A2A |
| **企业级 Agent 平台**(几百个 Agent) | A2A + ANP |

## 🏗 10.1.6 HelloAgents 通信协议架构

> 设计目标:**最简使用 + 足够灵活**。

### 三层架构

```
┌─────────────────────────────────────┐
│  智能体集成层 (Integration)            │
│  ReAct/SimpleAgent → Tool System    │
│  无需关心底层协议                       │
└──────────────┬──────────────────────┘
               ↓
┌─────────────────────────────────────┐
│  工具封装层 (Tool Wrapper)            │
│  MCPTool / A2ATool / ANPTool        │
│  都继承 BaseTool,**统一接口**          │
└──────────────┬──────────────────────┘
               ↓
┌─────────────────────────────────────┐
│  协议实现层 (Protocol)                │
│  MCP: 基于 FastMCP 库                 │
│  A2A: 基于 Google a2a-sdk            │
│  ANP: 自研轻量级实现                   │
└─────────────────────────────────────┘
```

→ **HelloAgents 让"用协议"和"用普通工具"一样简单**。

## 🚀 10.1.7 30 秒体验

### 安装

```bash
pip install "hello-agents[protocol]==0.2.2"
# + 安装 NodeJS(npx 命令)
```

### 三协议示例

```python
from hello_agents.tools import MCPTool, A2ATool, ANPTool

# 1. MCP:访问工具
mcp_tool = MCPTool()
result = mcp_tool.run({
    "action": "call_tool",
    "tool_name": "add",
    "arguments": {"a": 10, "b": 20},
})
print(f"MCP 结果: {result}")   # 30.0

# 2. ANP:服务发现
anp_tool = ANPTool()
anp_tool.run({
    "action": "register_service",
    "service_id": "calculator",
    "endpoint": "http://localhost:8080",
})
services = anp_tool.run({"action": "discover_services"})

# 3. A2A:智能体通信
a2a_tool = A2ATool("http://localhost:5000")
```

→ **3 个协议,3 行代码体验**。

## ⚠️ 小白避坑

1. **协议生态尚在早期**
   - MCP 最成熟,**优先用 MCP**
   - A2A/ANP 关注社区进展
2. **不要"全都要"**
   - 大多数场景**MCP 就够**
   - 不强行用 A2A/ANP
3. **MCP 工具的时效性**
   - 社区工具维护者多变
   - **推荐用大厂(Anthropic/GitHub/Google)背书的**
4. **协议 ≠ 替代框架**
   - MCP/A2A/ANP 是协议
   - LangChain/AutoGen 是框架
   - **协议在框架之下**,二者协同

## 📌 10.1 节要点

| 知识点 | 一句话 |
|---|---|
| **3 大限制** | 工具集成困境 + 能力瓶颈 + 协作缺失 |
| **协议价值** | 标准化 + 互操作 + 动态发现 + 可扩展 |
| **MCP** | Anthropic,智能体↔工具,**生态最成熟** |
| **A2A** | Google,智能体↔智能体,**对等通信** |
| **ANP** | 社区,智能体↔网络,**早期** |
| **选型** | 默认选 MCP,**多 Agent 协作才上 A2A** |
