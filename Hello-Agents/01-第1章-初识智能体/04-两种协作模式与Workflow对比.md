# 1.4 智能体应用的协作模式 + Workflow vs Agent

⬅ [03-动手实现旅行助手](03-%E5%8A%A8%E6%89%8B%E5%AE%9E%E7%8E%B0%E6%97%85%E8%A1%8C%E5%8A%A9%E6%89%8B.md)	|	➡ [进入第 2 章](../02-%E7%AC%AC2%E7%AB%A0-%E6%99%BA%E8%83%BD%E4%BD%93%E5%8F%91%E5%B1%95%E5%8F%B2/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)

---

## 🎬 故事比喻：你和 AI 怎么共事？

你雇了个 AI 助手。**用法有两种**：

| 模式 | 比喻 |
|---|---|
| **工具型** | AI 是**你的实习生** —— 你写代码,它帮你补全/纠错 |
| **协作型** | AI 是**你的同事** —— 你说"做个 X 项目",它自己规划执行 |

这一节我们看这两种模式 + 一个常被搞混的概念：**Workflow vs Agent**。

---

## 🔧 1.4.1 模式 A：作为开发者工具的智能体

> **核心**：AI 增强而非取代人,深度融入工作流。

### 4 大代表产品

| 工具 | 出品方 | 特色 |
|---|---|---|
| **GitHub Copilot** | GitHub + OpenAI | **代码自动补全 王者**,Copilot Chat 加对话能力 |
| **Claude Code** | Anthropic | 终端 AI 助手,**理解整个代码库**,支持 headless 模式(CI 用) |
| **Trae** | – | 轻量、快速响应,适合频繁迭代场景 |
| **Cursor** | – | **AI 原生编辑器**(不是插件,从零设计) |

### ⭐ 共同趋势

> AI **深度融入**软件开发全生命周期 → **重塑软件工程的效率边界**。

**人机协同模式**：
```
你: "写一个排序函数"
   ↓
AI: 自动生成代码框架
   ↓
你: 看一眼 → 接受 / 改 → 提交
   ↓
AI: 帮你 review 自己刚写的代码
```

→ **你做决策,AI 做执行**。

---

## 🤝 1.4.2 模式 B：作为自主协作者的智能体

> **核心**：从"命令-执行"演变为"目标-委托"。

### 范式转变

| | 工具型 | **协作型** |
|---|---|---|
| 你的角色 | 指挥者 | 委托人 |
| AI 的角色 | 实习生 | 独立项目成员 |
| 任务粒度 | 单步("补全这行") | 整体目标("做个 X") |
| AI 的工作方式 | 听指令 | **规划 + 推理 + 执行 + 反思** |

### 三大主流架构范式

#### ① 单智能体自主循环（早期）
- **代表**：BabyAGI、AutoGPT、AgentGPT
- **机制**：一个通用 Agent "思考-规划-执行-反思" 自我迭代
- **特点**：完成开放式高层目标

#### ② 多智能体协作（**当前最主流**）⭐
- **机制**：模拟人类团队协作

**两种子模式**：

##### 角色扮演式对话
- **代表**：**CAMEL**
- 例：两个 Agent 扮演"程序员"+"产品经理",在对话中协同完成任务

##### 组织化工作流
- **代表**：
  - **MetaGPT** —— 模拟"虚拟软件公司"
  - **CrewAI** —— 分工明确的工作流
  - **AutoGen** / **AgentScope** —— 灵活的对话模式
- 例：产品经理 Agent + 程序员 Agent + 测试员 Agent → 完整代码库

#### ③ 高级控制流架构
- **代表**：**LangGraph**
- **机制**：Agent 执行过程建模为**状态图**(State Graph)
- **优势**：灵活实现循环、分支、回溯、人工介入

→ 这些框架**第 6 章会详细讲**。

## 🆚 1.4.3 Workflow vs Agent —— 最常被混淆的概念

> **Workflow = 让 AI 按部就班执行指令**
> **Agent = 赋予 AI 自由度去自主达成目标**

### 直观对比

```
┌─────── Workflow（工作流）───────┐    ┌─────────── Agent（智能体）───────────┐
│                                  │    │                                       │
│  开始 → A → B → C → 结束          │    │   目标                                │
│         ↓ if X                   │    │     ↓                                  │
│         D                        │    │   LLM 分析 → 选工具 → 执行 → 看结果    │
│                                  │    │     ↑___________________________↓     │
│  ⚠️ 流程图固定,死板                │    │                                       │
└──────────────────────────────────┘    └──────────────────────────────────────┘
```

### 详细对比表

| 维度 | **Workflow** | **Agent** |
|---|---|---|
| **本质** | 静态的流程图 | 动态的决策系统 |
| **执行路径** | 预先定义 + 固定 | 运行时动态决定 |
| **判断条件** | `if-else` 写死 | LLM 推理判断 |
| **灵活性** | 低 | 高 |
| **可预测性** | 高 | 中(LLM 有随机性) |
| **适合场景** | 流程固定的任务 | 开放/模糊任务 |
| **成本** | 低(不依赖 LLM 推理) | 高(每步都调 LLM) |
| **可解释** | 完全可解释 | 部分(Thought 可见) |

### 💼 真实场景对比

#### 场景：费用报销审批

**Workflow 方式**：
```
员工提交报销单(触发)
   ↓ 自动判断金额
< 500: 部门经理审批
≥ 500: 部门经理 + 财务总监审批
   ↓ 审批通过
通知财务打款
```
→ 每一步都**预先设定**,**没有 AI 在动脑子**。

**Agent 方式**：
```
员工: "我去出差报销 5000 块"
Agent: 自己判断 → 调发票识别 OCR → 查公司报销规则 → 决定该谁审 → 自动提交...
```
→ Agent **自主决策**,根据情况调整流程。

#### 场景：智能旅行助手

**Workflow 不可行** —— 因为用户需求**无法预定义流程**：
- "去北京玩 3 天" 和 "去厦门玩 5 天" 流程相似但细节不同
- "我有 5000 预算" vs "我要奢华游"——决策路径完全不同

→ **必须用 Agent**(回顾 [1.3 节的实战](03-%E5%8A%A8%E6%89%8B%E5%AE%9E%E7%8E%B0%E6%97%85%E8%A1%8C%E5%8A%A9%E6%89%8B.md))。

### ⭐ 如何选择？

| 任务特点 | 用什么 |
|---|---|
| 流程固定 + 高频 + 成本敏感 | **Workflow** |
| 任务开放 + 需推理 + 灵活 | **Agent** |
| 大流程固定 + 局部需要灵活 | **混合**（Workflow 调 Agent 做某些子任务） |

→ **不是非此即彼**,生产系统常常**混合使用**。

## 🎯 1.4 节核心洞察

### 洞察 1：**你的角色在变**

```
传统软件: 程序员 → 写代码 → 程序自动执行
↓
AI 工具时代: 程序员 + Copilot → 共同写代码
↓
Agent 时代: 用户 → 设目标 → Agent 自己干完
```

### 洞察 2：**Workflow 没死,但 Agent 是未来**

- 简单可预测的任务永远会用 Workflow(快、稳、便宜)
- 复杂开放的任务才需要 Agent(贵但能干)
- 真正成功的系统是**Workflow 框架 + Agent 智能填空**

### 洞察 3：**框架百花齐放**

- BabyAGI / AutoGPT(早期)
- CrewAI / MetaGPT(组织化)
- AutoGen / AgentScope(灵活对话)
- LangGraph(状态图)
- → 都是为了解决"如何让多个 Agent 协作"

→ 这些**第 6 章**会一一动手实践。

---

## ⚠️ 小白避坑

1. **别炫技,该用 Workflow 就用**
   - 简单流程上 Agent **又贵又不稳定**
   - 真实生产中很多"AI 系统"其实是**带一点 AI 的 Workflow**
2. **多智能体不一定好**
   - 多了**通信成本暴增**,且更容易出错
   - 单 Agent 能搞定的别上多 Agent
3. **AutoGPT 已经被淘汰**
   - 太早期、太通用、效果差
   - 现在主流是 **CrewAI / LangGraph** 等更专业的框架

---

## 📌 1.4 节要点

| 知识点 | 一句话 |
|---|---|
| 工具型 Agent | Copilot / Cursor —— **增强人类工作流** |
| 协作型 Agent | CrewAI / MetaGPT —— **代替人类完成目标** |
| Workflow | 流程固定的自动化 |
| Agent | **目标-委托** 的自主系统 |
| 选型原则 | **流程固定用 Workflow,开放任务用 Agent** |
