# 1.3 动手体验：5 分钟实现第一个智能体

⬅ [02-构成与运行原理](02-%E6%9E%84%E6%88%90%E4%B8%8E%E8%BF%90%E8%A1%8C%E5%8E%9F%E7%90%86.md)	|	➡ [04-两种协作模式与Workflow对比](04-%E4%B8%A4%E7%A7%8D%E5%8D%8F%E4%BD%9C%E6%A8%A1%E5%BC%8F%E4%B8%8EWorkflow%E5%AF%B9%E6%AF%94.md)

> 🎯 **本节目标**：用 **80 行 Python** 手撕一个**智能旅行助手**，让 [T-A-O 范式](02-%E6%9E%84%E6%88%90%E4%B8%8E%E8%BF%90%E8%A1%8C%E5%8E%9F%E7%90%86.md)从纸上跳到屏幕上。

## 🎬 故事比喻：教小学生"自己思考做作业"

平时给小学生布置作业你得手把手教：先做第 1 题，再做第 2 题…
**这次不一样**：给他一张"作业流程说明书"+ 一些工具，让他**自己想 → 自己做 → 看结果 → 自己想下一步**。

→ 这就是我们要给 LLM 装的"自主思考"机制。

---

## 🎯 任务设计

**用户输入**：
> "你好，请帮我查询一下今天北京的天气，然后根据天气推荐一个合适的旅游景点。"

**Agent 要做的**：
1. 先查天气（调天气工具）
2. 看天气结果，**再决定**调景点推荐工具（参数包含天气）
3. 综合两者给出最终建议

→ **必须按顺序**——第 2 步**依赖**第 1 步的结果。
→ 这就是 T-A-O 循环的真实场景。

## 📜 Step 1：写 Agent 的"说明书"（System Prompt）

⭐ **整个 Agent 的灵魂**就是这段 prompt：

```python
AGENT_SYSTEM_PROMPT = """
你是一个智能旅行助手。你的任务是分析用户的请求，并使用可用工具一步步地解决问题。

# 可用工具:
- `get_weather(city: str)`: 查询指定城市的实时天气。
- `get_attraction(city: str, weather: str)`: 根据城市和天气搜索推荐的旅游景点。

# 输出格式要求:
你的每次回复必须严格遵循以下格式，包含一对 Thought 和 Action:

Thought: [你的思考过程和下一步计划]
Action: [你要执行的具体行动]

Action 的格式必须是以下之一:
1. 调用工具: function_name(arg_name="arg_value")
2. 结束任务: Finish[最终答案]

# 重要提示:
- 每次只输出一对 Thought-Action
- Action 必须在同一行,不要换行
- 当收集到足够信息可以回答用户问题时,必须使用 Action: Finish[最终答案] 格式结束

请开始吧!
"""
```

### 📝 这段 prompt 干了啥

| 部分 | 作用 |
|---|---|
| **角色设定** | "你是智能旅行助手" → 让 LLM 进入角色 |
| **工具列表** | 列出可用函数 + 签名 → LLM 知道能调啥 |
| **输出格式** | 强制 `Thought:` + `Action:` 结构 → 方便解析 |
| **终止条件** | `Action: Finish[...]` → 告诉 LLM 怎么"收工" |

→ **prompt 工程 = Agent 的核心代码**之一。

## 🐍 Step 2：实现两个工具函数

### 工具 1：查天气（用免费 API）

```python
import requests

def get_weather(city: str) -> str:
    """通过 wttr.in 查真实天气"""
    url = f"https://wttr.in/{city}?format=j1"
    try:
        response = requests.get(url)
        response.raise_for_status()
        data = response.json()

        current = data['current_condition'][0]
        weather_desc = current['weatherDesc'][0]['value']
        temp_c = current['temp_C']

        # ⭐ 关键:把 JSON 翻译成自然语言返回(给 LLM 用)
        return f"{city}当前天气: {weather_desc},气温 {temp_c} 摄氏度"
    except Exception as e:
        return f"错误: {e}"
```

### 工具 2：推荐景点（用 Tavily 搜索）

```python
import os
from tavily import TavilyClient

def get_attraction(city: str, weather: str) -> str:
    """根据城市和天气搜索景点推荐"""
    api_key = os.environ.get("TAVILY_API_KEY")
    tavily = TavilyClient(api_key=api_key)

    query = f"'{city}' 在'{weather}'天气下最值得去的旅游景点推荐及理由"
    response = tavily.search(query=query, search_depth="basic", include_answer=True)

    # Tavily 的 include_answer=True 会返回综合回答
    if response.get("answer"):
        return response["answer"]
    return "暂无相关推荐"
```

### 工具注册表

```python
# 把工具放进字典，方便主循环按名调用
available_tools = {
    "get_weather": get_weather,
    "get_attraction": get_attraction,
}
```

## 🤖 Step 3：封装 LLM 客户端

```python
from openai import OpenAI

class OpenAICompatibleClient:
    """兼容 OpenAI 接口的 LLM 客户端
    可对接 OpenAI 官方 / Azure / Ollama 等任何兼容服务
    """
    def __init__(self, model: str, api_key: str, base_url: str):
        self.model = model
        self.client = OpenAI(api_key=api_key, base_url=base_url)

    def generate(self, prompt: str, system_prompt: str) -> str:
        messages = [
            {'role': 'system', 'content': system_prompt},
            {'role': 'user',   'content': prompt}
        ]
        response = self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            stream=False
        )
        return response.choices[0].message.content
```

### 📝 设计要点

- **OpenAI 兼容接口**已成行业标准
- Ollama / vLLM / 国产 LLM 大多兼容
- 一个客户端能切换所有服务

## 🔁 Step 4：核心 Agent 循环

⭐ **这才是 Agent 的"心脏"**：

```python
import re

# ---- 1. 配置 ----
llm = OpenAICompatibleClient(
    model="YOUR_MODEL_ID",
    api_key="YOUR_API_KEY",
    base_url="YOUR_BASE_URL"
)
os.environ['TAVILY_API_KEY'] = "YOUR_TAVILY_API_KEY"

# ---- 2. 初始化 ----
user_prompt = "你好,请帮我查询一下今天北京的天气,然后根据天气推荐一个合适的旅游景点。"
prompt_history = [f"用户请求: {user_prompt}"]

# ---- 3. 主循环 ----
for i in range(5):   # ⭐ 最多 5 轮,防死循环
    print(f"--- 循环 {i+1} ---")

    # 3.1 拼当前 prompt
    full_prompt = "\n".join(prompt_history)

    # 3.2 调 LLM 思考
    llm_output = llm.generate(full_prompt, system_prompt=AGENT_SYSTEM_PROMPT)
    print(f"模型输出:\n{llm_output}")
    prompt_history.append(llm_output)

    # 3.3 解析 Action
    action_match = re.search(r"Action: (.*)", llm_output, re.DOTALL)
    if not action_match:
        observation = "错误: 未能解析到 Action 字段"
        prompt_history.append(f"Observation: {observation}")
        continue

    action_str = action_match.group(1).strip()

    # 3.4 判断是否结束
    if action_str.startswith("Finish"):
        final_answer = re.match(r"Finish\[(.*)\]", action_str).group(1)
        print(f"任务完成,最终答案: {final_answer}")
        break

    # 3.5 解析工具名和参数
    tool_name = re.search(r"(\w+)\(", action_str).group(1)
    args_str = re.search(r"\((.*)\)", action_str).group(1)
    kwargs = dict(re.findall(r'(\w+)="([^"]*)"', args_str))

    # 3.6 执行工具
    if tool_name in available_tools:
        observation = available_tools[tool_name](**kwargs)
    else:
        observation = f"错误: 未定义的工具 '{tool_name}'"

    # 3.7 把 Observation 喂回历史 → 下一轮循环
    print(f"Observation: {observation}")
    prompt_history.append(f"Observation: {observation}")
```

### 📝 代码深度解读

#### 关键点 1：`prompt_history` 累积记忆
```python
prompt_history = [f"用户请求: {user_prompt}"]
# 每轮把 llm_output 和 observation 都 append 进去
```
→ **历史 = Agent 的短期记忆**。每次 LLM 看到的都是完整对话历史。

#### 关键点 2：正则解析 Action
```python
action_match = re.search(r"Action: (.*)", llm_output, re.DOTALL)
```
→ 这是为什么 prompt 强制格式 `Action: xxx` —— 方便正则匹配。
→ 工程上**更稳定的做法**是用 **Function Calling**（OpenAI 标准），但理解原理用正则就够了。

#### 关键点 3：`max_iterations = 5`
```python
for i in range(5):
```
→ **防死循环**！LLM 可能反复调用同一个工具卡住。
→ 设上限是 Agent 工程的**铁律**。

#### 关键点 4：Finish 判断
```python
if action_str.startswith("Finish"):
    break
```
→ 让 LLM 知道**怎么收工**。
→ 没这个的话 LLM 可能永远循环。

## 🎮 Step 5：真实运行结果

```
用户输入: 你好,请帮我查询一下今天北京的天气,然后根据天气推荐一个合适的旅游景点。
==========================================
--- 循环 1 ---
模型输出:
Thought: 首先需要获取北京今天的天气情况,之后再根据天气情况来推荐旅游景点。
Action: get_weather(city="北京")
Observation: 北京当前天气:Sunny,气温 26 摄氏度
==========================================
--- 循环 2 ---
模型输出:
Thought: 现在已经知道了北京今天的天气是晴朗且温度适中,接下来可以基于这个信息来推荐景点了。
Action: get_attraction(city="北京", weather="Sunny")
Observation: 北京在晴天最值得去的景点是颐和园,因其美丽的湖景和古建筑。另一个推荐是长城...
==========================================
--- 循环 3 ---
模型输出:
Thought: 已经获得了景点建议,现在可以根据这些信息给用户提供满意的答复。
Action: Finish[今天北京天气晴朗,气温 26 摄氏度,非常适合外出游玩。
推荐去颐和园欣赏湖景和古建筑,或前往长城体验壮观景观和历史。]

任务完成,最终答案: ...
```

→ **3 轮循环搞定**，完整呈现了 T-A-O 范式。

## ⭐ 这个案例展示了 Agent 的 4 大基本能力

| 能力 | 在哪体现 |
|---|---|
| **任务分解** | 把"规划行程"拆成"查天气 + 推荐景点" |
| **工具调用** | 主动选择 get_weather / get_attraction |
| **上下文理解** | 第 2 轮用了第 1 轮 Observation 的"Sunny" |
| **结果合成** | 最后整合所有信息给出人话答复 |

→ 你已经做出了一个**真正的 LLM Agent**！🎉

## ⚠️ 小白避坑

1. **正则解析不稳**
   - 生产代码用 **Function Calling**（更可靠）
   - 详见 [Happy-LLM 第 7 章 Tiny-Agent](../../Happy-LLM/07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/05-Tiny-Agent%E5%AE%9E%E6%88%98%E9%80%9F%E8%A7%88.md)
2. **temperature 设小**
   - LLM 默认 1.0 太随机
   - Agent 用 **0.1~0.3** 更稳定
3. **prompt 改一个字效果差很多**
   - 字段名 / 顺序 / 标点都敏感
   - 多调几版 prompt
4. **API Key 别提交到 GitHub**
   - 用 `os.environ` 或 `.env` 文件
5. **网络问题要处理**
   - `try/except` 捕获 `requests` 异常,返回错误信息给 LLM
   - LLM 看到错误会自己处理(惊喜！)
