# 3.3 LLM 的缩放法则与局限性

## 🎬 故事比喻:LLM 不是万能的

LLM 像个**博学但偶尔胡说的天才**:
- **量变引起质变**:足够大才有"涌现能力"
- **会撒谎**:一本正经地胡说八道(幻觉)

→ 做 Agent 时,**这两件事会反复来烦你**。

---

## 📊 3.3.1 缩放法则(Scaling Law)

### 核心结论

> **LLM 性能 ≈ f(参数量 N, 数据量 D, 算力 C)**
> **三者按特定比例增长,性能可预测地提升**。

### 关键公式

**OpenAI**:`C ≈ 6 · N · D`,最佳 `D ≈ 1.7N`
**Chinchilla**(DeepMind):最佳 `D ≈ 20N`(数据要更多)

→ **完整 Scaling Law 推导 + 实战应用**:[Happy-LLM 4.2.1 Scaling Law](../../Happy-LLM/04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/05-Pretrain%E9%A2%84%E8%AE%AD%E7%BB%83.md#-scaling-law%E5%8F%82%E6%95%B0%E5%92%8C%E6%95%B0%E6%8D%AE%E6%80%8E%E4%B9%88%E9%85%8D)

### 对 Agent 开发者的启示

| 模型规模 | Agent 能力 |
|---|---|
| **< 1B** | 简单分类、补全(做 Agent 不够) |
| **1B–7B** | 简单工具调用,**适合做单步 Agent** |
| **7B–70B** | 多步推理,**做 Agent 主力** |
| **70B+ / GPT-4 级** | 复杂规划、Agent 协作,**生产级首选** |

→ **想做生产级 Agent,模型至少 7B 起**。

### ⭐ 涌现能力(Emergent Abilities)

> 某些能力(如 **CoT 推理 / few-shot learning**)**只在大模型上出现**。

```
能力 ↑                              ┌──── 涌现!
       │                            /
       │                           /
       │___________________________/
       └──────────────────────────► 模型规模
            阈值前               阈值后
```

→ **小模型做 Agent 局限多**,推理任务必须用大模型。
→ 详见 [Happy-LLM 涌现能力](../../Happy-LLM/04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/02-LLM%E5%9B%9B%E5%A4%A7%E8%83%BD%E5%8A%9B.md#-%E8%83%BD%E5%8A%9B-1%E6%B6%8C%E7%8E%B0%E8%83%BD%E5%8A%9Bemergent-abilities)

## ⚠️ 3.3.2 模型幻觉(Hallucination)—— Agent 的天敌

### 什么是幻觉?

> **LLM 一本正经地胡说八道,生成与事实不符的内容**。

#### 经典例子

```
User: 请列出 5 篇关于"量子机器学习"的最新论文。
LLM:
1. "Quantum ML in 2024" - Smith J. et al. (Nature, 2024)  ← 不存在
2. "QML Foundations" - Lee K. (NeurIPS, 2023)              ← 不存在
3. ...                                                       ← 全是编的
```

→ **看似专业,实际全是 LLM 编的**。这就是幻觉。

### 幻觉的根源(3 大原因)

| 原因 | 解释 |
|---|---|
| **训练目标**(CLM) | 模型只学"预测下一个词",不学"判断真假" |
| **训练数据噪声** | 互联网本身有错信息 → 模型学错了 |
| **知识截止日期** | 训完之后的事 → 模型不知道,只能编 |

### 对 Agent 的影响 ⚠️

| Agent 类型 | 受幻觉影响程度 |
|---|---|
| 工具调用 Agent | 中(可能生成错的 API 参数) |
| 知识问答 Agent | **极高**(编不存在的事实) |
| 代码生成 Agent | 高(编不存在的 API/函数) |
| 多步规划 Agent | 高(规划基于错误前提) |

### 缓解策略(Agent 必备)

| 策略             | 解释                                  | 详细                                                                                                      |
| -------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **RAG**        | 让 Agent 先**检索真实文档**再回答              | [第 8 章 RAG](../08-%E7%AC%AC8%E7%AB%A0-%E8%AE%B0%E5%BF%86%E4%B8%8E%E6%A3%80%E7%B4%A2/03-RAG%E5%9F%BA%E7%A1%80%E4%B8%8E%E5%8E%9F%E7%90%86.md) + [Happy-LLM RAG](../../Happy-LLM/07-%E7%AC%AC7%E7%AB%A0-%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8/02-RAG%E5%8E%9F%E7%90%86%E6%B7%B1%E5%85%A5.md) |
| **工具调用**       | 让 Agent **调真实 API**(如计算器、搜索引擎)而非凭记忆 | [第 1 章实战](../01-%E7%AC%AC1%E7%AB%A0-%E5%88%9D%E8%AF%86%E6%99%BA%E8%83%BD%E4%BD%93/03-%E5%8A%A8%E6%89%8B%E5%AE%9E%E7%8E%B0%E6%97%85%E8%A1%8C%E5%8A%A9%E6%89%8B.md)                                                                |
| **Reflection** | 让 Agent **自我反思**输出,纠正错误             | 第 4 章 [Reflection 范式](../04-%E7%AC%AC4%E7%AB%A0-%E6%99%BA%E8%83%BD%E4%BD%93%E7%BB%8F%E5%85%B8%E8%8C%83%E5%BC%8F/00-%E7%AB%A0%E8%8A%82%E6%80%BB%E8%A7%88.md)                                                      |
| **温度调低**       | `temperature=0` 让模型更确定              | [3.2.1](02-%E4%B8%8ELLM%E4%BA%A4%E4%BA%92.md#%E6%97%8B%E9%92%AE-1temperature%E6%B8%A9%E5%BA%A6)                                                               |
| **结构化输出**      | 强制 JSON / 函数调用,减少自由发挥               | OpenAI Function Calling                                                                                 |

## 🎯 LLM 的其他局限(简述)

| 局限 | 解释 | Agent 对策 |
|---|---|---|
| **知识时效性** | 训完就过期 | RAG / 联网搜索 |
| **长上下文低效** | "针在草垛"问题(长上下文中间内容被忽略) | 分段处理 / Memory |
| **计算能力差** | 大数运算容易错 | 调计算器工具 |
| **缺乏真实世界感知** | 不知物理定律 | 引入多模态 + 模拟器 |
| **训练数据偏见** | 复制人类偏见 | 对齐(RLHF/DPO) |
| **多语言不平衡** | 英文 >> 其他语言 | 选合适的多语模型 |

→ **每一项局限,都是某个 Agent 框架的发力方向**。
→ 详见 [Happy-LLM 4.x 现状](../../Happy-LLM/04-%E7%AC%AC4%E7%AB%A0-%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B/08-%E7%AB%A0%E8%8A%82%E5%B0%8F%E7%BB%93.md#-llm-%E7%9A%84%E7%8E%B0%E7%8A%B6%E4%B8%8E%E6%9C%AA%E6%9D%A5)

## 📌 3.3 节要点

| 知识点 | 一句话 |
|---|---|
| **Scaling Law** | 参数 + 数据 + 算力 三者按比例增长 → 性能可预测提升 |
| **涌现能力** | 大模型才有 CoT/few-shot,**做 Agent 用 7B+** |
| **幻觉** | LLM 固有缺陷,**无法根除,只能缓解** |
| **Agent 抗幻觉** | **RAG + 工具调用 + Reflection** 是三大法宝 |
