# 12.4 数据生成质量评估 —— 给"AI 出的题"打分

## 🎬 故事比喻:让 AI 当"数学竞赛出题人"

> **场景**:你是教培公司,想让 LLM **自动出 AIME(美国数学邀请赛)风格的题**,刷给学生练手。
>
> 让 GPT-4 出了 **1000 道题**,现在问题来了:
> - **这些题质量怎么样?**
> - **比真题差多少?**
> - **能直接给学生用吗?**
>
> 总不能 1000 道全靠人审 —— **人审 1 道 10 分钟,1000 道 = 167 小时**,谁顶得住?

→ 本节教你**自动化评估 AI 生成数据的质量**,三招组合拳:

| 招式 | 比喻 | 干啥 |
|---|---|---|
| **LLM Judge** | 请 GPT-4 当"评委" | 给每道题打分(1-5) |
| **Win Rate** | "盲品"对比真题 | 让 LLM 选哪个更好 |
| **人工验证** | 专家 Review | 终审兜底 |

---

## 🔧 技术拆解:为什么是这三招?

### (1)单一方法的局限

| 方法 | 优点 | 致命缺点 |
|---|---|---|
| **全人工** | 最准 | 慢、贵、不可扩展 |
| **只用 LLM Judge** | 快 | 可能"AI 自吹自擂"(bias) |
| **只跟真题比** | 客观 | 不知道**好**到啥程度 |

→ **三招组合**,优势互补:
- LLM Judge:**绝对评分**(单题打分)
- Win Rate:**相对评分**(vs 真题)
- 人工:**最终把关**

### (2)为什么用 AIME?

> **AIME** = American Invitational Mathematics Examination,美国数学邀请赛

| 特点 | 为啥适合做评估基准 |
|---|---|
| 答案是 **0-999 整数** | 评分简单,不用语义对比 |
| 涵盖代数/几何/数论/组合/概率 | 题目多样,能测多领域 |
| 难度中等(需多步推理但不要高深理论) | 适合 LLM 当前水平 |
| 有 **900+ 真题**(1983-2025) | 现成参考样本 |

→ 数据集:`TianHongZXY/aime-1983-2025`(HuggingFace)

## ⭐ 加深理解:三方法详细拆解

### 方法 1:LLM Judge —— 让 GPT-4 当评委

#### 4 个评分维度(每个 1-5 分)

| 维度 | 评什么 | 满分(5)标准 |
|---|---|---|
| **正确性 Correctness** | 数学逻辑对不对,答案准不准 | 推理无误 + 答案精确 |
| **清晰度 Clarity** | 题目表述清不清楚,解答好不好懂 | 没有歧义 + 步骤分明 |
| **难度匹配 Difficulty Match** | 难度像不像 AIME 中等偏难 | 难度恰好(不水也不偏怪) |
| **完整性 Completeness** | 解答步骤全不全 | 包含所有推理 |

#### 3 个汇总指标

```
平均分 = ∑(单题平均) / 题目数         ← 整体水平
通过率 = (平均分 ≥ 3.5 的题数) / 总数  ← 基本质量
优秀率 = (平均分 ≥ 4.5 的题数) / 总数  ← 高质量占比
```

| 指标 | 健康线 |
|---|---|
| 平均分 | ≥ 4.0 / 5.0 |
| 通过率 | ≥ 80% |
| 优秀率 | ≥ 40% |

### 方法 2:Win Rate —— 盲品对比真题

#### 流程

```
            生成题 A      AIME 真题 B
                ↓               ↓
                └───→ LLM 评委 ←─┘
                       ↓
              判断:谁更好?
               ┌───────┼───────┐
              Win    Tie    Loss
              (A胜) (平局) (A输)
```

#### 三个比例

| 指标 | 公式 | 含义 |
|---|---|---|
| **胜率 Win Rate** | Wins / Total | A 比真题好的比例 |
| **败率 Loss Rate** | Losses / Total | A 比真题差的比例 |
| **平局率 Tie Rate** | Ties / Total | 质量相当 |

→ **理想结果:Win Rate ≈ 50%**(说明生成题质量接近真题)

⚠️ **坑**:Win Rate 远高于 50% 不一定是好事 —— 可能是**评委有偏见**(比如更喜欢 AI 生成的固定句式)!

### 方法 3:人工验证 —— 终审

> 为什么 LLM Judge + Win Rate 还不够?

数学题的**正确性是 0/1 的**(答案要么对要么错),LLM Judge **可能算错**!

→ 必须**人工兜底**,但要**降低成本**:用 Gradio 做一个 Web 界面,让验证者点击式打分。

| 验证状态 | 含义 |
|---|---|
| ✅ approved | 通过 |
| ❌ rejected | 拒绝 |
| 🔄 needs_revision | 需修改 |

## 🐍 代码详解:从生成到评估全流程

### Step 1:AIME 题目生成器

```python
from helloagents import HelloAgentsLLM, SimpleAgent
from datasets import load_dataset
import time, json, re, os
from tqdm import tqdm

# 生成提示词(英文,与 AIME 真题保持一致)
GENERATION_PROMPT = """You are a professional mathematics competition problem 
designer, skilled in creating AIME-style problems.

【Reference Example】(For style reference only, generate a completely different problem)
Problem: {example_problem}
Answer: {example_answer}

AIME Problem Characteristics:
1. Answer: An integer between 0 and 999
2. Topics: Algebra, Geometry, Number Theory, Combinatorics, Probability, etc.
3. Style: Multi-step reasoning, no advanced theory
4. Difficulty: Medium to hard (AIME problems 6-9)

Please generate a **completely different** AIME-style problem, output in JSON:
{
    "problem": "Problem statement in English",
    "answer": 123,
    "solution": "Detailed solution steps",
    "topic": "Algebra"
}
"""

class AIMEGenerator:
    """AIME 题目批量生成器"""

    def __init__(
        self,
        llm: HelloAgentsLLM = None,
        delay_seconds: float = 1.0,           # API 调用最小间隔(防限流)
        use_reference_examples: bool = True,
        reference_dataset: str = "TianHongZXY/aime-1983-2025"
    ):
        self.llm = llm or HelloAgentsLLM()
        # 用 SimpleAgent 包装,system_prompt 设定身份
        self.agent = SimpleAgent(
            name="AIME Generator",
            llm=self.llm,
            system_prompt="You are a professional mathematics competition problem designer."
        )
        self.delay_seconds = delay_seconds

        # 加载 900+ AIME 真题作为参考样例
        if use_reference_examples:
            dataset = load_dataset(reference_dataset, split="test")
            self.reference_examples = list(dataset)

    def generate_and_save(self, num_problems: int = 30, output_dir: str = "./generated_data"):
        """带智能延迟的批量生成"""
        # 清理旧检查点
        for file in os.listdir(output_dir):
            if file.startswith("checkpoint_"):
                os.remove(os.path.join(output_dir, file))

        # 用 tqdm 显示进度条
        with tqdm(total=num_problems, desc="Generating AIME", unit="problem") as pbar:
            last_call_time = 0
            for i in range(num_problems):
                # ⭐ 关键:确保 API 调用间隔(防止 429 限流)
                if last_call_time > 0:
                    elapsed = time.time() - last_call_time
                    if elapsed < self.delay_seconds:
                        time.sleep(self.delay_seconds - elapsed)

                # 生成单题(内部会随机选一个 reference example)
                start = time.time()
                problem = self.generate_single()
                last_call_time = time.time()

                # 进度条显示题目元数据
                pbar.set_postfix({
                    "topic": problem.get('topic', 'N/A'),
                    "answer": problem.get('answer', 'N/A'),
                    "time": f"{last_call_time - start:.1f}s"
                })
                pbar.update(1)
```

#### ⚠️ LaTeX 数学公式坑

生成的题目含 LaTeX 公式(如 `$\frac{a}{b}$`),`\frac` 的反斜杠在 JSON 里**非法**!

```python
def _parse_response(self, response: str) -> dict:
    """解析 LLM 响应(处理 LaTeX 转义)"""
    # 提取 JSON 部分
    if "```json" in response:
        json_str = response.split("```json")[1].split("```")[0].strip()
    else:
        json_str = response.strip()

    try:
        return json.loads(json_str)
    except json.JSONDecodeError:
        # ⭐ 修复:把未转义的 \ 替换为 \\
        # 正则:找不是合法转义字符前面的反斜杠
        fixed = re.sub(r'(?<!\\)\\(?!["\\/bfnrtu])', r'\\\\', json_str)
        return json.loads(fixed)
```

> **报错预兆**:`Invalid \escape: line 4 column 185` → 100% LaTeX 转义问题!

from helloagents.evaluation import Tool, AIDataset, LLMJudgeEvaluator

### Step 3:Win Rate 评估工具

```python
class WinRateTool(Tool):
    """Win Rate 成对对比评估工具"""

    def run(self, params: dict) -> str:
        # 加载生成数据 + 真题
        gen_problems = AIDataset("generated", params["generated_data_path"]).load()
        ref_problems = AIDataset("real", year=2025).load()

        wins, losses, ties = 0, 0, 0
        total = min(len(gen_problems), len(ref_problems))

        for gen, ref in zip(gen_problems, ref_problems):
            # ⭐ 关键:盲品 —— 不告诉 LLM 哪个是生成的
            prompt = f"""比较以下两道 AIME 数学题的质量:
题目A:{gen['problem']}
题目B:{ref['problem']}

请判断:A、B、还是 Tie(质量相当)?
"""
            result = self.llm.run(prompt).strip().upper()

            if "A" in result and "B" not in result:
                wins += 1
            elif "B" in result and "A" not in result:
                losses += 1
            else:
                ties += 1

        # 计算三个比例
        return json.dumps({
            "win_rate": wins / total,
            "loss_rate": losses / total,
            "tie_rate": ties / total,
            "total_comparisons": total
        })
```

import gradio as gr
import json

def create_verification_ui(data_path: str):
    """创建 Gradio Web 界面"""
    problems = json.load(open(data_path))
    verifications = {}  # 保存验证结果

    def submit(problem_id, correctness, clarity, difficulty, completeness, status, comment):
        verifications[problem_id] = {
            "problem_id": problem_id,
            "scores": {
                "correctness": correctness,
                "clarity": clarity,
                "difficulty": difficulty,
                "completeness": completeness
            },
            "status": status,    # approved / rejected / needs_revision
            "comment": comment
        }
        # 自动保存
        with open(data_path + "_verifications.json", "w") as f:
            json.dump(verifications, f, indent=2, ensure_ascii=False)
        return "✅ 已保存,下一题"

    with gr.Blocks() as demo:
        gr.Markdown("# AIME 题目人工验证")

        # 题目展示
        problem_display = gr.Markdown()

        # 4 个维度评分(滑块 1-5)
        c1 = gr.Slider(1, 5, label="正确性", step=1)
        c2 = gr.Slider(1, 5, label="清晰度", step=1)
        c3 = gr.Slider(1, 5, label="难度匹配", step=1)
        c4 = gr.Slider(1, 5, label="完整性", step=1)

        # 验证状态(三选一)
        status = gr.Radio(
            ["approved", "rejected", "needs_revision"],
            label="验证状态"
        )
        comment = gr.Textbox(label="评论(可选)", lines=2)

        submit_btn = gr.Button("提交验证")
        result = gr.Textbox(label="状态")

        submit_btn.click(submit, [problem_display, c1, c2, c3, c4, status, comment], result)

    return demo

# 启动界面

## 💡 实战经验:质量标准与调优

### 推荐质量标准

| 指标 | 推荐值 | 含义 |
|---|---|---|
| **LLM Judge 平均分** | ≥ 4.0/5.0 | 整体质量合格 |
| **LLM Judge 通过率** | ≥ 80% | 大部分题可用 |
| **Win Rate** | 45%~55% | 接近真题水平 |
| **人工通过率** | ≥ 90% | 最终把关合格 |

### 生成策略调优

| 评估结果 | 优化方向 |
|---|---|
| 正确性低 | 在 prompt 加"请确保答案正确,验算后输出" |
| 清晰度低 | 增加"题目表述简洁,无歧义"约束 |
| 难度匹配低 | 提供更多 AIME 6-9 题样例 |
| 完整性低 | 要求"包含每一步推理" |
| Win Rate < 40% | 题目质量明显不如真题 → 换更强 LLM |
| Win Rate > 60% | 可能评委偏见 → 换不同评委交叉验证 |

## ⚠️ 小白避坑

1. **不要 100% 信 LLM Judge** —— GPT-4 可能给自己生成的题打高分(bias),要交叉验证
2. **Win Rate 要"双盲"** —— 不能告诉评委哪个是 AI 生成的,会有偏好
3. **小心 LaTeX 转义** —— `\frac` 在 JSON 里报错,提前用正则修复
4. **延迟不能省** —— 没 sleep 直接被 OpenAI 限流,白生成
5. **检查点要打** —— 生成 1000 道题用 1 小时,中断后没存就全没了
6. **答案格式要统一** —— AIME 答案都是 0-999 整数,生成时强制约束
7. **人工抽查不可少** —— 哪怕自动化评估再准,也要人工抽 10% 复核

## 📊 三方法对比

| 方法 | 速度 | 成本 | 准确性 | 适用场景 |
|---|---|---|---|---|
| **LLM Judge** | 快(1 题 ~2s) | 中(API 费) | 中 | 大规模初筛 |
| **Win Rate** | 中(1 对 ~5s) | 中 | 中高 | 与基准对比 |
| **人工验证** | 慢(1 题 ~5min) | 高(人工费) | 高 | 最终把关 |

→ **最佳实践**:三层漏斗
```
LLM Judge(1000 题) → 通过率 80%
       ↓
Win Rate(800 题)   → Win Rate ≥ 45%
       ↓
人工验证(抽 10%)   → 最终 approved 850 题
```
