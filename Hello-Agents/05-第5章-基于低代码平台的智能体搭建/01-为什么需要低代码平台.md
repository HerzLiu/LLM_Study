# 5.1 为什么需要低代码平台 + 三大平台选型

## 🎬 故事比喻:WordPress 之于网站

回想一下**网站开发**的演变:

| 时代 | 方式 |
|---|---|
| 90 年代 | 手写 HTML(像第 4 章手撕 Agent) |
| 2000 年代 | 拼接 PHP + MySQL |
| 2010+ 年代 | **WordPress / Wix / Squarespace** —— 拖拽就能建站 |

→ **绝大多数网站早已不用纯手写**。
→ **Agent 也走同样的路**。

---

## ⚖️ 5.1.1 为什么需要低代码平台?

### 4 大核心价值

#### 🎯 价值 1:**降低技术门槛**

| 谁能搞 Agent? |
|---|
| ❌ 纯代码时代:**只有程序员** |
| ✅ 低代码时代:**产品经理 / 设计师 / 运营 / 业务专家**都行 |

→ **极大地拓宽了创新的边界**。

#### 🎯 价值 2:**提升开发效率**

| 任务 | 纯代码时间 | 低代码时间 |
|---|---|---|
| 搭原型 (MVP) | **数天** | **数小时** |
| 调试 | 看日志靠经验 | **可视化** |
| 切换工具 | 改代码重写 | **拖个节点** |

→ 对**专业开发者也是巨大效率提升**。

#### 🎯 价值 3:**可视化与可观测性**

- **纯代码**:`print()` 看日志 → 痛苦
- **低代码**:**图形化看数据流动 + 节点状态** → 一目了然

→ "**调试体验是核武器级别的提升**"。

#### 🎯 价值 4:**标准化 + 最佳实践沉淀**

平台内置:
- ReAct 模板
- 优化的 RAG 检索引擎
- 标准化工具接入规范
- ……

→ **直接用业界最佳实践**,**不踩坑**。

---

## 🆚 低代码 vs 纯代码:不是替代,是分层

```
        高层抽象
            ↑
   ┌────────────────────────┐
   │   低代码平台              │  ← 关注业务逻辑
   │   (Coze / Dify / n8n)   │
   ├────────────────────────┤
   │   框架(LangChain 等)    │  ← 关注 Agent 范式
   ├────────────────────────┤
   │   纯代码(第 4 章)        │  ← 关注实现原理
   ├────────────────────────┤
   │   LLM API                │
   └────────────────────────┘
            ↓
        底层细节
```

→ **每一层都有它的位置**。学习时建议**自下而上**(先懂原理,再用高层抽象)。

---

## 🌍 5.1.2 当前三大主流平台速览

> 智能体低代码平台**百花齐放**,本书重点讲 3 个有代表性的:**Coze / Dify / n8n**。

### Coze(字节出品)

| 维度 | 描述 |
|---|---|
| **核心定位** | **零代码/低代码 Agent 构建王者** |
| **特点** | 可视化 + 插件库丰富 + 一键发布抖音/飞书/微信/豆包 |
| **适用人群** | **入门用户 / 产品经理 / 运营 / 个人创作者** |
| **致命短板** | **不支持 MCP**(虽然插件多,但被锁在自家生态) |

### Dify(开源全栈)

| 维度 | 描述 |
|---|---|
| **核心定位** | **开源 LLM 应用开发与运营平台**(BaaS + LLMOps) |
| **特点** | RAG + Agent + 数据标注 + 微调,**全栈一站式** |
| **适用人群** | **有技术背景的开发者** / **企业级团队** |
| **致命亮点** | **支持 MCP** + **可本地部署** + **开源** |

### n8n(通用自动化王者)

| 维度 | 描述 |
|---|---|
| **核心定位** | **工作流自动化工具**(LLM 只是其中一个节点) |
| **特点** | 数百预置节点(SaaS / 数据库 / API),**连接能力强** |
| **适用人群** | 需要**将 AI 嵌入现有业务流程**的开发者 |
| **学习曲线** | **较陡**(但很有"工程感") |

---

## 🎯 5.1.3 选型决策树

```
你是非技术人员,想快速做 AI 玩具/工具?
   │
   └──→ Coze (拖拽 + 一键发布)

你是开发者,想做企业级 AI 应用?
   │
   └──→ Dify (全栈 + MCP + 可本地)

你已经有一堆 SaaS 工具/业务系统,想让 AI 串起来?
   │
   └──→ n8n (节点连接万物)

你要做的事极其定制化,任何平台都不能完全满足?
   │
   └──→ 用代码 (回到第 4 章 / 第 6 章框架)

实际生产可能 混合使用:
   原型用 Coze 验证 → Dify 重构生产版 → 用 n8n 集成到现有系统
```

---

## 💡 5.1.4 平台 vs 框架 vs 代码 的本质差异

| 维度 | **平台**(本章) | **框架**(第 6 章) | **代码**(第 4 章) |
|---|---|---|---|
| 抽象层级 | 最高 | 中 | 最低 |
| 学习成本 | 低 | 中 | 高 |
| 灵活度 | 中(被平台约束) | 高 | 最高 |
| 部署 | 平台代管 / Docker | 自部署 | 自部署 |
| 迭代速度 | **最快** | 中 | 慢 |
| 适合做 | 业务原型 / 标准应用 | **生产级定制** | 研究 / 极致优化 |

---

## ⚠️ 小白避坑

1. **不要因为"会写代码"就鄙视低代码**
   - 真实工程中,**70% 的 Agent 用低代码就够**
   - **代码是最后 20% 极致优化的需求**才用
2. **不要被平台 vendor lock-in**
   - Coze 上做的 Agent **基本不能搬到别处**
   - **重要项目用 Dify(开源)/ 自建代码** 更安全
3. **MCP 是大势所趋**
   - 选平台时**优先考虑支持 MCP** 的(Dify ✓ / n8n 部分支持)
   - Coze 的"不支持 MCP" 是真正的致命伤
4. **学习曲线 ≠ 长期效率**
   - n8n 学习曲线陡,**但学会后效率最高**
   - Coze 上手快,**但天花板低**

## 📌 5.1 节要点

| 知识点 | 一句话 |
|---|---|
| **为啥要低代码** | 降门槛 + 提效率 + 可视化 + 最佳实践 |
| **Coze** | 字节,零代码王者,**适合非技术** |
| **Dify** | 开源全栈,**适合开发者 + 企业** |
| **n8n** | 通用自动化,**适合系统集成** |
| **核心选择** | 没有最好的,**根据需求选** |
| **代码 vs 平台** | **互补不替代**,真实生产常混用 |
