## 🎯 终极选型决策树

```
你的核心需求是什么?
   │
   ├── 想做个 AI 玩具或机器人快速验证想法?
   │   └──→ ⭐ Coze (5 分钟上手)
   │
   ├── 想做企业级 AI 应用,需要可控可定制?
   │   └──→ ⭐ Dify (开源 + 全栈 + MCP)
   │
   ├── 已经在用一堆工具,想加 AI 串起来?
   │   └──→ ⭐ n8n (连接万物)
   │
   ├── 我是研究者,想搞高度定制化?
   │   └──→ 用代码 (回到第 4 章 / 第 6 章框架)
   │
   └── 综合需求复杂?
       │
       └──→ 混合方案:
            - Coze 做面向用户的入口
            - Dify 做后端核心 Agent
            - n8n 做系统集成 + 自动化
            - 代码做最关键的几个模块
```

## 💼 真实场景应用对照

### 场景 1:**个人创作者做"AI 内容助手"**
- 需求:写文章 + 配图 + 发布
- **推荐**:**Coze**
- 原因:零代码、多平台一键发布、UI 友好

### 场景 2:**初创公司做"AI 客服"**
- 需求:接入官网 + 私有知识库 + 高可控
- **推荐**:**Dify**
- 原因:开源可控、RAG 强、模型灵活

### 场景 3:**企业内部"AI 流程自动化"**
- 需求:邮件 + Slack + Jira + 数据库 全打通
- **推荐**:**n8n**
- 原因:节点丰富、连接能力强、可自托管

### 场景 4:**算法团队做"研究原型"**
- 需求:定制 RL 训练、需要细控
- **推荐**:**纯代码**(第 4 章 / 第 6 章)
- 原因:平台都不够灵活

## ⭐ 三大平台共同的"道"

不管选哪个,都遵循**同样的核心理念**:

| 共同点                | 解释                          |               |
| ------------------ | --------------------------- | ------------- |
| **可视化拖拽**          | 比写代码快 10 倍                  |               |
| **节点 / 插件 / 工具复用** | 站在巨人肩上                      |               |
| **声明式配置** > 命令式编程  | 描述"做什么"而非"怎么做"              |               |
| **JSON 数据流**       | 标准化的节点间通信                   |               |
| **LLM 是大脑,工具是手脚**  | [第 1 章](../01-%E7%AC%AC1%E7%AB%A0-%E5%88%9D%E8%AF%86%E6%99%BA%E8%83%BD%E4%BD%93/01-%E4%BB%80%E4%B9%88%E6%98%AF%E6%99%BA%E8%83%BD%E4%BD%93.md) 的核心思想 |
| **Prompt 工程是灵魂**   | 配置工具是次要,**写好 prompt 才是关键**  |               |

## 📝 本章总结

### 核心收获

1. **低代码平台不是替代代码,是更高层的抽象**
2. **三大平台各有定位,没有最好,只有最合适**:
   - Coze = 易用王者(创作者首选)
   - Dify = 全栈专业(开发者/企业)
   - n8n = 通用集成(系统打通)
3. **实战中常常混合使用**,**互补而非互斥**
4. **不管用哪个,Prompt 工程都是灵魂**

### 不变的工程经验

| 经验 | 解释 |
|---|---|
| **先用平台快速验证想法** | 不要一上来就写代码 |
| **数据安全敏感场景必须自托管** | Dify/n8n 而非 Coze |
| **优先支持 MCP 的平台** | 接入新兴生态 |
| **平台不够用了再考虑代码** | 不要为了写代码而写代码 |
