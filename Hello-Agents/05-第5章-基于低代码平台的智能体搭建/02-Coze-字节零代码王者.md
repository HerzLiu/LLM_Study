## 🎬 故事比喻:乐高 + 应用商店

**Coze 就像乐高积木**:
- 你不用懂塑料怎么造
- 不用懂模具怎么开
- **只需把现成的积木拼起来** → 一个城堡就成了

更妙的是:**做完之后能一键发到抖音、飞书、微信、豆包**……
→ **创意 → 产品 上线就是分分钟**。

## 🎮 5.2.3 实战:构建"每日 AI 简报"助手

### 案例目标

每天**自动**从 36 氪、虎嗅、IT 之家、InfoQ、GitHub、arXiv 抓取 AI 头条 + 论文 + 项目,**整合成一份精炼简报**。

### 涉及的核心技能

| 技能 | 解释 |
|---|---|
| **多源信息聚合** | RSS + GitHub + arXiv 三大插件并行抓数据 |
| **智能体行为定义** | 角色设定 + Prompt 控制内容质量 |
| **自动化工作流** | 数据获取 → 处理 → 格式化输出 一气呵成 |

---

### 🛠 Step 1:添加并配置信息源插件

> Coze 的**最大优势 = 插件生态丰富**。

#### 4 大数据源插件

| 插件 | 用途 | 配置示例 |
|---|---|---|
| **RSS 插件** | 订阅媒体 RSS | 36kr.com/feed / rss.huxiu.com 等 |
| **GitHub 插件** | 追踪开源项目 | q=AI, per_page=10, sort=updated |
| **arXiv 插件** | 学术论文 | count=5, search_query=AI |

#### 配置示例(直接复制能用)

```yaml
RSS 链接:
  - 36氪:  https://www.36kr.com/feed
  - 虎嗅:  https://rss.huxiu.com/
  - IT之家: http://www.ithome.com/rss/
  - InfoQ: https://feed.infoq.com/ai-ml-data-eng/

GitHub 配置:
  q: AI
  per_page: 10
  sort: updated

arXiv 配置:
  count: 5
  search_query: AI
```

### 🛠 Step 2:可视化编排连接

在 Coze **可视化界面**里:
1. 拖出 3 个数据源插件(RSS / GitHub / arXiv)作为输入
2. 拖出 **大模型节点**作为处理器
3. 用线连接它们,数据流从输入 → 处理 → 输出

→ **像搭乐高一样**。

### 🛠 Step 3:设定角色 + 提示词

#### System Prompt(系统提示词)定义"长期人设"

```markdown
# 角色
你是一位资深且权威的科技媒体编辑,擅长高效精准地整合 AI 领域简报,
特别在技术动态、前沿学术研究和热门开源项目方面拥有深入分析能力。

## 工作流
### 日报输出格式
1. 日报开头标注:"AI日报 | 日期 | by@作者"
2. 每条标题前加独有 Emoji
3. 输出内容必须与 AI/LLM/AIGC 高度相关
4. 每条提供原始链接 + 简短精准描述
```

#### User Prompt(用户提示词)定义"本次任务"

```markdown
- **信息提取**: 从 `{{articles}}` 等输入源,筛选 AI 相关文章,
  整理为 **"AI 技术新闻"** 模块
- **学术摘要**: 从 `{{arxiv}}` 总结最新论文,形成 **"AI 学术论文"** 模块
- **项目筛选**: 从 `{{GitHub}}` 选出 5 个最热项目,
  整理为 **"AI 开源项目"** 模块

# 注意
- 严格遵循输出格式
- 总量: 10条新闻 + 5篇论文 + 5个项目
```

### 🛠 Step 4:测试 + 多渠道发布

#### 测试
- 在 Coze **预览界面**运行
- 检查内容准确性、格式、风格
- 不满意 → **回去调 Prompt 或插件参数**

#### 一键发布
Coze 支持**一键发到**:
- ✅ 抖音
- ✅ 飞书机器人
- ✅ 微信公众号
- ✅ 豆包智能体
- ✅ API 调用(自己集成)

→ **同一个 Agent,同时出现在 5 个平台**。

## ⭐ 5.2.5 Coze 优势与局限性

### ✅ 优势

| 优势 | 解释 |
|---|---|
| **插件生态** | **国内最丰富**,几乎啥都能接 |
| **可视化编排** | 拖拽就能搭复杂流程 |
| **提示词控制精细** | 支持 prompt 库 + 模板 |
| **多平台部署** | 抖音/飞书/微信/豆包 **一键搞定** |
| **持续扩张生态** | 不断接入新平台(手机厂商/硬件厂商) |

### ⚠️ 局限

| 局限 | 影响 |
|---|---|
| **不支持 MCP** ⚠️ | **致命** —— 被锁在自家插件生态 |
| **部分插件配置复杂** | 需要 API Key 等 → 对纯小白仍有门槛 |
| **导入导出受限** | 付费版才能导出,且是 zip 而非标准 JSON |
| **数据隐私** | 在字节服务器,**敏感数据不能用** |
| **国际版受限** | 国内/海外用户体验差异 |

### 💡 PDF 作者的真实吐槽

> "**不支持 MCP 是最致命的**。尽管插件市场极其丰富,但不支持 MCP 可能会成为限制其发展的枷锁。"

## 🎯 5.2.6 何时用 Coze?

```
✅ 适合:
- 你不会写代码
- 想快速验证一个 AI 想法
- 想做个抖音/飞书/微信机器人
- 内容创作类应用(简报/写作助手/角色扮演)
- 对数据隐私要求不高

❌ 不适合:
- 企业级生产应用(用 Dify)
- 复杂的系统集成(用 n8n)
- 涉及敏感数据
- 想用 MCP 工具
- 想自托管
```

## ⚠️ 小白避坑

1. **手动配置 RSS 链接时检查可用性**
   - 很多 RSS 已经死链
   - 加个 RSS 之前先**浏览器打开看看**有没有内容
2. **大模型节点 Temperature 设低**
   - 简报类任务用 0.3 以下
   - 否则 LLM 会"加戏"编内容
3. **测试时用真实数据,别用样例**
   - 样例数据测过 ≠ 真实场景 OK
4. **付费才能商用**
   - 免费版有调用次数限制
   - 真要做产品要看价格表
