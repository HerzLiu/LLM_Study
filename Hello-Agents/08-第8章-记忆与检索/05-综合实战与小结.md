## 🎬 实战目标

构建一个**智能文档问答助手**:
- 用户上传一批 PDF / Markdown 文档
- Agent 能**基于文档准确回答问题**(RAG)
- Agent 能**记住用户偏好**(Memory)
- 支持**多轮上下文对话**

→ **Memory + RAG 综合应用**。

---

## 🛠 8.5.1 完整代码示例

### Step 1:**初始化所有组件**

```python
from hello_agents import SimpleAgent, HelloAgentsLLM, ToolRegistry
from hello_agents.tools import MemoryTool, RAGTool

# 创建 LLM
llm = HelloAgentsLLM()

# 创建 Memory 工具
memory_tool = MemoryTool(
    user_id="user123",
    memory_types=["working", "episodic", "semantic"],
)

# 创建 RAG 工具
rag_tool = RAGTool(
    knowledge_base_path="./docs",      # 文档目录
    namespace="user123_docs",          # 用户隔离
    collection_name="docs_collection",
)
```

### Step 2:**加载文档到 RAG**

```python
# 批量加载
rag_tool.execute("load_directory", directory="./docs")
# ✓ 加载了 50 个文档,生成 320 个 chunks
```

### Step 3:**创建 Agent + 注册工具**

```python
agent = SimpleAgent(
    name="文档问答助手",
    llm=llm,
    system_prompt="""你是一个智能文档问答助手。

可用工具:
- memory: 用于记住用户偏好和对话历史
- rag: 用于从文档库检索相关知识

工作流程:
1. 先用 rag 检索相关文档
2. 基于检索结果回答
3. 把重要的偏好/事实用 memory 记下来
4. 下次类似问题先查 memory,再查 rag""",
)

tool_registry = ToolRegistry()
tool_registry.register_tool(memory_tool)
tool_registry.register_tool(rag_tool)
agent.tool_registry = tool_registry
```

### Step 4:**对话循环**

```python
print("📚 智能文档问答助手已就绪!")
while True:
    user_input = input("\n你: ")
    if user_input.lower() in ["exit", "quit"]:
        break

    response = agent.run(user_input)
    print(f"助手: {response}")
```

## ⭐ 8.5.3 设计哲学回顾

### 哲学 1:**借鉴人类认知**

```
人类记忆 4 层 → HelloAgents 4 种 Memory
人类开卷考     → RAG 检索增强
```

### 哲学 2:**万物皆为工具**(贯穿全章)

```
Memory → MemoryTool
RAG    → RAGTool
   ↓
统一接入 → tool_registry.register_tool()
   ↓
Agent 调用方式完全一样
```

### 哲学 3:**多策略融合**

```
检索: 向量 + MQE + HyDE 三路并行
记忆评分: 相似度 × 时间衰减 × 重要性
   ↓
混合 > 单一
```

### 哲学 4:**Memory + RAG 协同**

```
RAG 检索到的高质量答案 → 存入 Memory
   ↓
下次类似问题 → 优先从 Memory 答(快)
```

## 📊 8.5.4 性能与成本权衡

### Memory 性能

| 类型 | 写入速度 | 检索速度 | 存储成本 |
|---|---|---|---|
| Working | 极快(内存) | 极快 | 0 |
| Episodic | 中(SQLite+Qdrant) | 快 | 中 |
| **Semantic** | 慢(NLP 抽取 + Qdrant+Neo4j) | 中 | 高 |
| Perceptual | 慢(多模态编码) | 中 | 高 |

→ **不要无脑全用 Semantic**,**按需选择**。

### RAG 成本

```
每次 RAG 调用 ≈ 2~4 次 LLM 调用 + 1~3 次 Embedding
   - MQE: 1 次 LLM(扩展)+ N 次 Embedding
   - HyDE: 1 次 LLM(假答)+ 1 次 Embedding
   - 最终回答: 1 次 LLM
```

→ **生产环境用缓存** + **Top-K 调小**(3~5)。

## 🎯 8.5.5 何时用 Memory? 何时用 RAG?

| 场景 | Memory | RAG |
|---|---|---|
| **个性化对话**(记住用户偏好) | ✅ | – |
| **多轮上下文**(记住前文) | ✅ | – |
| **企业知识库问答** | – | ✅ |
| **文档查询** | – | ✅ |
| **客服**(基于 FAQ) | – | ✅ |
| **复杂场景**(个性化 + 知识) | ✅ | ✅ |

→ **不要无脑都用**,**按需选**。

## 📝 8.5.7 本章核心收获

### 收获 1:**Memory 设计模式**(可迁移)
```
分类:Working / Episodic / Semantic / Perceptual
操作:add / search / forget / consolidate
评分:相似度 × 时间 × 重要性
```

### 收获 2:**RAG 完整流程**
```
文档处理 → 嵌入 → 向量存储 → 多策略检索 → 上下文构建 → LLM 生成
```

### 收获 3:**多策略检索三件套**
```
向量检索 + MQE(查询扩展)+ HyDE(假设答案)
```

### 收获 4:**Memory + RAG 协同**
```
RAG 答案 → Memory(沉淀知识)
Memory 命中 → 跳过 RAG(省钱)
```

## ⚠️ 整章踩坑清单

| 坑 | 解法 |
|---|---|
| 文档分块太大/太小 | chunk=500, overlap=100 |
| 多用户数据串台 | `user_id` + `namespace` 严格隔离 |
| Embedding 切换没清库 | 切换前**清空所有向量** |
| MQE/HyDE 成本高 | 加缓存 + 限频 |
| Memory 都用 Semantic | 区分场景,Working 优先 |
| `importance` 都设 0.5 | 系统性区分高(0.8)/中(0.5)/低(0.2) |
| `forget` 删错重要数据 | 用前导出备份 |
